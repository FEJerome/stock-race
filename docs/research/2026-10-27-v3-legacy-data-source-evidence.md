# 2026-10-27 · V3 历史数据源证据与最小验证捷径

## 状态与边界

本报告整理 Stock-Race V3 Demo 的定向只读调研，回答三个问题：旧 `data-service` 已解决什么、还剩哪些关键未知、最小真实验证应怎样排序。本报告不构成数据源选定、运行验收或许可结论。

- 当前正典：本地 main `b5edf4f`。
- develop 顶点：`b70ca94`；其历史中的旧 `data-service` 通过 commit 对象核查，不把顶点已删除的目录当作现存代码。
- 调研时间：2026-10-27。
- 方法：只读代码、依赖清单、历史文档、测试脚本、JSON 结果和 Git 历史；主会话亲核跨资产语义、原始 JSON 统计口径、修复顺序和关键缺陷。
- 本轮未运行旧脚本或测试，未安装依赖、启动服务、访问外部 API、读取实际环境文件或验证任何 Key。
- “今天未验证”指 2026-10-27 未获得新的运行证据；历史记录只约束其当时样本和环境。

## 结论摘要

1. **旧成果能把“从零摸接口”缩成“带着已知缺陷做固定探针”，不能替代今天的真实验证。** 最有价值的是两组带原始 JSON 的报价测试、失败样例、后续修复位置和证据记录模板，而不是历史星级、成功率或实时源排名。
2. **本轮定位到的两组真实 JSON 都在 develop 历史，不在 main 当前树。** 它们只覆盖 2026-02-10 一个上午的报价/基本信息，不覆盖日线、四资产、公司行动或回测语义。
3. **旧“100% 成功”口径不可靠。** 空调用未抛异常即可记为批量成功，总成功又取“单股或批量成功”，所以空结果和错误数值也可能计入成功。
4. **股票有日线与少量分红入口；ETF、指数缺少类型化验证；场外基金 NAV 与可见时点基本从零开始。** 真实日历、完整公司行动、费用适用元数据、限频、权限与许可均未形成当前证据。
5. **推荐按风险而非旧实时排名验证：**先 AKShare 的基金 NAV 可见性，再 ETF/指数；随后 Baostock 股票原始价、公司行动和日历；Tushare 在取得授权后交叉核验；直接新浪/腾讯/东方财富只用于补缺。

### 5. 旧“100% 成功”为什么不能用

`a8e1fd7:data-service/scripts/test_all_6_sources_20min.py:143-167` 显示：

1. 批量调用只要不抛异常，就设置 `batch_quotes_success=True`，不要求非空；
2. 总成功使用 `single_quote_success OR batch_quotes_success`；
3. `quotes_count` 另行统计，因此会出现成功率为 100%、报价数却为 0 的组合。

报告中的“成功率”“批量成功率”和“鲁棒性评级”没有同时满足以下四层：

1. 调用/传输成功；
2. 返回非空且覆盖全部预期标的；
3. 字段类型、单位、时间和资产身份通过 schema；
4. 与独立权威参考值对账通过。

V3 不得复用旧百分比作为主要验收指标。

## 六、可直接复用的负例与验证用例

| 旧证据 | 转成 V3 的用例 | 必须避免 |
|---|---|---|
| 空批量仍计成功 | 断言 `expectedSymbols == actualSymbols`、必要行数非零，分别记录四层成功 | 只用 HTTP 200 或不抛异常作为通过 |
| 东方财富价格缩放异常 | 固定高价股与独立权威值对账，检查原始字段、`fltt` 和单位 | 只断言 `price > 0` |
| 腾讯斜杠数值 | 将历史字符串做成离线 parser fixture，显式处理无效必填字段 | 所有解析失败都 safe 成 0，掩盖数据错误 |
| executor 关键字参数错误 | 新同步 probe 绕开；若复用 async 包装，为修复候选补回归 | 在旧 router 里边修边测，混淆服务故障与源能力 |
| 集合竞价零价格 | 零值必须结合市场阶段、停牌和字段语义判断 | 把零值一概视为有效行情或一概填成上一价 |
| `trade_cal` 自检、最近分红 | 升级成节假日日历断言和完整公司行动字段探针 | 接口有返回就宣称日历/公司行动完成 |
| 历史 JSON 与研究指标结构 | 复用证据清单，增加 assetType、固定区间、adjustment、版本、事件时间、noFallback、rawHash | 继续只存成功率和平均延迟 |
| develop CSV 与 integration 文件 | CSV 只测 parser；真实 integration 抽成单源、固定区间、硬断言探针 | 用合成样例证明真实源可用，或允许空结果通过 |

旧失败只用于设计首测，**不允许跳过任何主候选在今天的 smoke**。

## 七、推荐的真实数据源验证顺序

以下是后续获得单独授权后的建议，不是本轮已执行步骤。

### 0. 离线准备与条款门禁

1. 固定 ProbeResult manifest、绝对日期、资产身份和独立权威参考；记录隔离环境的 Python 与库版本。

### 1. AKShare 广度优先：先基金 NAV，再 ETF/指数

若只有 NAV 日期而没有 publishedAt，立即记录缺口，进入“保守下一可见期假设是否可接受，或是否需要基金公司/官方公告等来源”的裁决；不得把当日未知 NAV 当作当时可见。

## 八、所有真实探针共用的最小契约

### 1. 输入与样本

- 使用固定绝对区间，禁止 `days=5` 或当前时间导致样本漂移。
- 每类资产至少核对两个固定日期的独立权威值；公司行动需包含现金分红和送转案例。
- 低并发、小样本，不主动触发限流；不同时间重复只做 smoke，长期稳定性另行验证。

### 2. 硬断言

- 资产身份、代码和类型一致；预期标的完整，结果非空。
- 字段类型、单位、复权、时区/交易日和重复日期检查通过。
- OHLC 关系、原始价与复权价关系、公司行动和净值序列符合所选口径。
- 来源事件时间与采集时间分开，明确无随机、无缓存伪造、无跨源合成 fallback。
- 未知代码、空区间、字段缺失和错误响应都有显式结果，不静默补值。
- 跨源只比较同口径原始数据，不平均；差异必须能由单位、复权或时间解释。

### 3. 每次保存的脱敏证据

- 数据源、接口和库版本；请求的资产、类型、区间和复权语义。
- 开始时间、来源事件时间、采集时间、耗时、行数和错误类型。
- 原始响应 hash 与必要的本地样本，不保存凭据。
- 调用成功、完整非空、schema 合格、权威值对账四层结果分别记录。
- 不把短窗口成功率直接命名为长期稳定性或生产 SLA。

### 4. 进入 V3 数据假设冻结前的最低门槛

1. 基金可见时点有真实字段，或有经维护者批准且明确展示的保守规则。
2. ETF/指数身份明确，不与股票代码或交易语义混用。
3. 股票原始价、公司行动和真实日历足以支撑资金与份额账本。
4. 费用假设与行情元数据分离，各自有来源和版本。
5. 数据访问、存储、展示和再分发方式与许可相符。

任一缺口都不能用历史“100% 成功”或“生产就绪”描述补足。

- 日期：2026-10-29（系统时间 14:57 +08:00）
- 研究问题：找回 V1/V2 关于游戏化、竞赛、AI 角色与“雇佣 AI 股票经理人”的原始构想，判断哪些可供 V3 Demo 概念复用，哪些已被明确否决或已过时。
- 范围：旧 main 的 README、`docs/` 历史产品/设计文档与 `frontend/` 关键界面；`origin/develop` 顶点的 Local/MVP/Full 文档、提示词与 Vue 界面，以及必要的分支历史。
- 方法：两条独立只读检索分别盘点 V1、V2，主会话再亲核核心产品原文、界面代码、MVP 转向和当前 V3 边界。V2 全程使用 `git show/git grep/git log`，未 checkout。
- 主要基准：V1 代码 `047bbf9897ae55ce5c2a59abc823229a54436ca3`；V2 `b70ca94ebe6ff741a7850eba77a5c88988d6fb7e`。当前非环境业务代码与 V1 基准无差异；引用其他历史版本时另行注明。
- 边界：未启动服务、安装依赖、运行测试或历史脚本；未读取实际环境文件，`security.py` 整文件跳过。历史“冻结”“完成”“生产就绪”只表示当时文档措辞，不是本轮验收。本报告是资产研究，不是产品方向或实施授权。

## 结论摘要

1. **“雇佣 AI 股票经理人”与 V2 是直接同源，几乎不是新造的隐喻。** V2 根 README 已写“你不是在炒股，你是在经营一家基金公司”，用户“招聘”不同模型的“AI 基金经理”；PRD 明确“用户作为‘投资经理’，雇佣AI作为‘交易员’”。出处：`b70ca94:README.md`、`b70ca94:docs/PRD.md:52-60`。
2. **新概念的四个主环节都有历史根源，其中“对话形成策略”和“看 AI 工作过程”曾是核心设计。** V2 有“董事长面试新人基金经理”、五维策略收集、增量修改策略、“可读的AI内心戏”和“空闲→监控→唤醒→决策→执行→复盘”状态机；但“随时可对话”的完整交互实现未获本轮验证。
3. **V1 提供竞赛骨架，V2 把它扩展成角色经营游戏。** V1 的核心是多 AI 虚拟交易竞赛、排行、赛季、勋章与称号；V2 增加招聘、试用、周薪、实习生/经理/合伙人职级、激励档位、荣誉馆和差异化人设。`Race` 可确认对应多 AI 竞赛玩法，但未找到英文命名的词源记录。
4. **可复用的是产品意图与表达模式，不是旧实现已完成的能力声明。** V1 排行榜、AI 账户与决策日志大量使用 mock；V2 Local 虽有策略表单、经理人卡片和决策详情 UI，决策历史接口仍明确是未持久化占位，晋升规则也在不同文档中互相冲突。
5. **V2 末端确实放弃了实时竞赛，但只明确约束 MVP，不等于全项目永久否决。** 2026-03-20 的 MVP 文档转向收盘后的单一“AI复盘搭档”，排除实时交易、排行/竞赛和 MVP 阶段对话；同提交也声明 Local 技术实验室不受影响。当前 V3 若复用“经理人”，应复用角色与呈现层，不能带回模型直接下单、现金奖励或实时荐股语义。

## 一、V1：竞赛是产品主骨，AI 账户是初级角色载体

### 1.1 原始定位与 Stock-Race 的“Race”

`07d32ed:docs/analysis/REQUIREMENTS.md`（V1 需求文档，当前文件仍为同一内容）：

> “让用户能够将虚拟资金分配给不同的AI大模型，让AI基于实时股票数据和预设策略进行虚拟交易，并通过竞赛形式展示不同AI的交易能力。”（第 6 行）

> “创建一个教育性、娱乐性和研究性相结合的AI股票交易竞赛平台。”（第 9 行）

同文件第 24-28 行把“创建 AI 账户”定义为分配虚拟资金、选择模型、配置策略提示词与风险偏好、监控状态和交易记录；第 55-59 行定义：

> “排行榜：按收益率、夏普比率、最大回撤等指标排名”
> “比赛周期：支持日赛、周赛、月赛、自定义周期比赛”
> “奖项系统：虚拟勋章、等级称号、特殊权限”

因此，**事实**是 V1 的中文产品名和核心玩法均为“AI 股票竞赛平台”，`Race` 对应 AI 账户/模型间的模拟交易竞赛。**未核验**的是英文名称的具体命名过程；仓库中未找到专门的命名记述，不能把词源推断写成事实。

### 1.2 AI 角色化与工作过程可见

V1 已有三类角色化表达：

- **职业角色**：`047bbf9:ai-service/src/ai_service/prompts/base_prompts.py:115` 将模型设定为“专业的股票交易AI助手”。
- **策略人格**：`047bbf9:scripts/demo_stock_race.py:116-159` 分别定义“保守型AI投资顾问”和“进取型AI投资顾问”提示词；这是演示脚本，不是已验证的通用规则引擎。
- **账户拟人化**：`047bbf9:frontend/src/pages/AIAccounts.tsx:44-101` 使用“量化策略AI”“价值投资助手”“技术分析大师”“风险控制专家”等名称、模型图标和绩效评分；第 156-217 行将头像、模型标签、运行状态与评分进度条组合成角色卡片。

“看 AI 工作”的界面雏形是 `047bbf9:frontend/src/components/ai/AIDecisionLog.tsx:33-47`：每条决策包含 `aiName`、动作、`confidence`、自然语言 `reason` 和 `executed/pending/rejected/expired` 状态；第 54 行起明确为模拟数据。该组件的 Timeline、筛选和状态徽标，比排行榜更直接对应新概念的“看见经理人工作过程”。

### 1.3 V1 的游戏化界面

`047bbf9:frontend/src/pages/Competition.tsx` 提供了完整的竞赛视觉语言：

- 第 78-96 行：前三名使用金/银/铜色皇冠 Avatar；

但第 34 行明确写着“模拟排行榜数据”。奖励卡中的现金金额也是静态 mock 文案，不能当成真实奖励机制或复用建议。

## 二、V2：从“AI 竞赛”发展为“经营基金公司、招聘 AI 交易员”

### 2.1 与新概念几乎相同的产品定义

`b70ca94:README.md` 开篇原文：

> “你不是在炒股，你是在经营一家基金公司。”

> “用户扮演‘投资总负责人’，受‘投资董事长’之托管理虚拟基金。你可以‘招聘’来自不同‘大学’（DeepSeek、通义千问、Kimi 等）的 AI 基金经理，让它们用真实的投资风格进行 PK。”

`b70ca94:docs/PRD.md:52-60` 进一步冻结了当时的产品画布：

> “AI模型农场——用户作为‘投资经理’，雇佣AI作为‘交易员’进行虚拟股票交易。”

> “关键壁垒：先发优势 + 人设差异化 + 数据沉淀 + 用户习惯。”

这不是零散的“游戏化”想法，而是已经用于组织用户旅程、雇佣流程、虚拟资金、成长体系和商业模式的核心隐喻。

### 2.2 “先对话形成策略”：面试与五维收集两套设计

**面试式角色扮演**出现在 V2 保存的 V0.9 历史架构文档中，不能误写为 V2 新实现：

- `b70ca94:docs/architecture/HISTORICAL/V2026-02-10-SERVICE_ARCHITECTURE.md:471-475`：“用户与 DeepSeek 对话（新人基金经理角色扮演）”，随后提炼对话并生成提示词；
- 第 529-547 行：用户点击“生成基金经理”，从对话提炼“投资理念、风险偏好、关注领域、决策风格”；
- 第 708-721 行：“你是新人基金经理的导师。用户是投资董事长，正在面试你。”并要求保持角色一致、不给具体交易建议。

**Local 的五维策略收集**则有提示词和界面两类资产：

- `b70ca94:docs/PRD.md:265-282` 的雇佣步骤为：选择雇佣类型、试用/正式、配置投资研究点数、进行五维策略收集对话、确认雇佣；核心流程是“用户输入 → AI追问（填补维度）→ 策略文档生成 → 后续决策的上下文”。
- `b70ca94:docs/modules/local/PROMPTS.md:25-31`：“每次只问一个问题”“如果用户回答不清晰，温和地追问”“提供选项让用户选择”；第 34 行起依次收集风险承受、关注板块、持仓周期、仓位止损和市场范围，第 232 行起提供经典策略套餐。
- `b70ca94:local/frontend/src/components/strategy/StrategyWizard.vue:8-30` 有套餐卡片，第 30-205 行有风险、持仓、市场等配置和汇总回读。它证明策略配置 UI 存在，不等于多轮聊天前端已完整联通。
- `b70ca94:docs/discussion/discussion-log.md:73-75`：“修改策略 = 在已有策略基础上增量调整（非重置）”，与“随时对话、持续调整经理人”同源。

### 2.3 “看工作过程、专业细节可查”是明确的体验支柱

`b70ca94:docs/discussion/discussion-log.md` 有两条非常直接的原文：

> “可读的AI内心戏：每次决策触发时，AI用自然语言生成决策理由（结合技术指标、实时新闻等）。”（第 77-80 行）

> “核心状态机：AI交易员生命周期：空闲→监控→唤醒→决策→执行→复盘。”（第 567 行）

专业信息采用分层表达。`b70ca94:docs/modules/local/PROMPTS.md:359-367` 的决策结构同时包含：

- `reason`：“决策理由（100字以内，用户可见）”；
- `analysis`：“详细分析”；
- `risk_assessment`：“风险评估”；
- `confidence` 与建议仓位。

界面上，`b70ca94:local/frontend/src/views/AgentDetail.vue:332-347` 展示决策理由、置信度和 Token 用量，第 245-253 行在交易历史中展示 `decision_reason`，第 436-443 行通过 WebSocket 弹出“AI 决策”通知。它们可直接启发“经理人工作日志 + 专业详情抽屉”。

实现边界必须同时记录：`b70ca94:local/backend/api/decision.py:325-335` 明确写着 “decisions are not persisted yet”，决策历史接口仍为占位。因此这里可复用的是信息架构与交互意图，不是现成、完整的工作日志后端。

| 设计 | 原文出处与内容 |

## 三、明确否决、转向与过时内容

### 3.1 明文否决：仅针对 MVP 的实时竞赛方向

`b70ca94:mvp/docs/DIRECTION_REDEFINITION.md`：

> “正式放弃原 MVP 方向。放弃：AI 交易员实时竞赛平台（微信小程序形态）。”

> “新方向：AI 复盘搭档 / AI 观察员”，面向收盘后复盘，以人格化分析员陪伴用户。

该文件末尾同时限定：“Local 版本的开发计划……不受本决策影响”“本文档仅约束 MVP 形态的产品方向”。`b70ca94:mvp/docs/MVP_DEFINITION.md §1.2` 又列出明确不做：

> “实时行情 / 实时交易”
> “选股建议 / 买卖时机”
> “收益排行 / 竞赛机制”
> “对话交互（MVP 阶段）”

所以准确结论是：**实时竞赛和对话曾被 2026-03-20 的 MVP 明确否决；Local 没有被同一文档否决，Full 也没有完成重新确认。** 文档中的合规案例与法律判断本轮未独立核验，这里只确认“当时以此为由转向”，不作法律结论。

### 3.2 同一 V2 顶点存在过期文档与规则冲突

- `b70ca94:mvp/README.md:33-37` 已列“放弃 AI交易员实时虚拟交易、多AI竞赛排行榜”，第 97 行标注旧 `DELIVERY_PLAN`“需更新”；
- 但 `b70ca94:docs/architecture/CURRENT/MVP/README.md:46-50` 仍保留云端排行榜，根 README 与 PRD 也仍是招聘/竞赛叙事。这些材料必须按日期和适用形态阅读，不能选一份当作整个 V2 的统一终态；
- 晋升条件也不一致：`docs/discussion/discussion-log.md:349-353` 采用 Lv.6/Lv.12；`docs/modules/local/IMPLEMENTATION_PLAN.md:255` 采用收益率 10%/30% 与交易日条件；`local/README.md:75-78` 又采用收益率 5%/15% 与交易次数条件。数值规则不可直接复用。

### 3.3 与当前 V3 正典的冲突，而非“V2 已否决”

当前已批准的 `636fc65:docs/features/v3-demo-complete-contract.md §0.2、§1.2` 明确：

- 路径为“自然语言意图 → 声明式 AST → 校验 → 权威回读 → 用户确认 → 确定性执行”；
- 模型不直接产生订单，不做模型逐日决策、自动实时交易或荐股；
- 每个 Run 只有一个资产，不以旧四服务、随机 mock 或静态曲线替代新内核。

因此，**若“雇佣 AI 经理人”用于当前 V3，应把它作为角色与叙事外壳**：对话形成并修改规则，经理人“工作过程”来自可审计 RunEvent 的只读投影，专业细节来自 AST、Readback、RunSpec、事件和报告证据。不能借角色隐喻恢复 V1/V2 的模型直接 buy/sell、逐日自主决策或实时荐股。若新方向确实要改变这些边界，则属于新的产品/技术决策，不在本调研授权内。

## 五、旧 UI/交互中值得借鉴的游戏感表达

1. **经理人卡片**：V2 `AgentCard.vue` 的实习生/经理/合伙人徽章、收益进度条和发光状态；V1 `AIAccounts.tsx` 的头像、模型标签、运行开关和评分。适合作为“我的经理人”列表，但评分必须来自真实、明确口径，不能沿用 mock 绩效。
2. **工作日志**：V1 `AIDecisionLog.tsx` 的 Timeline、理由、置信度、执行状态与筛选；V2 `AgentDetail.vue` 的决策理由和交易历史下钻。它是最贴近“看经理人工作”的旧组件范式。
3. **状态与反馈动效**：V2 `animations.css` 的 `breathing-light`、`pulse-glow`、`number-roll-up/down`、`card-lift-hover`，可分别表达运行、出现新事件、数值变化和卡片响应；应服务于状态理解，不用动效掩盖数据空态。
4. **职级与成就视觉**：V2 `variables.css` 的 Bronze/Silver/Gold 金属徽章体系，以及 `Leaderboard.vue` 的奖牌排名。职级徽章可独立复用；排行视觉只有恢复竞赛时才需要。
5. **策略套餐与回读**：V2 `StrategyWizard.vue` 的套餐卡片、图标化风险选项和提交前摘要，适合作为对话快捷选项与确认视图，而非重新变成一堵模板表单墙。
6. **竞赛冲刺反馈**：V1 `Competition.tsx` 的皇冠、排名变化和“距离前10名”进度条具有明确游戏感，但仅适用于竞赛语义。静态现金奖励卡不应复用。

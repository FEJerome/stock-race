## 执行摘要

### 核心发现
论文提出的事件抽取方法是**基于云端大模型的 Few-shot + Chain-of-Thought (CoT) Prompt 学习方法**，通过精心设计的提示词模板从文本中提取结构化事件三元组（触发词、主体、客体）。论文**未涉及事件类型分类体系**（如业绩/股权/治理/业务/政策），也**未提出事件强度计算公式**，而是通过下游 BERT 分类模型的预测概率间接量化事件影响。

### 阻断性不确定项
| 问题 | 状态 | 说明 |
|------|------|------|
| 事件类型分类体系 | ❌ 缺失 | 论文未定义业务维度的事件类型分类 |
| 事件强度计算公式 | ❌ 缺失 | 论文无单一事件强度计算，仅有分类概率因子 |
| 事件抽取准确率指标 | ❌ 缺失 | 论文未报告抽取模块的P/R/F1指标 |

### 与项目文档的主要差异
项目草稿文档中提到的"业绩/股权/治理/业务/政策"五维事件分类体系**并非来自论文**，可能是项目自身的业务设计。论文采用的是**技术导向**的事件表示（三元组+时间关系），而非**业务导向**的事件分类。

## 研究发现

### 1. [核心方法] 论文提出的事件抽取方法是什么？

**[CERTAIN]** 论文采用**基于云端大模型的提示词学习方法**，结合以下两种策略：

#### 1.1 技术原理

| 策略 | 原理 | 来源 |
|------|------|------|
| **Few-shot (上下文学习)** | 在 Prompt 中加入具体示例，提供明确的任务场景和期望输出格式 | GPT-3 上下文学习策略 [1] |
| **Chain-of-Thought (CoT)** | 将复杂抽取任务分解为逻辑子步骤，模拟人类思维依次求解 | Wei et al. 思维链方法 [2] |

#### 1.2 实现步骤

事件抽取分为三个步骤，通过统一的 Prompt 模板执行：

```
┌─────────────────────────────────────────────────────────────┐
│  Step 1: 抽取事件触发词                                      │
│  - 识别文本中描述主体和客体之间关系的词汇                      │
│  - 通常为动词或动名词（如"发售"、"排起"）                    │
├─────────────────────────────────────────────────────────────┤
│  Step 2: 抽取主体与客体                                      │
│  - 对每个触发词，寻找对应的主体(Subject)和客体(Object)        │
│  - 主体/客体可以是人、物、地点等实体                          │
├─────────────────────────────────────────────────────────────┤
│  Step 3: 结构化结果返回                                      │
│  - 以 JSON 格式返回事件三元组列表                             │
│  - 字段: {Id, Trigger, Subject, Object}                      │
└─────────────────────────────────────────────────────────────┘
```

### 2. [实现细节] 具体如何实现？

#### 2.1 Few-shot Prompt 模板设计 **[CERTAIN]**

Prompt 模板包含三部分：**指示** + **例子** + **输入**，使用换行符分隔。

**【指示部分】**
```
你是一个事件抽取器，提供一段文本，请根据语法结构，抽取文本中所有的事件三元组并返回，遵守以下流程。

1) 抽取文本所有事件触发词。事件触发词，用于描述主体和客体之间的关系，通常为是动词，如"吃"，"跑"等。

2) 对于每个事件触发词，寻找对应的主体和客体。主体表示事件涉及的实体，可以是人、物、地点等。客体表示事件中与主体发生关系的实体。

3) 将所有事件三元组以{"Id":原文本中的顺序, "Trigger":事件触发词, "Subject":主体, "Object":客体} json形式，放在list中返回。
```

**【例子部分】**
```
Input:今天华为手机发售，一大早店外就排起了长长的队伍，人气火爆

Output:
1) 抽取文本所有事件触发词。["发售", "排起"]

2) 对于每个事件触发词，寻找对应的主体和客体。
"发售"对应的主体与客体为"华为手机"，""；
"排起"对应的主体与客体为"店外"，"长长的队伍"。

3) 按照指定格式返回事件三元组列表。
[{"Id":0, "Trigger":"发售", "Subject":"华为手机", "Object":""},
 {"Id":1, "Trigger":"排起", "Subject":"店外", "Object":"长长的队伍"}]
```

**【输入部分】**
```
Input:<NewsContent>
Output:
```

#### 2.2 事件类型分类体系 **[UNKNOWN]**

论文**未定义**业务维度的事件类型分类体系（如业绩/股权/治理/业务/政策及其子类）。

论文采用的是**统一的结构化表示方法**：
- 所有事件都表示为 `{Id, Trigger, Subject, Object}` 四元组
- 不区分事件的业务类型
- 通过**时间关系**（BEFORE/AFTER/EQUAL/VAGUE）而非事件类型来组织事件

论文中提及的示例事件包括：
| 示例 | 触发词 | 主体 | 客体 | 隐含类型（推断） |
|------|--------|------|------|------------------|
| 华为手机发售 | 发售 | 华为手机 | (空) | 产品/业务 |
| 店外排起队伍 | 排起 | 店外 | 长长的队伍 | 市场反应 |
| 公司发布新产品 | 发布 | 公司 | 新产品 | 产品/业务 |
| 公司涉嫌偷税漏税 | 涉嫌 | 公司 | 偷税漏税 | 法律/风险 |
| 格力电器累计回购 | 回购 | 格力电器 | (空) | 资本运作 |

#### 2.3 事件强度计算公式 **[UNKNOWN]**

论文**未提出**单一事件的强度计算公式。

论文采用的**间接量化方法**是通过下游 BERT 分类模型的预测概率来构建因子：

```
步骤1: 获取分类概率
  pc(x) = 股票在类别C上的预测概率 (C ∈ {上涨h, 下跌l, 振荡})

步骤2: 计算对数几率
  Lc(x) = log[ pc(x) / (1 - pc(x)) ]

步骤3: 构建因子值
  Fa = Lh(x) - Ll(x)
```

其中 `Fa` 代表"股票上涨与下跌的相对可能性之差"，作为该文本（及其包含的所有事件）的综合影响量化值。

**关键结论**: 论文不计算单一事件的强度，而是将所有事件作为整体输入 BERT 模型，通过学习到的表示来间接反映事件组合的影响。

### 4. [验证方式] 如何验证实现是否正确？

#### 4.1 论文采用的验证方法 **[CERTAIN]**

论文**未使用**传统 NLP 评价指标（准确率、召回率、F1值）来验证事件抽取模块。

而是采用**端到端的下游任务验证**：

```
验证流程:
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  事件抽取    │ → │ 时间关系判断 │ → │ BERT分类预测 │ → │ 分层回测验证 │
│ (云端大模型) │    │ (本地大模型) │    │             │    │             │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
                                                            ↓
                                                    模拟总收益差指标
```

#### 4.2 评价指标 **[CERTAIN]**

| 指标 | 公式 | 说明 |
|------|------|------|
| **累计收益率 (AR)** | AR = (CV - BV) / BV × 100% | 投资周期内整体收益 |
| **模拟总收益差 (E)** | E = Σ(第1层收益) - Σ(第5层收益) - 基准收益 | 核心指标，值越大表示分层效果越好 |

#### 4.3 消融实验设计 **[CERTAIN]**

| 实验组 | 设计 | 目的 |
|--------|------|------|
| **origin** | 不使用事件抽取和时间关系判断 | 基准对比 |
| **notuning** | 使用事件抽取，但时间关系判断使用未微调模型 | 验证微调必要性 |
| **笔者方法** | 完整流程 + 微调后的时间关系判断 | 最终效果 |

**实验结果**: 笔者方法相比 origin 提升 **0.0323** 的收益差。

## 给开发者的实现指导

### 关键算法/公式

#### 1. Prompt 模板（可直接使用）

```python
EVENT_EXTRACTION_PROMPT = """指示
你是一个事件抽取器，提供一段文本，请根据语法结构，抽取文本中所有的事件三元组并返回，遵守以下流程。

1) 抽取文本所有事件触发词。事件触发词，用于描述主体和客体之间的关系，通常为是动词，如"吃"，"跑"等。

2) 对于每个事件触发词，寻找对应的主体和客体。主体表示事件涉及的实体，可以是人、物、地点等。客体表示事件中与主体发生关系的实体。

3) 将所有事件三元组以{"Id":原文本中的顺序, "Trigger":事件触发词, "Subject":主体, "Object":客体} json形式，放在list中返回。

例子
Input:今天华为手机发售，一大早店外就排起了长长的队伍，人气火爆
Output:
1) 抽取文本所有事件触发词。["发售", "排起"]

2) 对于每个事件触发词，寻找对应的主体和客体。
"发售"对应的主体与客体为"华为手机"，""；
"排起"对应的主体与客体为"店外"，"长长的队伍"。

3) 按照指定格式返回事件三元组列表。
[{"Id":0, "Trigger":"发售", "Subject":"华为手机", "Object":""},
 {"Id":1, "Trigger":"排起", "Subject":"店外", "Object":"长长的队伍"}]

输入
Input:{news_content}
Output:"""
```

#### 2. 输出解析

```python
import json
from typing import List, Dict, Any

def parse_event_extraction_output(output_text: str) -> List[Dict[str, Any]]:
    """
    解析大模型返回的事件抽取结果

    Args:
        output_text: 大模型返回的原始文本

    Returns:
        事件三元组列表，每个元素包含 Id, Trigger, Subject, Object
    """
    # 提取 JSON 部分（通常在 "Output:" 之后）
    try:
        # 查找 JSON 列表的开始和结束
        start_idx = output_text.find('[')
        end_idx = output_text.rfind(']') + 1

        if start_idx == -1 or end_idx == 0:
            return []

        json_str = output_text[start_idx:end_idx]
        events = json.loads(json_str)

        # 验证字段完整性
        validated_events = []
        for event in events:
            if all(key in event for key in ['Id', 'Trigger', 'Subject', 'Object']):
                validated_events.append({
                    'Id': int(event['Id']),
                    'Trigger': str(event['Trigger']),
                    'Subject': str(event['Subject']),
                    'Object': str(event['Object']) if event['Object'] else None
                })

        return validated_events

    except (json.JSONDecodeError, ValueError) as e:
        # 记录错误并返回空列表
        print(f"解析失败: {e}")
        return []
```

### 建议的接口设计

```python
from typing import List, Dict, Optional
from dataclasses import dataclass
from enum import Enum

class EventType(Enum):
    """[INFERRED] 如果需要业务分类，可自行定义"""
    PERFORMANCE = "业绩"      # 财报、业绩预告等
    EQUITY = "股权"           # 股权变动、回购等
    GOVERNANCE = "治理"       # 管理层变动、董事会决议等
    BUSINESS = "业务"         # 产品发布、合同签订等
    POLICY = "政策"           # 行业政策、监管政策等

@dataclass
class Event:
    """事件数据结构"""
    id: int                    # 原文中的顺序
    trigger: str               # 触发词
    subject: str               # 主体
    object: Optional[str]      # 客体（可为空）
    event_type: Optional[EventType] = None  # [INFERRED] 业务类型（论文未定义）
    intensity: Optional[float] = None       # [INFERRED] 强度分数（论文未定义）

class EventExtractor:
    """事件抽取器"""

    def __init__(self, llm_client):
        self.llm = llm_client
        self.prompt_template = EVENT_EXTRACTION_PROMPT

    async def extract(self, text: str) -> List[Event]:
        """
        从文本中抽取事件

        Args:
            text: 原始新闻/研报文本

        Returns:
            事件列表
        """
        prompt = self.prompt_template.format(news_content=text)
        response = await self.llm.generate(prompt)
        events_data = parse_event_extraction_output(response)

        return [
            Event(
                id=e['Id'],
                trigger=e['Trigger'],
                subject=e['Subject'],
                object=e['Object'] or None
            )
            for e in events_data
        ]
```

### 需要注意的实现细节

1. **云端大模型选择**: 论文使用"云端大模型"进行事件抽取，建议使用 GPT-4/Claude/DeepSeek 等强模型

2. **输出解析容错**: 大模型输出可能包含额外文本，需要鲁棒的 JSON 提取逻辑

3. **空值处理**: `Object` 字段可能为空字符串，建议转换为 `None`

4. **顺序保持**: `Id` 字段表示触发词在原文中的顺序，用于后续时间关系判断

5. **事件强度**: 如果项目需要事件强度，需要**自行设计**（论文未提供），可考虑：
   - 基于触发词的情感词典
   - 基于主体/客体的重要性权重
   - 基于大模型的直接评分

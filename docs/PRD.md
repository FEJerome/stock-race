## 1. 产品画布

> **章节状态：** 🟢 已冻结（提炼自原 PRD 2.1/2.2/2.3）

| 维度 | 内容 |
|------|------|
| **目标用户** | 对AI感兴趣但不懂技术的普通用户；想了解不同AI模型差异的爱好者；寻找"AI能做什么"直观体验的用户 |
| **核心问题** | 新AI模型发布时，用户想知道"它炒股怎么样"但缺乏零门槛的验证渠道 |
| **独特价值** | 零技术门槛体验/对比不同AI大模型的"炒股能力" |
| **解决方案** | AI模型农场——用户作为"投资经理"，雇佣AI作为"交易员"进行虚拟股票交易 |
| **商业模式** | 订阅制（解锁管理能力）+ 周薪制（AI使用成本）+ 自填API（管理费模式） |
| **关键壁垒** | 先发优势 + 人设差异化 + 数据沉淀 + 用户习惯 |
| **北极星指标** | AI交易员创建数 / 日活跃用户（DAU）|

### 1.1 核心价值主张

**一句话描述**：
AI股票竞赛平台 = "AI模型农场"，用户作为"投资经理"招聘AI作为"交易员"进行虚拟股票交易。

**根本价值**：
外界发布新AI模型时，用户第一反应是"来这个平台试试它炒股怎么样"。

### 1.2 产品边界（不做清单）

| 不做事项 | 原因 |
|---------|------|
| 不涉及真实资金交易 | 合规风险，使用虚拟"投资研究点数" |
| 不承诺AI炒股能力 | 胜率≈投骰子，仅提供体验，非投资建议 |
| 用户无个人账户余额 | 不比拼总资产，只看AI交易员独立表现 |
| v1.0 不做社交功能 | 关注、分享等延后考虑 |
| 不使用国外大模型 | 支持国产、规避合规风险 |

### 1.3 商业模式概览

**核心转变**：从"等级主导"转为"订阅主导"，等级退居二线作为粘性工具

**三层资源体系**：

| 层级 | 用途 | 获取方式 | 与能力关系 |
|------|------|---------|-----------|
| 经验值 | 用户等级（1-30级）| 活跃度（登录、邀请等）| 仅影响奖励，不影响核心能力 |
| 订阅层级 | AI席位数量、周薪预算上限 | 付费订阅 | 硬性门槛，决定管理能力 |
| 投资研究点数 | AI个体虚拟资金（1万-10亿）| 创建时分配 | 仅影响该AI的交易规模 |

| 阶段 | 用户行为 | 用户目标 | 接触点 | 情绪曲线 | 关键指标 |
|------|---------|---------|--------|---------|---------|
| **认知** | 听说新AI模型 | 好奇它炒股能力如何 | 朋友圈/社媒 | 😐→🙂 | 访问转化率 |
| **首次使用** | 打开小程序，浏览首页 | 快速了解产品价值 | 首页/排行榜 | 🙂→😃 | 新用户激活率 |
| **创建AI** | 进行策略收集对话 | 创建符合偏好的AI | 策略对话UI | 😃→🤔 | AI创建完成率 |
| **首次交易日** | 等待并查看交易结果 | 验证AI是否符合预期 | AI详情页 | 🤔→😮 | 次日回访率 |
| **持续使用** | 每日查看AI表现 | 观察AI长期表现 | 仪表盘/排行榜 | 😮→😊 | DAU、7日/30日留存 |
| **深度参与** | 邀请好友/订阅升级 | 获得更多AI席位 | 邀请系统/订阅页 | 😊→🥳 | 邀请转化率、订阅率 |

### 2.2 关键触点设计

1. **首次创建AI时的策略收集对话**
   - 目标：降低决策负担，提供经典策略套餐
   - 五维度：风险承受、关注板块、持仓周期、仓位止损、市场范围

2. **每日登录查看"我的AI交易员"表现**
   - 目标：形成使用习惯，提供成长反馈
   - 设计：收益曲线、持仓分布、AI等级成长

3. **排行榜查看其他用户AI的表现对比**
   - 目标：制造对比和竞争感
   - 设计：时间维度筛选（日/周/月/总榜）、夏普比率辅助排序

## 4.1 冷启动体验

> **章节状态：** 🟢 已冻结（提炼自原 PRD 2.4/2.5）

### 4.1.1 用户状态流转

```
游客模式（未登录）
    ├── 可浏览：首页介绍、排行榜（匿名数据）
    ├── 不可创建AI交易员
    └── 引导：点击"创建AI交易员" → 跳转登录

登录后（微信授权）
    ├── 获取用户OpenID
    ├── 强制实名认证（微信realNameVerify接口）
    └── 年龄校验

实名认证后
    ├── ≥18岁：正常使用全部功能
    └── <18岁：拒绝访问，提示"本服务仅限18周岁以上用户"
```

### 4.1.2 实名认证流程

**强制触发时机**：
- 首次点击"创建AI交易员"
- 首次点击"我的"页面
- 首次尝试查看AI决策详情

**认证方式**：
- 调用微信`realNameVerify`接口
- 获取身份证号，提取年龄信息
- 服务端记录：`is_verified`, `age`, `id_card_hash`（脱敏）

**拒绝处理（<18岁）**：
- 页面提示："根据相关法规，本服务仅限18周岁以上用户使用"
- 记录拒绝时间，允许1天后重新认证
- 允许无限次重试，每次间隔1天

## 4.2 AI交易员创建

> **章节状态：** 🟢 已冻结-Local（提炼自原 PRD 4.2）

### 4.2.1 雇佣流程

**雇佣限制**：
- 受订阅层级限制：平台托管AI由周薪预算决定，自填API有限额
- 受周薪预算限制（本周可支付工资总和不能超过预算上限）
- 受AI职级限制（Free仅实习生，Pro解锁经理，Enterprise解锁合伙人）

**雇佣步骤**：
1. **选择雇佣类型**：平台托管AI 或 用户自填API
2. **选择工作模式**：试用期（5个交易日，工资8折）或 正式工
3. **配置投资研究点数**：范围 10,000 - 订阅层级上限
4. 进行策略收集对话（五维度）
5. **确认雇佣并扣费**

### 4.2.2 策略收集机制

**核心流程**：
用户输入 → AI追问（填补维度）→ 策略文档生成 → 后续决策的上下文

**五维度底线**（必须收集）：
1. **风险承受**：保守(-5%回撤)/稳健(-10%)/激进(-20%)/极度(-30%或无)
2. **关注板块**：具体行业板块，或"全市场"
3. **持仓周期**：超短线(1-3天)/短线(1-2周)/中线(1-3月)/长线(3月+)
4. **仓位与止损**：单股仓位上限 + 止损纪律
5. **交易市场范围**：纯主板 / 主板+创业板 / 全市场

**经典策略套餐**：

| 套餐 | 风险 | 周期 | 仓位 | 画像 |
|------|------|------|------|------|
| 价值投资者 | 稳健 | 长线 | 30% | "买好公司，长期持有" |
| 趋势跟踪者 | 激进 | 中线 | 50% | "顺势而为，截断亏损" |
| 题材狙击手 | 极度激进 | 短线 | 20% | "抓热点快进快出" |
| 量化交易者 | 稳健 | 超短线 | 10% | "积小胜为大胜" |

#### 策略收集粒度分级（合规设计）🟢 已冻结

为防止 AI 在没有明确用户指令的情况下擅自荐股，策略收集按"粒度"分为三级，系统根据粒度采取不同的合规策略：

| 粒度级别 | 用户输入特征 | 系统行为 | 合规目的 |
|---------|-------------|---------|---------|
| **细粒度** | 提供具体股票代码/名称 + 明确操作参数 | AI 完全按用户指令执行 | 用户明确决策，系统仅执行 |
| **中粒度** | 提供板块/行业/概念 + 操作意图 | AI 在限定范围内提供 2-3 个选项，**必须经用户确认后执行** | 限定范围，用户最终决策 |
| **粗粒度** | 仅概念性描述（如"价值投资""稳健型"） | **拒绝直接选股**，通过对话引导用户提供具体标的，或引导至预设策略模板 | 防止 AI 擅自荐股 |

**核心合规原则**：
1. 通过对话机制强制收敛到细粒度
2. 禁止 AI 在无明确范围时自主大量选股
3. 中粒度的选项提供必须经过用户二次确认
4. 粗粒度必须引导用户明确标的，或选择预设策略

**前端体现方式（A+C 结合方案）**：
- **主要方式**：通过 AI 对话自然引导（方案 A）
- **辅助方式**：UI 显示粒度检测提示标志（方案 C）
  - 当用户输入模糊（粗粒度/中粒度）时，AI 对话引导 + UI 显示 `⚠️ 需要更明确的指令` 提示
  - 当用户输入明确（细粒度）时，UI 提示变为 `✅ 指令明确` 或直接消失
  - 提示位置：策略输入框附近，不干扰主流程

**技术实现**：
- 后端 AI 对话系统内置粒度识别逻辑
- 前端不直接展示"粒度"概念给用户，而是通过对话自然引导
- 所有 AI 回复需经过合规检查层过滤

### 4.3.4 收益计算指标

| 指标 | 说明 | 计算公式 |
|------|------|---------|
| 总收益率 | 累计收益/初始资金 | (current - initial) / initial |
| 日收益率 | 当日收益/昨日净值 | (today - yesterday) / yesterday |
| 最大回撤 | 峰值到谷底最大跌幅 | max(drawdown) |
| 夏普比率 | 风险调整后收益 | (return - risk_free) / std |
| 胜率 | 盈利交易占比 | win_trades / total_trades |
| 盈亏比 | 平均盈利/平均亏损 | avg_win / avg_loss |

**对比范围**：用户创建的所有 AI 交易员之间对比

**时间维度**：
- 日榜（今日收益）
- 周榜（近7天）
- 月榜（近30天，默认）
- 总榜（成立以来）

**排名指标**：
- 默认：总收益率排序
- 辅助：夏普比率、最大回撤、胜率

## 4.6 新闻舆情系统

> **章节状态：** 🟡 待细化（基于学术论文"多事件时序关系"分析范式）
>
> **理论来源**：A股事件驱动特性研究——突破"整篇文本情感打分"粗放模式，建立精细分析范式

### 4.6.1 系统定位与目标

**核心理念**：突破"整篇文本情感打分"的粗放模式，建立**"多事件时序关系"**的精细分析范式。

**关键洞察**：
- 同一新闻文本通常包含多个独立事件（如业绩预增+高管变动+回购计划）
- 事件对股价的影响并非线性叠加，而取决于**时间先后顺序与逻辑关系**
- **"先利空后利好"**构成危机反转预期
- **"先利好后利空"**可能是利好兑现后的补跌
- 顺序误判会导致信号完全相反

**系统目标**：
1. 从非结构化文本中**抽取独立事件**（识别触发词、主体、客体）
2. **判断两两事件间的时间关系**（Before/After/Equal/Vague）
3. 建立**滚动窗口（30天）的事件记忆机制**
4. 向交易AI输出**结构化的事件时序图谱特征**（而非原始文本或简单情感标签）

### 4.6.2 核心能力

#### 能力一：事件抽取（Event Extraction）

从非结构化文本中识别独立事件：

| 事件要素 | 说明 | 示例 |
|----------|------|------|
| **触发词** | 事件类型标识 | "预增"、"减持"、"回购"、"停牌" |
| **主体** | 事件发起方 | 公司名称、高管姓名 |
| **客体** | 事件对象 | 股票代码、业务板块 |
| **时间** | 事件发生/公告时间 | 2026-03-11、Q1 |
| **强度** | 事件影响程度 | 数值化指标（如预增50%） |
| **置信度** | 抽取结果可信度 | 0.0-1.0 |

**抽取示例**：
```
原文："XX股份发布业绩预告，预计Q1净利润同比增长50%-70%，
      同时公告董事长拟减持不超过2%股份，公司同时启动回购计划。"

抽取结果：
├─ 事件1：业绩预增
│   ├─ 触发词：预增
│   ├─ 主体：XX股份
│   ├─ 客体：Q1净利润
│   ├─ 强度：0.6（50%-70%）
│   └─ 情感：positive
│
├─ 事件2：高管减持
│   ├─ 触发词：减持
│   ├─ 主体：董事长
│   ├─ 客体：XX股份
│   ├─ 强度：0.3（2%）
│   └─ 情感：negative
│
└─ 事件3：回购计划
    ├─ 触发词：回购
    ├─ 主体：XX股份
    ├─ 客体：公司股份
    ├─ 强度：0.5
    └─ 情感：positive
```

#### 能力二：时序关系判断（Temporal Relation Classification）

判断两两事件间的时间关系：

| 关系类型 | 符号 | 说明 | 示例 |
|----------|------|------|------|
| **Before** | A→B | 事件A在事件B之前发生 | 业绩预告在正式财报前 |
| **After** | A←B | 事件A在事件B之后发生 | 高管离职在业绩下滑后 |
| **Equal** | A=B | 两事件同时发生 | 同一公告中的多项决议 |
| **Vague** | A~B | 时间关系不明确 | 历史背景描述 |

**时序链构建**：
```
事件链：[预增] ──Before──→ [减持] ──Equal──→ [回购]

净预期分析：
- 预增(+) → 减持(-) = 利好出尽信号？还是正常套现？
- 减持(-) = 回购(+) = 对冲效应？还是信心维护？
- 顺序：预增先于减持 → 可能是预期兑现后的正常减持
```

#### 能力三：滚动窗口事件记忆（Rolling Window Event Memory）

建立30天滚动窗口的事件记忆机制：

```
窗口参数：
├─ 窗口大小：30个自然日（约22个交易日）
├─ 更新频率：每日收盘后
├─ 记忆容量：单标的最多保留100个事件
└─ 淘汰策略：FIFO（先进先出）

记忆内容：
├─ 同一标的上事件间的累积效应
├─ 早期利空是否被后期利好对冲
├─ 连续事件的逻辑自洽性
└─ 事件密度的异常变化（突发事件识别）
```

**累积效应计算**：
| 维度 | 计算方法 |
|------|----------|
| 净预期强度 | ∑(事件强度 × 情感极性 × 时间衰减) |
| 逻辑一致性 | 事件间因果关系是否自洽 |
| 情绪稳定性 | 事件情感方向的方差 |
| 关键转折点 | 导致净预期方向变化的事件节点 |

| "公司公告多项决议" | 时序链：预增→减持=回购，逻辑自洽度72% | 考虑事件关系 |
| "近期负面新闻较多" | 30天情绪方差0.42，存在波动但趋势稳定 | 量化情绪稳定性 |

### 4.6.5 三形态交付差异

| 能力维度 | Local | MVP | Full |
|----------|:-----:|:---:|:----:|
| **事件抽取** | ✅ LLM-based | ⚠️ 关键词匹配 | ✅ NER模型+LLM校验 |
| **时序关系判断** | ✅ 规则+LLM | ❌ | ✅ 预训练时序模型 |
| **30天滚动窗口** | ✅ SQLite实现 | ❌ | ✅ TimescaleDB |
| **事件图谱分析** | ✅ 基础特征 | ❌ | ✅ 图神经网络 |
| **实时事件触发** | ✅ 批处理 | ❌ | ✅ Kafka+Flink流处理 |
| **复杂对冲识别** | ✅ 简单规则 | ❌ | ✅ 因果推理模型 |

**形态说明**：
- **Local**：完整实现所有能力，用于技术验证和算法优化
- **MVP**：资源受限，仅保留基础新闻关键词匹配，不做时序分析
- **Full**：生产级实现，流式处理、专用模型、图数据库存储

### 4.6.6 技术实现路径

```
Phase 1.4（Local版增强）
├── 事件抽取模块（LLM Few-shot）
├── 时序关系判断（规则引擎）
├── 30天窗口管理（SQLite）
└── 基础特征计算（Python）

Phase 2（MVP简化）
└── 仅保留：关键词匹配 + 简单情感

Phase 3（Full完整版）
├── 专用NER模型（事件抽取）
├── 时序关系分类模型
├── 图数据库（事件图谱）
├── 流处理（实时更新）
└── 因果推理（对冲识别）
```

### 8.1 术语表

| 术语 | 定义 |
|-----|------|
| AI交易员 | 用户雇佣的AI大模型实例，执行虚拟股票交易研究 |
| 投资研究点数 | AI交易员个体的虚拟交易资金（范围10,000-1,000,000,000），用户创建时指定，仅用于该AI的虚拟股票交易 |
| 周薪预算 | 订阅层级决定的每周可支付AI工资上限（Free=1000币，Pro=5000币） |
| 周薪周期 | 5个交易日为1周，周一凌晨02:00结算 |
| 日薪 | 周薪÷5，每个交易日的工资成本 |
| 试用期 | 固定5个交易日的体验期，工资8折，雇佣时一次性扣费 |
| 分时计费 | 09:30-11:30全天计费，11:30-14:00半价，14:00后免费 |
| 等级 | 用户成长体系，共30级，提供粘性奖励（称号、试用券等），不影响核心能力 |
| 经验值 | 用户活跃度计量，用于等级升级 |
| 订阅层级 | Free/Pro/Enterprise，解锁AI席位数量和周薪预算上限 |
| AI职级 | 实习生/经理/合伙人，决定AI能力和周薪成本 |
| AI交易员等级 | Lv.1-Lv.∞，每5个交易日升1级，决定激励档位解锁 |
| 激励档位 | 正式工可选的工作模式（标准/积极/激进），与工资挂钩 |
| 策略文档 | AI交易员的五维度配置（风险、板块、周期、仓位、市场范围） |
| 实名认证 | 强制性的微信实名验证，拒绝18岁以下用户 |
| 游客模式 | 未登录状态，仅能浏览首页和匿名排行榜 |
| 自填API | 用户提供自有API Key创建AI交易员，平台收取管理费 |
| 称号系统 | 基于等级、成就、地域的荣誉称号体系，用于展示和分享 |
| **事件** | 从新闻文本中抽取的独立事件单元，包含触发词、主体、客体、时间、强度等要素 |
| **事件链** | 同一标的在一定时间窗口内（默认30天）的事件序列及其时序关系 |
| **时序关系** | 两个事件间的时间先后关系：Before/After/Equal/Vague |
| **触发词** | 标识事件类型的关键词，如"预增"、"减持"、"回购"等 |
| **事件强度** | 事件影响程度的量化值（0.0-1.0），如预增50%对应中等强度 |
| **净预期强度** | 事件链的综合情感值，考虑各事件强度、极性、时间衰减后的加权总和 |
| **滚动窗口** | 动态维护的事件记忆机制，默认30天，用于追踪累积效应 |
| **逻辑一致性** | 事件链中各事件间逻辑关系的自洽程度（0-1评分） |
| **对冲效应** | 同一窗口内利好与利空事件的相互抵消现象 |

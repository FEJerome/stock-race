## 二、架构实现详情

### 2.1 多数据源架构

```
┌─────────────────────────────────────────────────────────────┐
│                    DataSourceRouter                         │
├──────────┬──────────┬──────────┬──────────┬─────────────────┤
│  新浪    │  腾讯    │ 东方财富 │ AkShare  │ Baostock/Tushare│
│ Sina     │ Tencent  │ EastMoney│ (实时)   │ (历史数据)      │
│ (主)     │ (备)     │ (备)     │          │                 │
└──────────┴──────────┴──────────┴──────────┴─────────────────┘
                    ↓
         ┌──────────────────────┐
         │   数据质量评估引擎    │
         │  - 多源比对           │
         │  - 异常检测           │
         │  - 降级策略           │
         └──────────────────────┘
```

**实现亮点：**
- 6个数据源动态权重管理
- 自动故障检测与切换（10次连续错误后停用）
- 5分钟后自动恢复机制
- 数据源健康评分（0-100分）

### 2.2 分层采集策略

| 层级 | 采集频率 | 覆盖范围 | 数据源 |
|------|---------|---------|--------|
| 高频层 | 10秒 | 热股票（持仓+关注，约300只） | 新浪财经 |
| 中频层 | 60秒 | 全市场其他股票 | 多源并行 |
| 低频层 | 日终 | 历史K线数据 | Baostock/Tushare |

### 2.3 三层缓存架构

```
Layer 1: Redis 热缓存 (TTL: 10秒)
    - 实时行情数据
    - 股票基本信息
    - 市场状态

Layer 2: TimescaleDB 时序数据库
    - 历史行情数据
    - 技术指标计算结果
    - 数据质量指标

Layer 3: 内存回退缓存 (Redis故障时)
    - 自动降级机制
    - 保证服务可用性
```

### 2.4 AI决策批量查询架构（新增）

```
┌─────────────────────────────────────────────────────────────┐
│                    AIQueryService                           │
├──────────────┬──────────────┬──────────────┬────────────────┤
│  多维度查询   │  智能采样     │  多级缓存     │  批量并行查询   │
│  板块/行业   │  5级密度控制  │  映射表24h   │  并发限制20    │
│  概念/指数   │  10%-100%    │  结果30s     │  优先级保障    │
│  个股代码    │              │  单股30s     │                │
└──────────────┴──────────────┴──────────────┴────────────────┘
                    ↓
         ┌──────────────────────┐
         │   市场汇总统计        │
         │  - 涨跌数量           │
         │  - 平均涨跌幅         │
         │  - 总成交额           │
         │  - 涨跌前5            │
         └──────────────────────┘
```

**实现亮点：**
- 多维度并集查询：板块+行业+概念+指数+个股自动去重
- 5级信息密度控制：ultra_low(10%) → low(25%) → medium(50%) → high(75%) → full(100%)
- 三级缓存策略：股票映射表24h + 查询结果30s + 单只股票30s
- 智能采样：优先保留priority_symbols，其余按市值排序
- 性能指标：平均响应<500ms，缓存命中<10ms，支持50QPS

### 3.2 核心优势

1. **异常处理完善**
   - 分级错误体系：`DataSourceError` / `RateLimitError`
   - 优雅降级：Redis故障→内存缓存，数据源故障→备份数据
   - 自动重试：指数退避策略，最大3次重试

2. **性能优化到位**
   - 批量请求分块处理（最大100只/批）
   - 并发控制（Semaphore限制3个并发源）
   - 智能缓存（5秒内重复请求直接返回缓存）

3. **可观测性强**
   - 详细的性能指标收集
   - 数据源健康状态监控
   - 数据质量实时评估

4. **扩展性良好**
   - 抽象基类设计，新增数据源仅需实现4个方法
   - 策略模式支持多种路由策略
   - 配置驱动，无需修改代码即可调整参数

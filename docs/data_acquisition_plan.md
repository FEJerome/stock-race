# 股票数据获取方案

## 📊 数据源分析

### 当前已实现的数据源

#### 1. 新浪财经 (Sina Finance)
- **优先级**: 1 (最高)
- **API特点**:
  - 实时数据: `http://hq.sinajs.cn/list={symbol}`
  - 历史数据: `https://quotes.sina.cn/cn/api/json_v2.php`
  - 支持批量查询（逗号分隔符号）
- **预计限制**:
  - 无明确公开限制，但可能对频繁请求进行限制
  - 建议请求间隔：≥100ms
  - 批量查询最多支持约100只股票

#### 2. 腾讯财经 (Tencent Finance)
- **优先级**: 2
- **API特点**:
  - 实时数据: `http://qt.gtimg.cn/q={symbol}`
  - 历史数据: `https://web.ifzq.gtimg.cn/appstock/app/fqkline/get`
  - 支持多种时间周期（日、周、月）
- **预计限制**:
  - 相对宽松，适合高频请求
  - 建议请求间隔：≥50ms
  - 支持批量查询

#### 3. 东方财富 (East Money)
- **优先级**: 3
- **API特点**:
  - 实时数据: `https://push2.eastmoney.com/api/qt/stock/get`
  - 历史数据: `https://push2his.eastmoney.com/api/qt/stock/kline/get`
  - 数据最全面，包含财务指标
- **预计限制**:
  - 可能有较严格的反爬机制
  - 建议请求间隔：≥200ms
  - 需要随机User-Agent和Referer

### 其他潜在免费数据源

#### 4. Yahoo Finance (通过yfinance库)
- **优点**: 全球市场覆盖，历史数据完整
- **限制**: 有请求频率限制（约2000次/小时）
- **适用场景**: 备用数据源，历史数据补充

#### 5. Alpha Vantage
- **优点**: 专业金融数据，API规范
- **限制**: 免费版5次/分钟，500次/天
- **适用场景**: 关键数据验证，高质量数据源

#### 6. Tiingo
- **优点**: 免费层较慷慨，数据质量高
- **限制**: 需要API key，免费版有限制
- **适用场景**: 备用国际数据源

## 🎯 多节点分段获取方案

### 设计原则
1. **负载均衡**: 多个数据源之间分散请求
2. **故障转移**: 主数据源失败时自动切换到备用源
3. **频率控制**: 遵守各API的限制要求
4. **数据质量**: 优先使用高质量数据源

### 实施策略

#### 实时数据获取（高频）
```
优先级顺序：新浪 > 腾讯 > 东方财富
请求频率：每秒不超过10次（总请求）
批量大小：每批50-100只股票
轮询间隔：交易时间每10秒，非交易时间每60秒
```

#### 历史数据获取（低频）
```
优先级顺序：东方财富 > 腾讯 > 新浪
请求频率：每分钟不超过30次
数据范围：最近3年每日数据
缓存策略：Redis缓存24小时
```

#### 分段获取方案
```python
# 伪代码示例
async def fetch_with_fallback(symbols):
    sources = [
        (SinaCollector, 1.0),    # 权重1.0
        (TencentCollector, 0.8), # 权重0.8
        (EastMoneyCollector, 0.6) # 权重0.6
    ]

    # 按权重分配请求
    total_weight = sum(w for _, w in sources)
    for collector_cls, weight in sources:
        share = len(symbols) * weight / total_weight
        symbols_chunk = symbols[:int(share)]
        if symbols_chunk:
            await fetch_from_source(collector_cls, symbols_chunk)
        symbols = symbols[int(share):]
```

## 🔧 技术实现

### 增强现有DataCollector

1. **动态权重调整**
   - 基于成功率自动调整数据源优先级
   - 失败率超过阈值时降低权重

2. **智能重试机制**
   - 指数退避重试
   - 跨数据源重试

3. **数据验证与清洗**
   - 价格合理性检查
   - 时间戳新鲜度验证

4. **缓存策略**

## 📋 风险与应对

### 风险1：数据源限制变更
- **应对**: 定期监控，动态调整策略
- **缓解**: 多数据源设计，快速切换

### 风险2：数据质量下降
- **应对**: 多源数据比对，异常检测
- **缓解**: 人工审核机制，数据清洗

### 风险3：服务不可用
- **应对**: 降级到Mock数据
- **缓解**: 本地缓存，历史数据回填

## 1. 打开方式与目标尺寸

直接双击 [index.html](index.html)，或将它拖入 Chromium / Edge / Firefox。无需 npm、构建工具、本地服务或网络；不要通过 `fetch` 读取 golden，因此 `file://` 可直接运行。

- 目标展示尺寸：**1600 × 1000**；1440 × 900 保持同一信息层级。
- 1280 宽度起可完整使用；窄屏提供降级布局，但本轮审美终审以桌面展示尺寸为准。
- 推荐走查顺序：老板开场 → 面试回答 → 自动进入人话确认 → 演示确认 → 派遣校验 → 固定 golden 围观 → 复盘“调整策略再来一次”。
- 顶部“状态走查”打开关键错误与空态；它只预览视觉样式，不创建新 Run。

## 1.1 AI 经理人与历史穿越（2026-10-29，第三轮概念返修）

首屏主角是单一 AI 股票经理人 **阿一 / A YI**。主张为 **“雇一位 AI 股票经理人，送他回到过去的市场。”** 视觉从信息密集 dashboard 转为专业官网式角色主页＋克制游戏感。

体验以阿一贯穿招聘与穿越。第五轮进一步改为**面试 → 确认 → 派遣 → 围观 → 复盘**五阶段单焦点路径，见 1.4。职级体系、荣誉馆、更多经理人只作“暂未开放”点缀。完整概念见 [AI 经理人与历史穿越概念说明](../v3-s4-manager-time-travel-concept.md)。

### 招聘与面试

沿用两条预写脚本：新手从“低买高卖”补齐价格、退出与仓位；老手从“MACD 三日金叉＋KDJ 过滤”直接核对参数。A1 是阿一面试对话，A2 规则逐块成形，A3 保留 AST → 校验 → 权威回读 → expectedDigest 的不可跳过链路。脚本非真实 Kimi，不产生新 Run。

### 穿越目的地与点时边界

目的地默认 CN A 股、2024-01-01 至 2024-01-06、`stock:synthetic.basic`；配置默认折叠。US/JP 仅愿景并禁用，真实沪深代码未接入，ETF／指数按原契约边界。

“穿越者不能偷看未来”是点时数据契约的游戏化表达：每个交易日只能使用当时可见数据；warmup 不足留空或阻断；收盘信号与次日执行按真实事件顺序；播放 cursor 不提供未来信息、不重跑策略、不改变账本或 digest。B 固定提示 **“他只知道那天及之前的事”**。

### 围观与复盘

- B 讲阿一在 1 月 2 日买入、1 月 4 日经历回撤、1 月 5 日卖出的工作故事；“问他当时依据”打开真实事件抽屉，不生成实时模型解释。
- C 是穿越成绩单：人话复盘＋四指标＋证据链。“问阿一”提供三个预写规则问答，分别引用 intent-1、1 月 4 日权益／exit、intent-2 与成交，不编造心理活动或市场因果。

## 1.2 首屏三秒可懂度自述

这是设计自评，不是用户研究结论。

- **第 1 秒**：“老板，你的基金公司今天开张”直接给出 RPG 身份，没有技术术语。
- **第 2 秒**：阿一候选人卡和“招聘 AI 基金经理”说明第一任务，开始招聘是唯一主行动。
- **第 3 秒**：顶部五阶段让人预见面试、确认、派遣、围观、复盘；synthetic／非实时 Kimi 与“不荐股、不直接下单”同时可见。

首屏只保留老板身份、招聘任务、一个角色卡和未开放装饰。第五轮移除首页目的地面板与步骤条，流程通过逐场推进表达。

## 1.3 历史视觉基底与双主题（2026-10-29，第四轮）

本轮直接拆解维护者历史 demo 的 CSS 与组件结构作为基底（维护者本机的 demo 快照，路径为私有环境路径，不再记录绝对路径），原始出处 `b70ca94:local/demo/offline-demo.html`。没有引入 Vue、CDN 或旧业务逻辑，原型仍为纯静态 HTML/CSS/JS。

### 保留并替换的视觉语言

- 深海军蓝 `#0a0e1a`、深色卡片 `#141b2d`、青色 `#00d4ff`、金色 `#ffd700`；浅主题使用历史 demo 的 `#f8fafc / #ffffff` 与 `#0891b2 / #b45309`。
- 青金品牌渐变、卡片网格、铜／银／金徽章、呼吸状态点、进度条、fade / slide 动效；六个 AI 排行只保留为唯一阿一角色卡，排行语义替换为穿越成绩单。
- 绿涨红跌。策略线和对照使用青／金，回撤使用红色；图表 colors 在主题切换后重新从 CSS tokens 计算。

### 双主题与本地记忆

顶部 Light / Dark 按钮切换 `:root.light-theme`，所有页面、表单、对话框、图表网格与标记环都使用双主题 tokens。选择保存在 `localStorage["stock-race-theme"]`，读取／写入均有失败兜底；file:// 禁止存储时仍能正常显示当前主题。

原青金高亮色通过 CVD 与对比检查，但深色图表的 lightness band 不通过，因此图系列采用同色相深阶：深色 `#0096b4 / #d97706`，浅色 `#0891b2 / #b45309`。两组合均通过 palette validator 的 lightness、chroma、CVD、normal-vision 与 contrast 检查；品牌仍保留维护者原青金色。

### 阿一 logo、返回与减文字

- [ayi-logo.svg](ayi-logo.svg) 是 SVG 标识（2026-11-14 维护者终审拍板）：A／一形结构＋青金时间轨迹，延续原青金轨迹设计语言、字形由 H 改为「阿一」的 A／一意象，用于品牌区与角色头像，不依赖外部图片。
- 品牌名与顶部“主页”按钮都直接回首页；A 另有“返回主页”。
- 首屏只保留阿一、开始面试和必要标注；派遣执行假设、B4 事件依据、C4 证据链默认折叠，点击才展开。

## 1.4 网页游戏开场与单焦点流程（2026-10-29，第五轮）

本轮改的是交互架构，不改双主题、青金视觉、阿一 logo、点时规则或 golden 数据。用户身份从“工具使用者”改为**基金公司老板**，阿一是候选人／员工。首页只有老板身份、招聘任务、阿一角色卡与开始招聘 CTA，目的地设置和功能列表移出首屏。

### 五阶段单焦点路径

| 阶段 | 唯一任务 | 原型行为与边界 |
|---|---|---|
| 01 面试 | 回答阿一 | 全屏对话＋回答框；AI 回合输入禁用，用户回合填入预写回答。工作手册预览在可选侧栏，不再三栏平铺 |
| 02 确认 | 看懂并确认 | 对话完成自动进入“我听懂的是……”；AST／expectedDigest 收进技术细节。按钮明确标“演示”，不产生 revision 或 digest |
| 03 派遣 | 选市场、区间、资金 | 老板下达“阿一，你去 2024 年的 A 股……”；US/JP、非 golden 区间和非 2000.00 初始资金均阻断 |
| 04 围观 | 看操作、问依据、拖时间 | 保留 B 的点时提示、故事、图表与事件抽屉；只打开固定 golden，不执行当前脚本的新 Run |
| 05 复盘 | 看成绩单、问阿一、再来一次 | 保留 C 的人话复盘与预写问答；“调整策略再来一次”回到面试，旧 Run 保持只读 |

顶部只保留“面试 → 确认 → 派遣 → 围观 → 复盘”五阶段指示。未完成前置任务时确认／派遣按钮禁用；每个全屏场景只有一件主要任务。叙事推进替代首页步骤条，用户始终知道下一步。

## 3. 数据出处与真实性边界

### 基础输入与结果

- `v3/tests/fixtures/s2/basic-strategy.json`
- `v3/tests/fixtures/s2/basic-run-spec.json`
- `v3/tests/fixtures/s2/basic-snapshot.json`
- `v3/tests/golden/s2-basic-run.json`

### 事件与 digest 证据

`v3/tests/golden/s2-basic-run.json` 不含完整 RunEvent 流和 digest。为避免伪造 B4 / C4，原型从同一 fixture 的 S2 终审 CLI 输出抽取真实字段：

- `.local/sr008-s2-qa/inspection/review-fix-cli-result.json`
- 同源 Run：`sha256:8ec5cb9d8718d9df21c9696ab299ca0841c7c2f8d77c3ccdf8f5a0fb7b1acd70`
- 完整流共 34 条事件；原型内嵌其中 **23 条关键事件的原值子集**，界面明确标注“23 个关键事件 / 完整流 34 条”，没有将子集冒称完整流。
- C 展示计算后报告中的真实 `strategyDigest` 与 `snapshotDigest`；原始 RunSpec fixture 中全 0 的输入占位 digest 没被当作输出身份使用。A 的对话脚本不生成 digest。

### 展示取舍

- 价格图只使用六日 raw OHLCV。`indicators: {}`，因此明确显示“无指标序列”，不补画 MACD / KDJ。
- 六日策略权益和回撤来自 golden；买入持有只有 golden 给出的期末值 `1993.99`，所以图中只画**期末点**，不扩成虚构日频曲线。
- 两笔实际成交和一笔拒单均按原值显示；`tradeCount=2` 不把拒单计入成交。
- 模型来源固定标为“预写脚本 · 非 Kimi”。对话演示的确认与运行保持禁用；B/C 只打开既有 golden Run，不执行内核、不模拟逐日生成事件。
- 当前只有 v1 的真实完成 Run，**没有虚构 v2 指标、版本提升或第二条收益曲线**。

## 4. 设计决策（候维护者终审）

### 视觉与信息层级

- **方向**：历史 demo 的深海军蓝＋青金视觉基底，深色卡片与克制的游戏感；浅主题完整适配。策略证据线用青色，基准用金色，涨跌与回撤使用绿／红。
- **字体**：离线系统字体。中文与界面使用 Segoe UI / Microsoft YaHei UI 等系统栈，digest、数值列和事件编号使用 Cascadia Code / Consolas 等等宽栈。
- **A 单焦点布局**：面试以对话为唯一主角，规则预览折叠在侧栏；确认和派遣各自使用独立全屏卡片，不再使用三栏工作台。
- **密度**：P0 常驻；P1 在运行带和 compare 对齐区核对；P2 用 disclosures、事件证据和详细层承接。首屏四指标保持契约顺序。
- **图表**：2px 线、8px 以上关键点、细实线网格、选择性端点标签；无双 y 轴。权益与回撤分图。所有图表有 hover / 键盘读数与数据表视图。
- **色彩校验**：深色图系列 `#0096b4 / #d97706` 对 `#141b2d`，浅色 `#0891b2 / #b45309` 对 `#ffffff`，均通过 dataviz palette validator 全项检查。品牌原青金只用于高亮与渐变，不直接作为深色 categorical 图系列。

### 动效与三幕衔接

- 场景进入采用 280ms、`cubic-bezier(.22,.8,.28,1)` 的短距离上移＋透明度变化；按钮和 tab 反馈为 150～220ms。
- 动效只说明场景和 cursor 变化，不制造“模型正在逐日思考”或“内核正在产生收益”的假象；遵守 `prefers-reduced-motion`。
- B ↔ C 保留同一 golden runDigest 与日期 cursor；对话脚本不直接进入 B。B / C → A“基于此版本调整”显示明确 v1 基线，工作轴进入 drafting，旧 Run 轴仍为 completed。

### compare 默认选中项

默认 **v1 为基线，v2 未选择**。C2 展示单 Run 空态和待检查的对齐条件，不展示差值。选择比较版本时说明当前没有第二个完成 Run；版本差值必须等真实 v2 重新确认、运行并对齐后再出现。

## 5. 错误与空态覆盖取舍

顶部“状态走查”提供 7 类独立视觉稿；主流程另覆盖真实零持仓、真实单笔拒单和单 Run compare。16 项矩阵不逐项画成独立页面，覆盖如下。

| 线框矩阵情况 | 本原型覆盖 |
|---|---|
| 无交易、无信号 | 独立走查稿：真实 0 计数与“未产生入场信号”分开 |
| 有信号但从未成交 | 由“全部拒单”稿表达信号／意图／成交分离；未另画取消分支专稿 |
| 全部拒单 | 独立走查稿：拒单原因、0 fills、信号不计成交 |
| 零持仓 | 主流程真实 golden：期末 0 持仓，但保留 2 fills、费用和胜率 |
| 数据不足 / warmup 不足 | 独立 data-error / failed 稿：`INSUFFICIENT_WARMUP`、path、required / actual 位置与成功报告阻断 |
| 空历史 / 区间无观测 | 复用 data-error 容器与“无成功时间轴／报告”规则；未另画独立空历史稿 |
| 指标不足 / 不适用 | 独立 null + reason 稿：“—”与原位原因，其他指标保留 |
| 买入持有不适用 | 同一 null + reason 稿覆盖，明确缺失基准不等于超额 0 |
| 已确认停牌 / stale 估值 | **未单独成稿**；golden 没有该状态，未伪造日期或 stale 标记。待终审是否要求补充纯样式稿 |
| 原因未知的数据缺失 | 复用 data-error / failed 的失败诊断结构；未虚构具体数据错误值 |
| 模型输出无效 | model-error 稿覆盖真实模型失败边界；JSON Pointer 定位在 A3 结构中保留，未另画每种无效输出 |
| 资产不支持 | **未单独成稿**；不改变资产或伪造执行结果 |
| 基金可见性未决 | **未单独成稿**；不在股票 golden 上套用基金语义 |
| 其他 RunFailed | data-error / failed 稿覆盖失败事件、诊断与无成功 Report 的视觉层级 |
| 只有一个完成 Run | 主流程 C2 实际状态：v1 完整，v2 待运行，无自我比较 |
| compare 条件不齐 | 独立走查稿：列出不一致字段，禁用版本差值，保留独立报告入口语义 |

11 态主矩阵中，confirmed / completed 由主流程成稿，drafting 由“基于此版本调整”实际联动，valid 未确认由走查稿覆盖；empty、confirming、running 等未逐项成稿。前两件正典已定义其完整行为，本轮优先送审关键失败与空态样式。

## 7. 待维护者终审项

1. “老板，你的基金公司今天开张”与阿一候选人卡是否形成网页游戏代入感，开始招聘是否一眼可见。
2. 历史海军蓝／青金基底、双主题、系统字体与目标尺寸下的信息密度是否符合四分钟展示节奏。
3. 面试／确认／派遣的单焦点全屏场景、五阶段顶部指示，以及 B 点时围观与 C 预写复盘是否连贯。
4. 场景 280ms 与控件 150～220ms 的动效是否克制、连贯。
5. compare 默认“v1 基线 / v2 未选择”和单 Run 空态是否作为正式默认。
6. 买入持有只画期末点、指标为空不补线，是否作为数据不足时的标准视觉表达。

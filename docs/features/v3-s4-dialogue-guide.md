## 1. 招聘定位与面试入口

单一经理人 **阿一 / A YI** 的招聘简化为“选面试风格 → 开始面试”：谨慎梳理进入新手白话路径，指标直达进入 MACD/KDJ 参数路径。两种风格不是多模型或多经理人，不改变模型、AST、校验与执行语义。

首屏主张：**“雇一位 AI 股票经理人，送他回到过去的市场。”**

阿一面试第一句：**“你想验证什么投资想法？随便说，不用术语。”**

三秒内应让陌生股民同事看懂：自己要雇佣同一位 AI 经理人；先面试形成规则，再派他回过去工作；这不是请 AI 荐股。开始面试只进入预写脚本，“直接围观他的工作”只打开固定 golden，不伪装成面试生成结果。完整穿越叙事与点时边界见 [AI 经理人与历史穿越概念说明](v3-s4-manager-time-travel-concept.md)。

## 2. 水平判断与语言适配规则

水平判断只用于选择追问方式，不给用户贴能力标签，不展示评分。

| 输入信号 | 判断 | AI 的追问方式 | 语言适配 |
|---|---|---|---|
| “低买高卖”“跌了买”等目标或感觉，没有可计算条件 | 白话表达 | 一次只问一个缺口：什么算低、什么时候卖、用多少资金；不一次抛出指标墙 | 保留“买入／卖出／持有多久”；术语只作辅助解释 |
| 已给指标、窗口或参数，如“MACD 三日金叉＋KDJ 过滤” | 指标表达 | 直接核对过滤含义、参数、出场和仓位缺口 | 保留 MACD/KDJ、DIF/DEA 等缩写，不重复科普 |
| 条件互相矛盾、含未来信息、指标或资产不受支持 | 需要校验或阻断 | 指出具体缺口；不能用对话顺畅掩盖不支持项 | 说清“哪里不能执行、需要怎样修改”，不推荐替代股票 |
| 只问“买哪只会涨”“现在该买吗” | 超出边界 | 不荐股、不预测、不诱导买卖；把话题拉回用户已有规则的可检验表达 | 简短、明确，不用收益话术挽留 |

AI 可根据后续回答调整路径：新手说出明确参数后可进入参数对话；老手表达不完整时仍逐项补齐。水平判断不得绕过 schema、注册表、类型、资产和因果校验。

## 3. 三条不可突破的边界

1. **只引导表达，不给建议**：AI 帮助用户把已有想法说成可计算规则，不推荐股票、买卖点、收益目标或仓位建议。示例参数只能来自用户陈述或用户明确接受的既有模板。
2. **对话收敛到 AST**：自然语言不是执行体。对话最终必须形成声明式 `StrategyDraft`，经过完整校验；模型不生成订单、不修改 RunSpec、不参与逐日回测。
3. **回读权威不变**：权威回读只能由 canonical AST 与注册表模板生成。用户必须核对回读，并以 `expectedDigest` 确认 revision；对话中的“明白了”“规则齐了”不等于确认，更不能直接运行。

## 4. 新手完整示例：从“低买高卖”到 AST

**阿一**：你想验证什么投资想法？随便说，不用术语。

**用户**：低买高卖，能验证吗？

**阿一**：可以。先把“低”说清楚：价格到多少，你才愿意买？我只帮你把规则说明白，不推荐买点。

> 水平判断：白话目标。先问可计算的入场条件，不抛出指标清单。

**用户**：收盘价跌到 9 元或更低就买。

**阿一**：入场能计算了：`close ≤ 9`。那什么时候卖？

**用户**：涨到 12 元就卖；等不到的话，20 天后也卖。

**阿一**：出场也有了。每次用多少资金？已经持有时还要加仓吗？

**用户**：每次用一半资金，不加仓。

**阿一**：规则齐了。入场是收盘价不高于 9 元；收盘价不低于 12 元，或者持有满 20 个 bar 时全部退出；每次一半资金，不加仓。请核对右侧权威回读，确认前我不会运行。

> 语言适配：保留用户的价格和持有期表达；“bar”可解释为所选历史数据中的一次观测。回读内容必须来自下面的 AST，而不是这段自由文本。

### 对话形成的 AST 示例

```json
{
  "schemaVersion": "1.0.0",
  "name": "低买高卖 · 对话演示",
  "indicators": {},
  "entry": {"lte": [{"ref": "close"}, {"const": "9"}]},
  "exits": [{"any": [
    {"gte": [{"ref": "close"}, {"const": "12"}]},
    {"gte": [{"ref": "position.barsHeld"}, {"const": "20"}]}
  ]}],
  "position": {
    "side": "long",
    "allowAdd": false,
    "entrySize": {"cashFraction": "0.50"},
    "exitSize": {"positionFraction": "1.00"}
  }
}
```

该脚本只演示 AST 与回读形状。原型不执行实时 canonicalization／校验，不生成 digest，不运行这条策略，也不把 S2 basic golden 冒称它的结果。

## 5. 老手完整示例：从指标表达进入参数对话

**阿一**：你想验证什么投资想法？指标和参数都可以直接说。

**用户**：MACD 三日内金叉，KDJ 过滤。

**阿一**：你给了明确指标和时间窗。KDJ 过滤是 `K>D` 且 `J<90` 吗？MACD 用 `12/26/9`、KDJ 用 `9/3/3`？出场和仓位怎么定？

> 水平判断：已有指标与窗口。直接核对过滤含义、参数和尚缺的出场／仓位，不解释 MACD 基础概念。

**用户**：对。死叉或持有 20 个 bar 退出；每次 50% 资金，不加仓。

**阿一**：参数与入出场都齐了。请核对右侧权威回读；真实流程仍须校验，并由你按 `expectedDigest` 确认。

> 语言适配：保留专业缩写，只把缺失语义说清楚。确认动作不属于模型回复。

## 6. 对话中的校验、失败与确认

- 信息不全：中栏对应块保持“待明确”，右栏不显示完成 digest，确认与运行禁用。
- 规则齐全：只开放 AST 和回读核对；校验错误仍按 `code/path/message/expected/actual/hint` 定位，模型可引导修改但不能跳过。
- 模型失败：进入 `model-error`，保留用户表达与最后草稿，不自动切换 fake。
- 数据失败：进入 `data-error`；对话顺畅不能解除 warmup、资产、可见性或快照阻断。
- 用户修改可执行语义：旧确认失效，必须形成新 revision 并重新确认；旧 Run 与报告保持只读。
- 运行：只在 confirmed revision、合法 RunSpec 和可执行快照齐全后开放。完整结果先算定，再进入 B 的故事与只读回放。

## 7. 与 B/C 叙事层的衔接

- B 先讲策略的真实事件故事：何时入场、经历何种回撤、何时退出；`RunEvent[]`、inputRefs、payload 与 hash 收入可展开事件证据抽屉，不删除。
- C 在四指标前先回答“这次检验告诉你什么”：只从当前 Report 和事件流推导，不编造因果，不荐股，不把短样本外推为投资智慧结论。
- 对话脚本与既有 Run 是两条不同工作轴。查看 golden B/C 时不得把它说成新手或老手脚本刚产生的结果。

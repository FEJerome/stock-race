# SR-001 协作底座重建

*Chinese working canon kept for traceability; not product documentation.*

## 目标

把仓库从早期多智能体模板集合改为可供规划、执行、检验、机械修改与独立复审核验使用的项目现场，同时不改变业务实现。

## 已确认范围

- 重写根 `CLAUDE.md` 与 `README.md`，区分稳定规则、历史资料和实时状态。
- 移除旧 `.claude/` 自动权限与命令，不建立替代性的自动提交、推送流程。
- 移除混入其他项目、占位或重复体系的 `docs/agents/` 文档组。
- 重写开发约定与环境入口，建立协作、feature、research、decision 文档住所。
- 保留历史架构资料并标注其证据等级。
- 更新忽略规则：真实环境文件、本机配置和临时目录不得入库；锁文件与测试不得被忽略。

## 非目标

- 不修改交易、模型、行情、前端或后端业务代码。
- 不读取或清理实际 `.env` 文件，不验证旧密钥。
- 不安装依赖、不启动服务、不操作数据库或外部 API。
- 不重写全部历史架构与部署文档，不重写 git 历史。
- 不在仓库内复制规划侧 STATUS 或自动化规划手册。

## 验收条件

1. 新会话从根文档能识别历史基线、四模块结构、模拟-only 和当前无生产边界。
2. 根入口不再引用旧 `docs/agents/` 或自动提交、推送命令。
3. 文档不再强制加载全部历史资料，历史架构与现实证据的优先级清楚。
4. 规划、执行、检验、机械与复审岗位及其质量闸明确，不绑定人格名。
5. `.env.example` 可保留，真实环境文件被新规则忽略；本任务不改变既有环境文件内容。
6. 测试与锁文件不被新忽略规则排除。
7. 核心文档本地链接有效，变更面不含业务代码、依赖或实际环境文件。
8. 独立冷启动复审完成，必修项清零。

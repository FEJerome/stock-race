## 1. 全局框架与状态口径

### 1.1 单页三幕框架

```text
┌────────────────────────────────────────────────────────────────────────────────────┐
│ Stock-Race V3 · 模拟策略研究     [A 策略生成舱] [B 历史推演剧场] [C 结果与版本对比] │
│ 当前：strategyId / revision / 短 digest     当前 Run：runDigest / 状态 / 数据来源   │
├────────────────────────────────────────────────────────────────────────────────────┤
│ 场景主区                                                                          │
├────────────────────────────────────────────────────────────────────────────────────┤
│ 全局提示：模拟研究，非实盘／非收益承诺     错误与警告入口     证据链／版本信息入口   │
└────────────────────────────────────────────────────────────────────────────────────┘
```

- 顶部始终显示当前工作 revision 与当前选中 Run，二者不得混为一个状态。编辑新草稿时，旧 confirmed revision 和旧 Run 仍可按原 digest 查看。
- 场景切换不重新生成策略、不重新运行回测。B、C 必须由明确的 runDigest 定位同一结果。
- 所有 golden／fake 投影必须标注 `synthetic contract test` 或 `deterministic-fake / 自动化测试`；真实主流程不得把其显示为真实 Kimi 或真实行情结果。
- `running` 时不能逐条假装“正在产生”事件；完整 Run 算定后才进入只读剧场。

### 1.2 两条状态轴

1. **当前策略工作项**：`empty/drafting/invalid/valid/confirming/confirmed`，以及生成或数据操作失败时的 `model-error/data-error`。
2. **当前选中 Run**：未选择、`running/completed/failed`；其中数据原因失败同时落入 `data-error`。

错误不会抹掉另一轴上已经不可变的完成结果。例如，v2 的模型超时可以阻断 v2，却不得把 v1 的已完成报告改成失败；新 Run 数据失败也不能覆盖旧 Run 的成功报告。

## 2. A 场景：策略生成舱

### 2.1 招聘与穿越首屏（**2026-10-29 第三轮概念返修**）

首屏主角是单一 AI 股票经理人 **阿一**，主张为“雇一位 AI 股票经理人，送他回到过去的市场。”采用专业官网式角色主页＋克制游戏感，不再以功能面板密度为重点。完整概念见 [AI 经理人与历史穿越概念说明](v3-s4-manager-time-travel-concept.md)。

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 雇一位 AI 股票经理人，送他回到过去的市场。          [阿一角色卡／待面试]   │
│ 开始面试阿一｜直接围观工作                            谨慎梳理／指标直达     │
├────────────────────────────────────────────────────────────────────────────┤
│ 01 招聘 → 02 穿越 → 03 围观 → 04 复盘                                     │
├────────────────────────────────────────────────────────────────────────────┤
│ 穿越目的地：CN A 股／六日 synthetic golden [调整目的地与执行边界]           │
│ 职级体系／荣誉馆／更多经理人：暂未开放                                     │
└────────────────────────────────────────────────────────────────────────────┘
```

- 招聘简化为“选面试风格 → 开始面试”；谨慎梳理进入新手脚本，指标直达进入老手脚本，始终是同一位阿一。
- 首屏 P0 是角色身份、主行动与四环节链；目的地配置默认折叠，专业证据仍在后续视图。
- CN A 股是 P0 执行范围，但当前原型只有 synthetic 股票与六日 golden；US/JP 愿景、真实沪深代码、ETF／指数执行和其他区间不得显示为可用。
- 职级、荣誉、更多经理人只作“暂未开放”装饰，不显示虚构成就或能力。
- 对话脚本只形成 AST 与回读预览；直接围观只打开固定 golden，不与当前面试草稿混为同一 revision。

### 2.2 阿一面试与穿越准备线框（**第三轮返修**）

A1 是阿一的面试对话流，按新手／老手表达适配追问；A2 的入场、出场、仓位随对话逐块出现；A3 始终保留校验、权威回读与确认门禁；A4 以“穿越目的地与执行假设”承接 RunSpec。完整脚本见 [对话式策略私教引导脚本](v3-s4-dialogue-guide.md)。

```text

│ A0 状态带：drafting / invalid / valid / confirmed …    registryVersion / 模型来源 │
├──────────────────────┬──────────────────────────────┬─────────────────────────────┤
│ A1 阿一面试对话流     │ A2 规则随对话成形              │ A3 校验与权威回读            │
│                      │                              │                             │
│ AI 第一句／水平判断   │ 策略名 / schemaVersion       │ ⚠ ValidationIssue[]          │

│                      │ 入场 BoolExpr 逐块形成        │  expected / actual / hint    │
│ AI 追问买入条件       │ 出场规则（继续追问形成）      │                             │
│ AI 追问卖出与仓位     │ 仓位：long-only / 禁止加仓    │ ✓ canonical digest           │
│                      │                              │ 权威 Readback 摘要            │
│ [下一句／重播]        │ [AST 只读视图]               │ clause ↔ astPath             │

│ A4 穿越目的地与执行假设（模型不可写）                                            │
│ 资产／executionProfile｜DataSnapshot digest／来源／质量｜起止区间｜warmup extra    │
│ 初始资金 CNY｜费用／滑点／结算／report profile｜可见性｜engine/registry/canon…     │
│ 复权／单位／许可／公司行动／假设与警告           [运行回测]（仅 confirmed 且可执行）│
└────────────────────────────────────────────────────────────────────────────────────┘
```

### 2.3 区域、按钮与信息层级

| 层级 | 内容 | 交互与反馈 |
|---|---|---|
| P0：当前必须判断 | 当前对话与缺失语义、逐块形成的入出场规则、阻断错误、权威回读、revision/digest、确认与运行按钮 | AI 只引导表达不荐股；`invalid` 时定位 A2 对应 AST 节点；对话称“规则齐了”不解除校验与确认门禁 |
| P1：运行前必须核对 | 资产／快照／区间、初始资金、warmup、费用／滑点／结算／可见性、引擎与注册表版本 | RunSpec 由用户／application 控制；修改策略语义使当前确认失效，修改 RunSpec 则形成不同 runDigest，不暗改策略 digest |
| P2：审计与辅助 | 能力清单、canonical AST、模型 provenance、辅助解释、修改历史、完整数据质量与许可 | 默认折叠但可直达；辅助解释不得覆盖权威回读；完整 digest 可复制，界面短哈希不能替代完整值 |

按钮口径：

- **生成／重新生成**：只请求真实模型草稿；生成中防重复提交，失败进入 `model-error`。
- **重新校验**：对当前草稿走同一完整校验链；不绕过 warning 或错误。
- **确认策略**：携带当前 `expectedDigest`；确认期间锁定语义编辑，digest 变化则失败。
- **运行回测**：仅在 confirmed revision、合法 RunSpec 和可执行快照齐全时可用；重复同 digest 请求返回同一完整结果。
- **基于此版本调整**（从 C 返回时）：保留基线标识，生成独立 revision，不复用旧确认。

### 3.1.1 围观经理人工作（**2026-10-29 第三轮概念返修**）

B 的首要叙事是“围观阿一在 2024 年 1 月的工作”：入场、关键回撤、退出三个章节。固定提示 **“他只知道那天及之前的事”**，把点时数据、warmup 和因果事件顺序翻译成用户语言；不得让角色显得能预知未来。

故事只能由当前 RunEvent/Report 的真实日期、成交、费用、权益和回撤推导，点击章节只移动共享 cursor。当日收盘信号与次日执行不得讲成预知全天走势。

B4 改为“阿一当时的依据”抽屉，默认收起；点击泳道事件或“问他当时依据”打开。抽屉展示真实 reasonCodes/inputRefs/payload/hash，不是实时模型解释。播放、暂停、加速和拖动只改变只读投影，不给角色新增信息，不改变账本或 digest。

### 3.2 图表与证据规则

- B1、B2、B3 共用 tradingDate／seq cursor；任一图表选中事件都同步 B4，不各自维护时间。
- B1 区分信号使用的点时序列与成交／账本使用的原始价；不可用指标段留空并解释，不补 0。
- B2 同时保留意图、实际成交与拒单。数量调整须能从 intent 追到 fill 和 `ORDER_SIZE_ADJUSTED` 等原因，不只画成交点。
- B3 的买入持有仅在契约允许时显示；指数没有可交易资金曲线，全部拒单或无信号也不等于基准不存在。
- B4 至少展示 `seq/tradingDate/phase/type/reasonCodes/inputRefs`，并可展开 event hash 链。播放速度只改投影节奏。
- `RunFailed` 可在失败诊断视图展示已保留事件与精确错误，但 B0 必须标 FAILED，不出现“完成报告”按钮假态。

### 3.3 信息层级与跳转

| 层级 | 内容 | 跳转 |
|---|---|---|
| P0 | 策略故事章节、当前日期、价格／指标、信号与订单、权益／回撤、播放控制 | 点击故事或“跳结果”只移动 cursor；“查看报告”进入同一 runDigest 的 C |
| P1 | 拒单原因、信号原因、stale／停牌／缺数、买入持有对照、现金／持仓 | 点击事件定位 B2 并展开 B4；点击 revision 可回 A 查看该已确认版本，只读 |
| P2 | 抽屉中的 inputRefs、完整 payload、intent/fill 链、事件 hash、RunSpec 与快照证据 | 证据默认收起但可直达；“基于此版本调整”回 A，不在 B 内直接改策略或账本 |


### 4.1.1 经理人复盘与穿越成绩单（**2026-10-29 第三轮概念返修**）

C 在四指标前呈现“阿一的穿越成绩单”与人话复盘，并提供“问阿一”的预写规则问答：为什么买入、关键回撤发生了什么、为什么卖出。回答只能引用当前 Run 的事件、日期、数值和原因，不生成心理活动、市场因果或实时模型回复。

人话层与问答不替代四指标、详细层、compare 对齐和证据链。指标不可用仍显示 `null + reason`，失败 Run 不生成成功复盘；六个 synthetic session 不外推为真实投资能力。

### 4.2 指标、比较与空态层级

| 层级 | 内容 | 产品规则 |
|---|---|---|
| P0 | 人话回读、首屏四指标、策略／买入持有曲线、当前 revision 与 Run 状态 | 人话层只回读真实结果；不可用指标显示“—”并在原位给 reason；交易次数为 0 时须配合无交易／全部拒单解释 |
| P1 | v1/v2 指标差值、订单差异、对齐条件、费用与拒单 | compare 先展示对齐检查，再展示差值；任一条件不符则保留两个独立报告，不计算策略版本优劣 |
| P2 | 胜率及成本配对、四桶现金、持仓、假设、许可、完整 hash／digest | 胜率分母为零时为 `null + reason`；小样本不包装成统计结论；完整精度可在详情查看 |

“基于此版本调整”必须携带用户选中的基线 revision，而不是暗中使用最新版本。v2 运行后仍保留 v1/v2 各自 strategyDigest、runDigest、Report 和独立跳转。

## 6. 主状态矩阵（三场景联动）

| 状态 | A 策略生成舱 | B 历史推演剧场 | C 结果与版本对比 | 允许动作与硬阻断 |
|---|---|---|---|---|
| `empty` | 意图、AST、回读为空；能力清单可浏览；生成按钮待有效输入 | 未选 Run 时显示“先确认并运行策略”，无坐标轴假数据 | 无报告；说明报告来源，不展示 0 指标 | 输入意图进入 `drafting`；确认、运行、compare 禁用 |
| `drafting` | 有意图或语义编辑；显示“未校验／确认已失效（如曾有）”与新 revision 上下文 | 可独立查看旧 Run，并标注其旧 revision；不投影当前草稿 | 旧报告仍可看；不得把旧报告称为当前草稿结果 | 可生成／校验；当前新语义未确认不得运行 |
| `invalid` | 显示结构化 error 与可见 warning；定位 AST path；坏 JSON 显示解析失败位置 | 旧 Run 可看；当前无新 Run | 旧报告可看；当前无新成功报告 | 可修复并重新校验；error 存在时确认和运行阻断 |
| `valid` | 展示 canonical AST、digest、权威回读及 warning；“确认策略”可用 | 旧 Run 可看；当前尚无新 Run | 旧报告可看；compare 不包含未运行 revision | 确认前运行禁用；确认进入 `confirming` |
| `confirming` | 锁定语义编辑，显示 expectedDigest 核对中 | 保持旧选中 Run，只读 | 保持旧报告，只读 | 成功进入 `confirmed`；digest 不符则回到 `valid` 并要求重新读取，禁止确认替换内容 |
| `confirmed` | revision/digest 已锁定；完整 RunSpec 与数据假设可核对 | 旧 Run 可看；当前 revision 待运行 | 旧报告可看；当前 revision 尚无报告 | 数据与 RunSpec 合法时可运行；修改可执行语义立即形成未确认新 revision |
| `running` | 显示 runDigest 与冻结假设，防重复运行；策略语义不被运行过程改写 | 当前 Run 只显示“完整结果计算中”，不伪造逐日事件；旧 Run 仍可另选 | 当前 Run 不显示部分成功报告或暂定指标 | 运行期无模型／网络；成功进入 `completed`，失败进入 `failed`，数据原因失败同时标为 `data-error` |
| `completed` | 显示该 confirmed revision 可“查看回放／报告／调整” | 全部播放、拖动、跳结果和事件证据可用 | 四指标、详细层与证据链可用；可再选兼容 Run compare | B/C 共用同一 runDigest；cursor 与场景切换不改 hash；v2 仍须重新确认 |
| `model-error` | 显示真实模型超时／不可用／修复耗尽及脱敏 provenance；保留意图与最后草稿 | 旧 Run 可独立查看；无当前新 Run | 旧报告可独立查看；无当前新成功报告 | 可重试真实模型或修改意图；不得自动切 fake、确认新草稿或运行新 revision |
| `data-error` | 显示快照／质量／warmup／资产／可见性或 RunSpec 错误；required/actual 等诊断可读 | 当前数据失败 Run 仅可显示 FAILED 诊断；不能播放成成功结果；旧 Run 不受影响 | 当前数据失败 Run 不输出成功 Report；旧报告不受影响 | 修复数据／配置后重新运行；不用上一价、0、随机数据或固定曲线掩盖未知 |
| `failed` | 显示 RunFailed 的 code/path/details 与冻结假设；confirmed revision 和历史结果仍保留 | 仅提供失败事件与诊断，不开放成功回放 | 不显示成功四指标或完整 Report；旧成功报告仍可独立打开 | 可查看诊断或返回 A；排除原因后重新发起，不把非数据故障误标为数据错误 |

## 7. 错误、空态与不适用矩阵

| 情况 | 识别与系统反馈 | A / B / C 的呈现 | 明确禁止 |
|---|---|---|---|
| 无交易、无信号 | Run 可完成；orders/fills/rejections 为空，tradeCount=0 是真实计数 | A 仍可查看策略；B 显示真实价格／指标／权益和“未产生入场信号”；C 显示真实现金权益、可用的买入持有及无交易解释 | 不把 tradeCount=0 改成 null；不画虚假买卖标记；不据此断言买入持有不存在 |
| 有信号但从未产生成交 | 信号与可能存在的意图／取消原因入账 | B 显示信号及后续事件；C 详细层保留订单轨迹，首屏交易次数按实际 fills 计算 | 不用信号数冒充交易次数 |
| 全部拒单 | intents/rejections 存在、fills 为空；每个拒单有 reasonCodes 与证据 | B 突出拒单标记和原因；C 的拒单 tab 默认有提示，交易次数为真实 0，其他指标按真实账本计算 | 不把全部拒单简化成“无信号”；不隐藏拒单后展示平稳成功曲线 |
| 零持仓 | 期末 position.total=`0`，可能来自已卖出或从未买入 | B 仍显示现金／权益／回撤；C 保留成交、费用与已平仓配对；明确“当前零持仓” | 不把零持仓等同无交易；不清空历史曲线或胜率 |
| 数据不足／warmup 不足 | `INSUFFICIENT_WARMUP`，展示 AST 最小值、extra、required/actual；任一分支不足整体阻断 | A 的运行区显示诊断；当前 B 无成功时间轴；当前 C 无成功 Report | 不缩短 warmup、不逐分支降级、不用 unavailable=false 继续运行 |
| 空历史／所选区间无有效观测 | 数据错误说明快照、区间与观测数 | A 允许改选快照／区间；B/C 显示无数据原因而非零线 | 不用 0 价格、前向填充或另一快照静默替代 |
| 指标不足／不适用 | 字段返回 `null + reason`；例如无已平仓批次时胜率不可用，买入持有不可形成时超额不可用 | C 对应卡片显示“—”与原位 reason，其他可用指标保留；B 对应序列留空并解释 | 不用 0 代替 null；不编造胜率、基准或曲线 |
| 买入持有不适用 | `buyAndHold.finalEquity/cumulativeReturn=null` 且有 reason | C 超额为“— + reason”；B 只画可用策略序列并说明缺基准 | 不把基准缺失当超额 0；指数不生成虚假资金曲线 |
| 已确认停牌／stale 估值 | 停牌不更新指标、不成交；估值可沿用最后价但必须标 stale | B 在日期、价格和事件上同时标记；C warnings／假设可查 | 不把停牌当普通新观测，不隐藏 stale 标记 |
| 原因未知的数据缺失 | 运行失败并保留精确诊断 | 当前 B/C 不显示成功结果；旧 Run 可独立查看 | 不用上一价或 0 补齐，不把缺数与停牌合并 |
| 模型输出无效 | 坏 JSON、额外字段、未知指标、未来引用等按解析／schema／语义错误呈现；记录有限修复次数 | A 定位错误并保留输入；B/C 只保留旧 Run；修复耗尽进入 `model-error` | 不将模型解释当回读，不切 fake，不跳过校验 |
| 资产不支持 | 显示资产类型、executionProfile 与拒绝原因；指数仅分析 | A 阻断运行；B/C 对指数只呈现合法分析，不出现订单／费用／资金曲线 | 不套用股票成交模型，不让模型选择替代资产 |
| 基金可见性未决 | 显示 visibility profile、法规／假设和缺失证据 | A 阻断未满足的执行；B/C 不用 navDate 冒充 publishedAt | 不改选已终审规则，不静默降级为股票时间线 |
| 其他 `RunFailed` | 保留失败事件、错误 code/path/details 与 runDigest | B 仅失败诊断；C 无成功四指标；旧成功 Report 仍可打开 | 不输出标为成功的完整报告，不覆盖旧结果 |
| 只有一个完成 Run | compare 区说明需要另一个 confirmed 且完成的 revision | C 提供“基于此版本调整并运行 v2”；单 Run 报告完整可用 | 不与自己伪造“版本提升” |
| compare 条件不齐 | 列出资产／快照／区间／资金／执行／engine/registry/canonicalization 的不符项 | 两个报告分别可看，compare 差值区禁用并给原因 | 不跨引擎、跨数据计算策略版本差值，不丢弃任一 revision digest |

## 8. 场景跳转与上下文保持

| 触发 | 目标 | 必须保持／改变 |
|---|---|---|
| A 运行成功 | B `completed` | 保持 confirmed revision、RunSpec、runDigest；cursor 初始位置可设首事件，不重跑 |
| B “查看报告” | C 单 Run 报告 | 保持同一 runDigest；返回 B 时恢复原 cursor |
| B/C “基于此版本调整” | A `drafting` | 带回明确基线 strategyId/revision/digest 与旧 AST；预填 RunSpec 仅供核对；新语义未确认 |
| A 选择历史完成 Run | B 或 C | 当前草稿不被覆盖；顶部同时区分“编辑中的 revision”和“查看中的 Run” |
| C “选择比较版本” | C compare | 先执行对齐检查；两个 runDigest 均保留，可分别回 B |
| 新模型／数据操作失败 | 停留当前场景并显示错误 | 旧 Run、旧报告、原 cursor 与证据链保持只读，不错误跳转到假成功页 |

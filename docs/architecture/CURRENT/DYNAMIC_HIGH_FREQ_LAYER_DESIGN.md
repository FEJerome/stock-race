# 动态高频层采集系统设计

## 概述

实现基于系统健康状态的动态高频层采集策略，以及加权热股票列表排序机制。

## 核心需求

### 1. 动态高频层股票数量

根据混合采集系统健康状态，动态调整高频层股票数量：

| 健康状态 | 高频层股票数 | 采集间隔 | 说明 |
|---------|-------------|---------|------|
| 优秀 (4源健康) | 200只 | 10秒 | 系统资源充足，可支持更多股票高频采集 |
| 良好 (3源健康) | 150只 | 10秒 | 轻微降级，减少高频股票数量 |
| 一般 (2源健康) | 100只 | 10秒 | 标准配置，保证核心股票高频更新 |
| 较差 (1源健康) | 50只 | 15秒 | 严重降级，仅保证极少数核心股票 |
| 临界 (0源健康) | 0只 | - | 暂停高频层，仅维持全量层 |

### 2. 加权热股票列表

后端提供的热股票列表包含权重信息：

```json
{
  "hot_stocks": [
    {"symbol": "000001.SZ", "weight": 95.5, "factors": {"view_count": 1000, "user_count": 500}},
    {"symbol": "600519.SH", "weight": 88.2, "factors": {"view_count": 800, "user_count": 400}},
    {"symbol": "000858.SZ", "weight": 72.1, "factors": {"view_count": 600, "user_count": 300}}
  ],
  "updated_at": "2026-02-13T10:00:00Z"
}
```

权重计算因素：
- 当前查看该股票的用户数 (40%)
- 近期查看次数/点击量 (30%)
- 股票的交易活跃度 (20%)
- 用户收藏/关注数量 (10%)

## 工作流程

### 1. 热股票列表更新流程

```
Backend 每30秒计算一次热股票权重
    │
    ▼
Market Data Service 每30秒拉取热股票列表
    │
    ▼
按权重排序，缓存到本地
    │
    ▼
根据系统健康状态确定高频层股票数N
    │
    ▼
选取权重最高的前N只股票
    │
    ▼
启动高频采集任务 (10秒间隔)
```

### 2. 动态调整流程

```
Health Monitor 每秒检查系统状态
    │
    ▼
状态变化时触发调整
    │
    ▼
重新计算高频层股票数N
    │
    ▼
如果N增加: 从热股票列表补充低权重股票
如果N减少: 从当前列表移除低权重股票
如果N不变: 检查权重排序是否有变化，必要时调整
    │
    ▼
平滑过渡：已采集股票继续采集，新增股票下一周期加入
```

## 容灾策略

### 1. 热股票列表获取失败
- 使用本地缓存的上一次列表
- 缓存有效期5分钟
- 超过5分钟使用默认热门股票列表（沪深300成分股）

### 2. 权重计算异常
- 权重异常值（>100或<0）自动修正为边界值
- 缺失权重的股票赋予默认权重50

### 3. 高频层股票不足
- 如果热股票列表数量 < 需要的N
- 使用全量股票列表补充（按市值排序）

## 性能指标

| 指标 | 目标值 | 说明 |
|-----|-------|------|
| 热股票列表更新延迟 | < 30秒 | 从Backend计算到Market Data Service获取 |
| 高频层调整延迟 | < 60秒 | 健康状态变化到高频层股票调整完成 |
| 权重计算精度 | 小数点后1位 | 权重值保留1位小数 |
| 内存占用 | < 10MB | 热股票列表缓存占用 |

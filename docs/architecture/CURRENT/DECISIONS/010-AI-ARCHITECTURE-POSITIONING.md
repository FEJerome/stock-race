# 010: AI 架构定位与演进路线图决策

> **状态**: 已采纳
> **决策日期**: 2026-02-13
> **决策者**: 项目创始人 + 首席架构师
> **影响范围**: Trading AI Service、整体架构演进

---

## 一、背景与问题

### 1.1 最初的愿景
项目创始人最初的设想是构建一个"DeepMind 式的 AI Agent"：
- 直接连接大模型（如 DeepSeek/Claude）
- 实时接收行情数据、用户账户信息
- AI 自主决策、自主交易
- 仿佛在与 DeepMind 对话

### 1.2 认知升级
通过技术调研，认识到：
- 直接调用 LLM API 返回的是**结构化数据**，不是 Agent
- 真正的 Agent 需要规划、记忆、工具使用、反思、自主执行等能力
- 对 AI/Agent/MCP/Skill 等概念的理解需要澄清

### 1.3 核心问题
- 当前架构究竟是什么？
- 是否需要做成真正的 Agent？
- 项目距离"Agent 化"还有多远？
- 技术能力边界在哪里？

---

## 二、架构师分析

### 2.1 当前架构的真实定位

**结论：不是 Agent，而是 "LLM as a Service"**

```
┌─────────────────────────────────────────────────────────┐
│               当前架构：决策建议生成器                    │
├─────────────────────────────────────────────────────────┤
│  数据聚合 → 提示工程 → 调用 LLM API → 解析响应 → 执行交易  │
│  (Prompt Wrapper + API Proxy)                           │
└─────────────────────────────────────────────────────────┘
```

**关键特征**：
- 单次调用，无状态
- 无记忆、无规划、无反思
- LLM 只生成建议，不自主行动
- 人在回路（Human-in-the-loop）

### 2.2 真正 Agent 的必备组件

```
┌──────────────────────────────────────────────────────────┐
│                   真正的 Agent 架构                       │
├──────────────────────────────────────────────────────────┤
│  1. 规划 (Planning)                                      │
│     - 能分解复杂任务：分析市场 → 选股 → 决定仓位 → 执行    │
│                                                          │
│  2. 记忆 (Memory)                                        │
│     - 短期记忆：当前对话上下文                            │
│     - 长期记忆：历史交易表现、用户偏好、市场规律            │
│                                                          │
│  3. 工具使用 (Tool Use)                                   │
│     - 能主动调用：查行情、查新闻、计算指标、下单           │
│     - 不是被动接收，而是"我需要最新价格，去查一下"         │
│                                                          │
│  4. 反思 (Reflection)                                    │
│     - 交易后复盘：为什么亏了？策略哪里错了？               │
│     - 自我修正：调整下次决策逻辑                          │
│                                                          │
│  5. 自主执行 (Autonomy)                                  │
│     - 不需要用户每一步确认                                │
│     - 设定目标后自主运行：监控 → 触发 → 决策 → 执行        │
└──────────────────────────────────────────────────────────┘
```

### 2.3 金融领域是否需要 Agent？

**架构师判断：不需要，当前架构更合适**

| 维度 | 当前架构 (LLM as a Service) | 真正 Agent |
|------|---------------------------|------------|
| **可解释性** | ✅ 提示词+响应=完整决策链，可审计 | ❌ 黑盒决策，难以解释 |
| **合规性** | ✅ "建议+确认"模式合规 | ⚠️ 自主交易可能触及监管红线 |
| **可靠性** | ✅ 简单可控，规则引擎兜底 | ❌ 复杂度高，难以预测行为 |
| **实现难度** | ✅ 已掌握 90% 所需知识 | ❌ 需学习 Agent 框架、向量检索等 |
| **技术风险** | ✅ 低 | ❌ 高 |

**核心洞察**：不要因技术酷炫而过度工程化。

## 三、决策结果

### 3.1 项目定位

**正式定位**：AI 增强的数据驱动交易系统

不是 Agent，而是：
- 数据整合器（多源行情聚合）
- 决策建议生成器（LLM 提供建议）
- 规则执行器（人工/规则确认后执行）
- 学习优化器（基于历史优化提示词）

### 3.2 演进路线图

#### 第一阶段：当前 → 小程序上线（3-6 个月）

**目标**：成熟、可交付、可上线

**任务清单**：
- [ ] 完成所有服务模块开发
- [ ] 前端极致美化
- [ ] 引入配置和监控中心
- [ ] 全面的压力测试
- [ ] 合规性审查
- [ ] 微信小程序备案
- [ ] 正式上线运营

**技术重点**：
- 多数据源接入 ✅
- 历史数据存储 ✅（T-020/021 已完成）
- 规则引擎完善
- 回测系统
- 监控告警

#### 第二阶段：轻量级 Agent 化（6-12 个月）

**目标**：引入轻量级 Agent 特性，但保持人在回路

**技术方案**：ReAct 模式（Reasoning + Acting）

```python
# 轻量级 Agent 示例
while task_not_done:
    # 1. LLM 思考需要什么信息
    thought = llm.think("分析茅台股票，我需要最新价格和新闻")

    # 2. LLM 决定行动
    action = llm.act("调用 get_stock_price('600519')")

    # 3. 执行工具
    observation = execute_action(action)

    # 4. 循环直到生成建议
    # 最终仍需人工确认
```

**需补充的技术栈**：
- LangChain / LlamaIndex（Agent 框架）
- 向量数据库（长期记忆）
- 工具注册机制
- 简单反思机制（交易日志分析）

**关键约束**：
- 保持"建议 + 确认"模式
- LLM 可以"反问"，但不可自主交易
- 所有行动需可追溯、可审计

#### 第三阶段：全自主 Agent（远期，12 个月以上）

**前提条件**：
- 第二阶段表现优异
- 解决合规、风控、责任归属问题
- 监管环境允许

**可能性**：低，保持观望

## 四、风险与缓解

### 4.1 技术风险

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| LLM 幻觉导致错误建议 | 中 | 高 | 规则引擎过滤 + 人工确认 |
| 数据源故障 | 中 | 高 | 多数据源备份 + 降级策略 |
| 系统性能瓶颈 | 低 | 中 | 压力测试 + 水平扩展 |

### 4.2 合规风险

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| 自动交易触及监管 | 中 | 高 | 明确"虚拟交易 + 建议"定位 |
| 金融牌照问题 | 低 | 高 | 咨询法律意见，确保不涉及真实资金 |

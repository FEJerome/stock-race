# 架构决策记录：Frontend 定位调整与联调阶段策略

**决策编号**: ARCH-2026-02-12-001
**决策日期**: 2026-02-12
**决策状态**: ✅ 已批准
**决策人**: 首席架构师、产品经理

---

## 1. 背景

### 1.1 项目现状

stock-race 项目采用六服务架构：
- **Backend**: API网关、业务编排
- **Market Data Service**: 行情数据采集
- **Trading AI Service**: AI交易决策
- **News Service**: 新闻情报分析
- **Miniprogram**: 微信小程序（用户入口）
- **Frontend**: React Web前端（原计划用户界面）

### 1.2 问题识别

在项目联调准备阶段，发现以下问题：

1. **用户入口单一**: Miniprogram 是主要C端用户触点，Web Frontend 当前仅用于开发调试
2. **资源分散风险**: 同时保障 Miniprogram 和 Frontend 联调会分散开发资源
3. **Frontend 价值未明确定位**: 作为用户Web界面与 Miniprogram 功能重复，缺乏差异化价值
4. **监控运维需求**: 生产环境缺少统一的监控和配置管理入口

---

## 2. 决策内容

### 2.1 核心决策

**决策1**: Frontend 在此次联调阶段暂停用户界面功能开发
**决策2**: Frontend 定位从"用户Web界面"调整为"监控中心 + 配置中心"
**决策3**: Miniprogram 作为唯一C端用户入口，优先保障联调
**决策4**: Frontend 监控中心开发延后至 Miniprogram 上线后启动

### 2.2 联调阶段参与策略

| 服务 | 联调阶段角色 | 优先级 | 说明 |
|------|-------------|--------|------|
| Miniprogram | 主要用户入口 | **P0** | 唯一C端用户界面，必须优先完成 |
| Backend | API网关 | **P0** | 承载 Miniprogram 全部流量 |
| Market Data | 行情数据源 | **P0** | Miniprogram WebSocket 直连 |
| Trading AI | AI决策服务 | **P1** | Miniprogram 通过 Backend 调用 |
| News Service | 新闻情报服务 | **P1** | 事件总线解耦，可并行 |
| **Frontend** | **暂不参与** | **P2** | **延后至 Miniprogram 稳定后** |

---

## 3. 决策理由

### 3.1 用户入口分析

| 入口 | 目标用户 | 使用场景 | 优先级 |
|------|---------|---------|--------|
| Miniprogram | C端投资者 | 日常交易、查看行情、管理AI账户 | **核心入口** |
| Web Frontend | 开发者调试 | API测试、数据查看 | 开发工具 |
| Web Frontend | 运维/管理员 | 监控服务状态、调整配置 | **未来定位** |

**结论**: Miniprogram 是项目成功的关键，Frontend 当前阶段价值有限。

### 3.2 资源集中原则

联调阶段资源有限，必须集中保障：
1. Miniprogram 与 Backend 的API对接（T-008/T-009）
2. Miniprogram 游客模式完整流程（C5-007~010）
3. Miniprogram WebSocket实时行情（O6-005~010）

Frontend 用户界面开发与 Miniprogram 并行将分散测试资源。

### 3.3 差异化价值定位

单纯的 Web 用户界面与 Miniprogram 功能高度重复，缺乏存在必要性。

转型为**监控中心 + 配置中心**后：
- 面向不同用户（运维/管理员 vs C端投资者）
- 提供差异化价值（生产监控 vs 交易功能）
- 填补架构空白（当前缺少统一监控配置入口）

## 4. Frontend 未来定位：监控中心 + 配置中心

### 4.1 监控中心

**目标用户**: 运维人员、开发人员、管理员
**核心功能**:

| 监控维度 | 功能描述 | 数据来源 |
|----------|---------|----------|
| 服务健康监控 | Backend/Market Data/Trading AI/News 健康状态可视化 | Health Check SDK |
| 事件总线监控 | Redis Streams 消息堆积、消费延迟、发布/消费速率 | Redis XINFO |
| AI决策性能监控 | Token消耗、响应时间、成功率、模型分布、成本分析 | Trading AI 事件 |
| 行情数据质量监控 | 数据源健康、数据延迟、异常波动、采集成功率 | Market Data 日志 |

### 4.2 配置中心

**目标用户**: 管理员、运维人员
**核心功能**:

| 配置类别 | 配置内容 | 生效方式 |
|----------|---------|----------|
| 动态配置管理 | Feature Flag、系统参数、告警阈值 | 即时生效（事件推送） |
| AI模型配置 | Prompt模板、模型参数、成本预算、降级策略 | 即时生效 |
| 业务规则配置 | 交易规则、风控阈值、通知规则、游客限制 | 即时生效 |

# Full 形态架构 (v2.0)

Full 形态是 **AI股票竞赛平台** 的完整商业运营版本，采用微服务架构。

## 产品定位

**一句话描述**: 生产级多用户 AI 股票竞赛平台，完整商业功能。

**核心价值**:
- 🏢 **企业级服务**: 高可用、高性能、可扩展
- 👥 **多用户支持**: 完整用户系统、社交功能
- 💰 **商业运营**: 订阅、等级、周薪完整闭环
- 🔧 **微服务架构**: 模块独立演进，团队并行开发

### 服务职责

| 服务 | 技术栈 | 职责 |
|------|--------|------|
| **Backend** | Go + Gin + GORM | 用户管理、账户管理、API 聚合 |
| **Trading AI Service** | Python + FastAPI | AI 交易决策、模型适配器 |
| **Market Data Service** | Python + FastAPI | 行情数据采集、清洗、推送 |
| **News Service** | Python + FastAPI | 财经新闻、舆论数据采集 |
| **Notification Service** | Go + Gin | 消息推送、通知管理 |
| **Config Center** | Go + Gin | 动态配置管理 |

## 技术栈变更

### 从 v0.9 到 v2.0

| 维度 | v0.9 | v2.0 Full |
|------|------|-----------|
| **Backend** | Node.js + Express | Go + Gin + GORM + Wire |
| **AI Service** | Python (旧框架) | Python + FastAPI |
| **Database ORM** | Prisma | GORM (Go) / SQLAlchemy (Py) |
| **依赖注入** | 手动 | Wire |
| **配置管理** | 手动 | Viper + Config Center |
| **通信** | HTTP + Redis | HTTP/gRPC + Kafka |

## 演进路径

```
Local (单体)
    │
    ├── 模块边界清晰
    ├── 领域模型确立
    └── 技术方案验证
    │
    ▼
Full (微服务)
    │
    ├── 按模块拆分服务
    ├── 通信方式升级
    └── 增加运维能力
```

**关键原则**: Local → Full 是"拆分"而非"重写"，业务逻辑保持不变。

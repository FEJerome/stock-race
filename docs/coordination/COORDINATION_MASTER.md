## 🔄 协调工作流程

### 1. 任务分配流程
```
协调智能体创建任务 → 更新本文档 → 通知对应模块智能体 → 智能体领取任务 → 更新状态为in_progress
```

### 2. 进度汇报流程
```
模块智能体每日汇报 → 更新模块进度表 → 协调智能体汇总 → 更新总体进度 → 报告给项目负责人
```

### 3. 代码合并流程
```
模块智能体完成功能 → 在worktree中提交 → 创建PR到develop分支 → 协调智能体审核 → 合并到develop → 删除feature分支
```

### 4. 冲突解决流程
```
发现冲突 → 通知协调智能体 → 协调会议 → 确定解决方案 → 实施解决 → 更新依赖文档
```

## 📞 沟通机制

### 每日汇报要求
- **时间**：每日工作结束前
- **内容**：今日完成工作、遇到的问题、明日计划
- **格式**：更新在本文档对应模块进度表中
- **责任人**：各模块智能体

### 阻塞问题上报
- **立即上报**：遇到技术阻塞、依赖问题、重大缺陷
- **上报方式**：更新进度表状态为`blocked`，在备注中说明问题
- **解决时限**：协调智能体在4小时内响应

### 里程碑汇报
- **阶段完成**：每个任务完成后
- **内容**：任务总结、成果展示、下一步建议
- **格式**：更新本文档，并创建专门成果文档

## 🛠️ 技术规范

### Git工作流规范
1. **分支命名**：`feature/模块-功能名`，如`feature/frontend-typescript-migration`
2. **提交信息**：`feat(模块): 简要描述`，如`feat(frontend): 迁移核心组件到TypeScript`
3. **代码审查**：协调智能体负责所有PR审查
4. **合并权限**：只有协调智能体可合并到develop分支

### 文档更新规范
1. **进度更新**：每日更新本文档进度表
2. **问题记录**：遇到问题立即记录
3. **成果文档**：任务完成后创建成果总结文档
4. **知识共享**：重要发现和技术方案分享到docs/

### 质量保证
1. **代码规范**：遵循项目现有规范
2. **测试要求**：新增功能必须有测试
3. **集成测试**：合并前运行基本集成测试
4. **性能基线**：关键功能性能不能下降

## ⚠️ 风险控制

### 技术风险
1. **TypeScript迁移风险**：可能引入新bug
   - **缓解措施**：逐步迁移，充分测试，保留回滚方案
2. **数据API限制风险**：免费API不稳定
   - **缓解措施**：多数据源备份，降级策略，缓存优化
3. **集成风险**：模块间接口变更冲突
   - **缓解措施**：提前协调，接口版本管理，兼容性保证

### 进度风险
1. **任务延期风险**：复杂度预估不足
   - **缓解措施**：每日进度监控，及时调整计划
2. **依赖阻塞风险**：模块间依赖导致等待
   - **缓解措施**：明确依赖关系，优先处理阻塞任务

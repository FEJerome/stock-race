## ⚙️ 执行策略（并行限制：最多4个）
**用户要求**：智能体并行执行数量不超过四个，其他智能体串行执行，等待运行的智能体结束。

**分组策略**：
- **第一组（并行，立即启动）**：后端工具智能体、后端服务智能体、协调智能体、前端逻辑智能体
- **第二组（串行等待）**：后端适配器智能体（等待编码问题解决）、前端组件智能体（等待API集成准备）

**依赖关系**：
```
编码问题解决 ← 后端适配器智能体启动 ← 完整数据流建立
网络稳定性验证 ← 前端API通信正常 ← 前端组件智能体启动
```

## 📊 阶段性汇报机制
**每日汇报**（各智能体负责）：
- **时间**：每日工作结束前
- **内容**：今日进展、遇到的问题、明日计划
- **格式**：更新在各自模块的TODO文档中

**阶段汇报**（协调智能体负责）：
- **时间**：关键里程碑完成时
- **内容**：阶段成果总结、项目状态更新、下一步计划
- **格式**：更新CLAUDE.md，直接向用户汇报

**周度汇总**（协调智能体负责）：
- **时间**：每周五工作结束前
- **内容**：本周完成情况、下周计划、风险分析
- **格式**：更新`docs/coordination/PROGRESS.md`

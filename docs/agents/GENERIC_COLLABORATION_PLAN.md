## ⚙️ 执行策略（并行限制：最多4个）
**核心原则**：智能体并行执行数量不超过四个，其他智能体串行执行，等待运行的智能体结束。

**分组策略示例**：
- **第一组（并行，立即启动）**：架构设计智能体、核心逻辑智能体、协调智能体、基础设施智能体
- **第二组（串行等待）**：接口服务智能体（等待架构设计完成）、用户界面智能体（等待核心逻辑准备）

**通用依赖关系**：
```
架构设计完成 ← 接口服务智能体启动 ← 系统集成测试
核心逻辑完成 ← 用户界面智能体启动 ← 端到端测试
基础设施就绪 ← 所有智能体开发 ← 持续集成
```

## 📅 AI股票竞赛平台MVP执行时间线
**目标**：快速交付最小可行产品，展示核心功能

**阶段一：环境搭建与基础架构（第1-2天）**
- D1：项目脚手架创建、技术栈配置
- D2：数据库设计、API接口定义、基础架构搭建

**阶段二：核心功能并行开发（第3-7天）**
- **后端核心智能体**：用户系统（单用户密码）、交易逻辑、持仓管理
- **AI集成智能体**：大模型API集成、交易决策逻辑、提示词模板
- **数据工程智能体**：股票数据采集、实时数据推送、数据存储
- **前端智能体**：交易界面、持仓展示、收益曲线、操作监控

**阶段三：集成测试与优化（第8-10天）**
- 系统集成：前后端对接、AI服务集成、数据流验证
- 功能测试：核心交易流程、AI决策、实时数据展示
- 性能优化：响应时间优化、数据延迟控制、内存使用优化

**阶段四：部署与演示准备（第11-14天）**
- 容器化部署：Docker配置、环境变量管理
- 监控配置：基本监控告警、日志收集
- 演示准备：演示数据准备、用户指南、故障排除

## 📊 阶段性汇报机制
**每日汇报**（各智能体负责）：
- **时间**：每日工作结束前
- **内容**：今日进展、遇到的问题、明日计划
- **格式**：更新在各自工作领域的文档中

**阶段汇报**（协调智能体负责）：
- **时间**：关键里程碑完成时
- **内容**：阶段成果总结、项目状态更新、下一步计划
- **格式**：更新项目主文档，向项目负责人汇报

**周度汇总**（协调智能体负责）：
- **时间**：每周工作结束前
- **内容**：本周完成情况、下周计划、风险分析
- **格式**：更新进度跟踪文档

## 📋 文档更新规范
- **任务状态**：`pending` → `in_progress` → `completed` → `blocked`
- **每日更新**：各智能体更新负责领域的工作文档
- **进度跟踪**：协调智能体更新进度文档和项目主文档
- **依赖管理**：跨模块变更更新依赖关系文档

## 🔄 主智能体任务分发流程
1. **任务接收**：主智能体接收复杂任务请求
2. **任务分析**：分析任务类型、复杂度、技术需求
3. **智能体匹配**：根据任务特性匹配最合适的智能体
4. **并行检查**：检查当前并行智能体数量（≤4）
5. **任务委派**：将任务分配给选定的智能体
6. **进度监控**：监控任务执行状态，但不参与具体开发

## ⚠️ 注意事项
1. **并行限制**：严格遵守最多4个智能体并行的限制
2. **依赖管理**：清晰记录和管理模块间依赖关系
3. **沟通协调**：定期同步进度，及时解决阻塞问题
4. **质量保证**：所有代码必须通过审查和测试才能合并
5. **文档完整**：保持文档与代码同步更新

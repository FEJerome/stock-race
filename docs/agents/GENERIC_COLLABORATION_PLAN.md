## 👥 智能体角色分配
**6个通用功能型智能体，最多4个并行执行**：

| 智能体 | 职责范围 | 通用工作目录 | 典型任务示例 | 优先级管理 |
|--------|----------|--------------|--------------|------------|
| **架构设计智能体** | 系统架构设计、技术选型 | `docs/architecture/`, `docs/design/` | 系统架构设计、接口定义、技术评估 | 🚨 高（基础依赖） |
| **核心逻辑智能体** | 核心业务逻辑实现 | `src/core/`, `src/logic/` | 业务算法实现、数据处理、规则引擎 | ⚠️ 中（业务核心） |
| **接口服务智能体** | API接口开发、服务层实现 | `src/services/`, `src/api/` | API设计、外部集成、数据格式转换 | ⚠️ 中（系统集成） |
| **用户界面智能体** | UI组件开发、用户体验 | `src/ui/`, `src/components/` | 组件开发、状态管理、交互实现 | ⚠️ 中（用户交互） |
| **基础设施智能体** | 工具类开发、配置管理 | `src/utils/`, `config/`, `scripts/` | 工具开发、CI/CD配置、环境搭建 | 🔄 持续（支持性） |
| **协调管理智能体** | 进度跟踪、冲突解决 | `docs/coordination/`, `docs/agents/` | 进度汇总、依赖管理、代码审查 | 🔄 持续（协调性） |

## ⚙️ 执行策略（并行限制：最多4个）
**核心原则**：智能体并行执行数量不超过四个，其他智能体串行执行，等待运行的智能体结束。

**分组策略示例**：
- **第一组（并行，立即启动）**：架构设计智能体、核心逻辑智能体、协调智能体、基础设施智能体
- **第二组（串行等待）**：接口服务智能体（等待架构设计完成）、用户界面智能体（等待核心逻辑准备）

**通用依赖关系**：
```
架构设计完成 ← 接口服务智能体启动 ← 系统集成测试
核心逻辑完成 ← 用户界面智能体启动 ← 端到端测试
基础设施就绪 ← 所有智能体开发 ← 持续集成
```

## 📅 通用执行时间线模板
**目标**：建立标准化开发流程，确保项目有序推进

**阶段一：架构与设计（第1周）**
- D1：需求分析和项目规划
- D2：系统架构设计和技术选型
- D3：接口定义和模块划分
- D4：开发环境配置和工具链建立
- D5：第一次阶段汇报（架构设计方案）

**阶段二：核心实现（第2-3周）**
- 核心逻辑智能体：业务逻辑实现
- 接口服务智能体：API和服务层开发
- 用户界面智能体：UI组件和交互实现
- 基础设施智能体：工具和配置完善

**阶段三：集成与测试（第4周）**
- 系统集成测试
- 端到端测试验证
- 性能优化和调整
- 最终验收测试

**阶段四：部署与维护（第5周及以后）**
- 生产环境部署
- 监控和日志配置
- 文档完善和知识转移
- 后续维护计划

## 📊 阶段性汇报机制
**每日汇报**（各智能体负责）：
- **时间**：每日工作结束前
- **内容**：今日进展、遇到的问题、明日计划
- **格式**：更新在各自工作领域的文档中

**阶段汇报**（协调智能体负责）：
- **时间**：关键里程碑完成时
- **内容**：阶段成果总结、项目状态更新、下一步计划
- **格式**：更新项目主文档，向项目负责人汇报

**周度汇总**（协调智能体负责）：
- **时间**：每周工作结束前
- **内容**：本周完成情况、下周计划、风险分析
- **格式**：更新进度跟踪文档

## 🔧 工作空间配置
配置6个git-worktree支持并行开发：
1. `worktree-architecture` - 架构设计智能体
2. `worktree-core-logic` - 核心逻辑智能体
3. `worktree-interface-service` - 接口服务智能体
4. `worktree-user-interface` - 用户界面智能体
5. `worktree-infrastructure` - 基础设施智能体
6. `worktree-coordination` - 协调管理智能体

## 📋 文档更新规范
- **任务状态**：`pending` → `in_progress` → `completed` → `blocked`
- **每日更新**：各智能体更新负责领域的工作文档
- **进度跟踪**：协调智能体更新进度文档和项目主文档
- **依赖管理**：跨模块变更更新依赖关系文档

## 🔄 主智能体任务分发流程
1. **任务接收**：主智能体接收复杂任务请求
2. **任务分析**：分析任务类型、复杂度、技术需求
3. **智能体匹配**：根据任务特性匹配最合适的智能体
4. **并行检查**：检查当前并行智能体数量（≤4）
5. **任务委派**：将任务分配给选定的智能体
6. **进度监控**：监控任务执行状态，但不参与具体开发

## ⚠️ 注意事项
1. **并行限制**：严格遵守最多4个智能体并行的限制
2. **依赖管理**：清晰记录和管理模块间依赖关系
3. **沟通协调**：定期同步进度，及时解决阻塞问题
4. **质量保证**：所有代码必须通过审查和测试才能合并
5. **文档完整**：保持文档与代码同步更新

## 🛠️ 项目适配指南
1. **角色自定义**：可根据项目需求调整智能体角色定义
2. **并行数调整**：根据团队规模调整并行限制
3. **时间线定制**：根据项目复杂度调整阶段划分
4. **工具链配置**：根据技术栈配置相应开发工具

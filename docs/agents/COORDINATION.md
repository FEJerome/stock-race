# 多智能体协调流程指南

## 🎯 概述

本文档定义多智能体协同开发的协调流程、沟通机制和冲突解决策略。通过标准化的工作流程，确保6个智能体能够高效、无冲突地并行开发。

## 📅 每日协调流程

### 晨间同步（虚拟）
**时间**：每个工作日开始前（通过文档更新实现）
**参与方**：所有智能体（通过文档更新）
**协调方**：协调智能体

**流程**：
1. 各智能体更新自己的TODO文档：
   - 更新"今日进展"部分
   - 记录"遇到的问题"
   - 制定"明日计划"
2. 协调智能体收集所有更新
3. 生成 `coordination/PROGRESS.md` 每日进度报告
4. 更新 `coordination/DEPENDENCIES.md` 依赖状态

**晨间更新模板**：
```markdown
### 今日进展
- [x] 完成XXX功能开发
- [ ] 进行YYY功能测试

### 遇到的问题
- 问题1：描述...
- 问题2：描述...

### 明日计划
1. 继续ZZZ功能开发
2. 测试AAA模块
```

### 晚间总结
**时间**：每个工作日结束时
**流程**：
1. 各智能体更新当日任务状态
2. 协调智能体汇总整体进度
3. 识别阻塞问题和依赖冲突
4. 更新项目状态到 `CLAUDE.md`（每周或里程碑时）

## 🔄 任务状态管理

### 任务状态流转
```
pending → in_progress → completed
           ↓
        blocked（需要协调）
```

### 状态更新规则
1. **开始任务**：将状态改为 `in_progress`
2. **完成任务**：将状态改为 `completed`，更新进度
3. **遇到阻塞**：标记为 `blocked`，记录问题
4. **依赖等待**：标记为 `waiting`，注明依赖方

### 阻塞问题处理
**定义**：阻碍任务进展的技术问题或依赖问题
**上报流程**：
1. 在TODO文档中标记任务为 `blocked`
2. 详细描述问题和尝试的解决方案
3. 在 `coordination/DEPENDENCIES.md` 中记录依赖
4. 通知协调智能体

**解决流程**：
1. 协调智能体分析问题优先级
2. 组织相关智能体协商解决方案
3. 更新依赖文档和任务状态
4. 记录解决方案供未来参考

## 📦 依赖管理

### 依赖类型
1. **代码依赖**：模块间API调用和接口依赖
2. **数据依赖**：数据格式和流转依赖
3. **时序依赖**：任务执行顺序依赖
4. **资源依赖**：共享资源（配置文件等）依赖

### 依赖记录
所有跨模块依赖必须记录在 `coordination/DEPENDENCIES.md`：

```markdown
## 依赖记录

### 前端组件 → 后端服务
- **依赖内容**：API响应数据格式
- **变更影响**：修改API响应结构需要同步更新前端
- **负责人**：前端组件智能体 + 后端服务智能体
- **状态**：稳定
- **最后验证**：2026-01-29
```

### 接口变更流程
**当需要修改跨模块接口时**：
1. **提前通知**：至少提前1天通知相关智能体
2. **文档更新**：更新接口文档和依赖记录
3. **并行开发**：
   - 提供向后兼容的过渡方案
   - 分阶段部署和测试
4. **协调测试**：协调智能体组织集成测试

## 🌳 Git工作流协调

### 分支管理
**分支命名规范**：
- `feature/{智能体缩写}-{功能描述}`
- 示例：`feature/be-adapters-编码优化`

**分支创建**：
1. 从最新的 `main` 分支创建
2. 分支名称清晰描述功能和负责智能体
3. 一个功能一个分支，避免过大的分支

### 代码合并流程
**标准合并流程**：
```
开发者提交PR → 协调智能体审核 → 集成测试 → 合并到main
```

**审核要点**：
1. **代码质量**：符合编码规范，有适当测试
2. **接口兼容**：不影响其他模块的接口
3. **文档更新**：相关文档已同步更新
4. **依赖管理**：跨模块依赖已正确处理

**紧急合并**（仅用于紧急修复）：
1. 通知协调智能体
2. 简化测试流程，但必须通过基础测试
3. 合并后立即通知所有智能体
4. 后续补全完整测试和文档

### 冲突解决策略
**预防措施**：
1. 模块职责清晰，减少代码重叠
2. 接口设计稳定，减少频繁变更
3. 及时合并小改动，避免大冲突

**解决流程**：
1. **识别冲突类型**：代码冲突 vs 逻辑冲突
2. **召集相关方**：冲突涉及的所有智能体
3. **协商解决方案**：基于技术优劣和项目需求
4. **实施解决**：由协调智能体主导合并
5. **记录经验**：更新协调指南避免重复

## 🚨 紧急问题处理

### 紧急问题定义
1. **系统崩溃**：服务无法启动或运行
2. **安全漏洞**：发现安全风险
3. **数据丢失**：用户数据丢失风险
4. **严重阻塞**：多个智能体工作被阻塞

### 处理流程
1. **立即通知**：直接通知协调智能体
2. **暂停相关工作**：避免问题扩大
3. **集中解决**：相关智能体集中解决问题
4. **恢复验证**：问题解决后验证恢复状态
5. **事后分析**：记录问题和改进措施

## 🤝 沟通和协作

### 沟通渠道
1. **文档沟通**：主要沟通方式（TODO文档、协调文档）
2. **问题记录**：详细记录问题和解决方案
3. **知识共享**：重要发现更新到相关文档

### 协作原则
1. **透明性**：工作进展和问题对协调智能体透明
2. **及时性**：及时更新状态，避免信息滞后
3. **责任性**：对自己负责的模块任务负责
4. **协作性**：积极协助解决跨模块问题

### 争议解决
1. **技术争议**：基于技术数据和项目需求决策
2. **优先级争议**：由协调智能体根据项目目标裁定
3. **资源争议**：协调智能体分配和调度

## 📚 培训和知识转移

### 新智能体入职
1. 阅读 `agents/ROLES.md` 了解角色职责
2. 学习 `agents/WORKTREE_GUIDE.md` 配置工作环境
3. 阅读负责模块的TODO文档
4. 了解项目架构（`CLAUDE.md`）
5. 与协调智能体进行初始协调

### 知识共享机制
1. **技术决策记录**：重要决策记录在相关文档
2. **问题解决方案库**：常见问题解决方案汇总
3. **最佳实践指南**：各模块开发最佳实践
4. **代码审查反馈**：通过代码审查共享知识

## 🔄 持续改进

### 流程改进
1. **定期回顾**：每两周回顾协调流程效果
2. **问题收集**：收集各智能体的流程问题反馈
3. **流程优化**：根据反馈优化协调流程
4. **文档更新**：及时更新协调指南

### 反馈机制
**反馈渠道**：
1. TODO文档中的问题记录
2. 协调文档的改进建议
3. 直接向协调智能体反馈

**处理流程**：
1. 收集和分类反馈
2. 分析改进优先级
3. 实施改进措施
4. 验证改进效果

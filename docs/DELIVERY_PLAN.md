# 多形态交付策略

本文档定义 AI股票竞赛平台 三种产品形态的交付边界。

- **Local**：本地部署版，自用（单用户），功能对齐Full但无商业功能
- **MVP**：合规验证版，微信小程序7天试用
- **Full**：完整商业版，多用户服务，全功能开放

## 形态核心差异

| 维度 | Local | MVP | Full |
|------|-------|-----|------|
| **部署方式** | 本地部署，自用 | 微信小程序云端 | 生产环境，多用户服务 |
| **用户数量** | 单用户（无登录） | 多用户（微信授权） | 多用户（完整账号） |
| **数据源** | 实时行情+新闻+舆论 | 实时行情 | 实时行情+新闻+舆论 |
| **AI模型** | 多模型并行对比 | 单一模型（DeepSeek） | 多模型并行 |
| **商业功能** | ❌ 无 | 7天试用限制 | 完整订阅+等级 |
| **前端形态** | Web（Vue + FastAPI） | 微信小程序 | 小程序+Web+App |
| **服务架构** | 单体后端（模块清晰） | 微服务 | 微服务 |

**核心原则**：
- Local ≠ 功能阉割版，而是 **自用版**
- Local 与 Full 的功能差异仅在于：**多用户支持** 和 **商业功能**
- Local 必须验证所有技术点：多数据源、多AI模型、实时数据

## Local 用户体验与技术实现

### 产品形态：本地服务 + 自动打开浏览器

**使用流程**：
```bash
$ python local.py
Starting Local AI Trading Platform...
Server running at http://localhost:8000
Opening browser... ✓
```

**用户体验**：
- 双击/命令行启动后，自动弹出浏览器新标签页
- 用户直接使用，无需关心"服务"概念
- 地址栏显示 `localhost:8000`（开发者自用场景可接受）
- 提供 `--headless` 参数（仅启动服务，不打开浏览器）

**不采用的方案**：
- ❌ 系统托盘应用（当前阶段不需要后台常驻）
- ❌ Electron/Tauri（技术栈冲突，增加复杂度）
- ❌ PyQt桌面（Vue前端已选，无需内嵌WebView）

### 技术实现细节

**后端架构**：FastAPI 单体 + 模块化设计

```
local/backend/
├── api/                   # API路由层
│   ├── market.py         # 行情接口（WebSocket + REST）
│   ├── news.py           # 新闻/舆论接口
│   ├── ai.py             # AI交易员管理
│   ├── trade.py          # 交易执行
│   └── strategy.py       # 策略配置
├── services/             # 业务逻辑层（从legacy复用）
│   ├── market_collector.py   # 原market-data-service
│   ├── news_collector.py     # 原news-service
│   ├── ai_adapter.py         # 原trading-ai-service
│   └── trading_engine.py     # 原backend简化
├── models/               # 数据模型（与core/复用）
├── db/                   # SQLite连接
└── main.py               # FastAPI入口 + 自动打开浏览器
```

**关键技术点**：

| 技术点 | 实现 | 理由 |
|--------|------|------|
| **异步架构** | FastAPI async/await | 行情采集、AI调用都是IO密集型 |
| **实时通信** | WebSocket | 前端实时接收行情推送 |
| **模块化** | APIRouter拆分 | 便于后续拆微服务 |
| **依赖注入** | FastAPI Depends | 管理数据库、配置、客户端 |

**性能评估**：
- 并发量：1（单用户自用）
- 数据存储：SQLite（GB级以下无压力）
- 采集频率：即使每秒采集，Python asyncio轻松处理

### 复用 Legacy 代码策略

**直接迁移的模块**（业务逻辑不变，换框架）：
- `legacy/services/market-data-service/` → `services/market_collector.py`
- `legacy/services/trading-ai-service/` → `services/ai_adapter.py`
- `legacy/services/news-service/` → `services/news_collector.py`

**演进保障**：
- Local阶段模块边界清晰 → Full阶段直接拆成微服务
- 不需要重写业务逻辑，仅需调整通信方式（函数调用 → HTTP/gRPC）

## 技术栈定义

### Local 技术栈（2026-03-06确定）

**后端**：FastAPI（Python单体服务）
- AI适配器：多模型支持（DeepSeek/通义/Kimi/GLM）
- 数据源适配器：多源混合（行情+新闻+舆论）
- 交易引擎：虚拟交易、持仓管理、收益计算
- 存储：SQLite（本地）

**前端**：Vue 3 + Vite
- 组合式API
- WebSocket实时数据推送
- 组件：AI管理、策略配置、实时行情、交易面板、收益图表

**与Full的演进关系**：
```
Local（单体）
├── AI适配器 ────────→ Full（ai-service微服务）
├── 数据源适配器 ────→ Full（market-data-service/news-service）
├── 交易引擎 ────────→ Full（trading-service）
└── Vue前端 ─────────→ Full（复用前端组件）
```

## 详细功能边界

### 1. AI交易员系统

**Local**：
- Web界面创建AI交易员
- **多模型选择**（DeepSeek/通义/Kimi等），可同时创建多个AI
- 完整的策略收集对话（5维度）
- AI职级系统（实习生/经理/合伙人）
- 多AI并行运行，对比收益表现

**MVP**：
- 小程序内表单创建
- 仅DeepSeek单一模型
- 标准策略收集
- 无职级系统

**Full**：
- 同Local，增加AI人设立绘
- 社交功能（分享AI策略）

### 2. 数据系统

**Local**：
- **实时行情**：多数据源混合（东方财富/新浪财经/同花顺等）
- **新闻数据**：财经新闻采集与展示
- **舆论数据**：社交媒体情绪数据
- 数据整合：多源融合、降权、failover

**MVP**：
- 单一实时行情源
- 无新闻/舆论数据

**Full**：
- 同Local
- 云端数据缓存与加速

### 3. 交易执行

**Local**：
- 基于实时数据的虚拟交易
- WebSocket推送价格变动
- 完整的持仓管理和收益计算
- 交易决策理由展示（AI内心戏）

**MVP**：
- 实时交易执行
- 7天试用期后锁定功能

**Full**：
- 同Local
- 历史回测功能

### 4. 用户系统

**Local**：
- **无用户登录**，开箱即用
- 数据存储在本地SQLite
- 单用户自用

**MVP**：
- 微信小程序授权登录
- OpenID识别用户
- 7天试用倒计时

**Full**：
- 完整注册/登录/找回密码
- 实名认证
- 订阅状态管理

## 开发顺序建议

### Phase 1：Local 本地验证（当前）
目标：验证所有技术点，自用版完整体验

1. **基础架构**
   - FastAPI + Vue 3 搭建
   - SQLite存储初始化

2. **数据采集系统**
   - 多数据源行情采集（复用legacy代码）
   - 新闻/舆论数据采集
   - WebSocket实时推送

3. **AI系统**
   - 多模型适配器（DeepSeek/通义/Kimi）
   - AI交易员创建与管理
   - 策略收集对话（Web版）

4. **交易系统**
   - 虚拟交易执行
   - 持仓管理
   - 收益计算与展示

5. **数据展示**
   - 实时行情面板
   - 交易历史
   - 收益图表
   - 多AI对比排行

### Phase 2：MVP 合规验证
目标：微信小程序合规上线

1. 接入微信登录
2. 单一模型支持（DeepSeek）
3. 7天试用限制
4. 简化版功能

### Phase 3：Full 商业运营
目标：生产环境多用户服务

1. 微服务拆分（基于Local的模块边界）
2. 用户系统完善
3. 订阅支付系统
4. 等级/社交功能
5. 性能优化与高可用

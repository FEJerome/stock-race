# Stock-Race项目注意事项

## 使用条款与项目规范

### 1. 项目定位与用途
- **教育研究性质**：本项目为AI股票竞赛平台的技术演示和原型验证
- **非真实交易**：所有交易均为虚拟操作，不涉及真实资金
- **数据免责**：股票数据来源于公开免费API，仅供参考，不保证实时性和准确性
- **开发学习目的**：适合学习微服务架构、实时数据处理、AI集成等技术

### 2. 环境部署注意事项
- **中国网络环境**：项目提供了中国镜像源优化版安装脚本（`*_china.sh`）
- **混合部署策略**：支持主机服务+容器化混合部署，便于开发调试
- **权限要求**：数据库安装需要sudo权限，容器化部署需要docker组权限
- **版本兼容性**：
  - Node.js要求≥20.0.0（当前v18.19.1可用但有警告）
  - Python要求≥3.8
  - Docker要求≥20.10（容器化部署需要）

### 3. 数据使用规范
- **数据源限制**：使用新浪、腾讯、东方财富三大免费数据源，遵守其API调用限制
- **频率限制**：单个IP每分钟不超过60次请求，避免被封禁
- **缓存策略**：实现智能TTL缓存，减少重复请求
- **数据验证**：多源交叉验证，异常数据自动丢弃
- **模拟降级**：所有数据源失败时优雅降级到模拟数据

## 安全规范

### 1. 代码安全
- **依赖审查**：定期更新依赖包，检查安全漏洞
- **输入验证**：所有API接口验证输入参数，防止注入攻击
- **错误信息**：生产环境不返回详细错误信息，避免信息泄露
- **密码安全**：使用bcrypt哈希存储用户密码

### 2. 数据安全
- **敏感信息**：数据库密码、API密钥等敏感信息使用环境变量存储
- **数据隔离**：开发环境和生产环境数据严格隔离
- **备份策略**：定期备份数据库，配置数据恢复流程
- **访问控制**：API接口实施适当的认证和授权检查

### 3. 网络安全
- **端口管理**：仅开放必要的服务端口（3000, 3001, 8000, 8001, 5432, 6379）
- **防火墙配置**：生产环境配置防火墙规则，限制访问来源
- **HTTPS部署**：生产环境必须启用HTTPS，配置SSL证书
- **速率限制**：实现API速率限制，防止暴力请求

### 4. 容器安全
- **镜像安全**：使用官方基础镜像，定期更新安全补丁
- **权限最小化**：容器以非root用户运行，限制权限
- **资源限制**：配置容器CPU和内存限制，防止资源耗尽
- **网络隔离**：使用Docker网络隔离服务，限制容器间通信

## 最佳实践建议

### 1. 开发环境最佳实践
- **环境一致性**：优先使用`docker-compose up -d`确保环境一致
- **版本控制**：使用nvm管理Node.js版本，venv管理Python环境
- **代码规范**：遵循项目编码标准，使用ESLint和Black等工具
- **提交规范**：遵循Conventional Commits规范，编写有意义的提交信息

### 2. 调试与排错
- **渐进验证**：逐个服务启动验证，使用`check_environment.sh`检查状态
- **日志管理**：统一日志格式，关键操作记录详细日志
- **监控指标**：实现服务健康检查，监控响应时间和错误率
- **问题隔离**：使用Docker容器隔离问题，快速重建环境

### 3. 性能优化
- **连接池管理**：数据库和Redis使用连接池，避免频繁创建连接
- **批量操作**：股票数据批量获取，减少API调用次数
- **缓存策略**：热点数据使用Redis缓存，配置合理的过期时间
- **异步处理**：I/O密集型操作使用异步模式，提高并发能力

### 4. 数据质量保障
- **多源验证**：同时从多个数据源获取数据，进行交叉验证
- **异常检测**：实现价格异常、时间戳异常等检测机制
- **质量评分**：基于时效性、完整性、合理性计算数据质量分数
- **降级策略**：数据质量低于阈值时自动降级到备用方案

### 5. 部署与运维
- **配置管理**：使用环境变量管理配置，区分不同环境
- **健康检查**：所有服务实现健康检查端点，便于监控
- **滚动更新**：生产环境使用滚动更新策略，避免服务中断
- **备份恢复**：制定数据库备份和恢复流程，定期测试

## 常见风险与应对

### 1. 数据源风险
- **风险**：免费数据源API变更或停止服务
- **应对**：实现多数据源负载均衡，设计备用数据源方案
- **监控**：实时监控数据源健康状态，自动故障转移

### 2. 网络风险
- **风险**：中国网络环境访问国外服务不稳定
- **应对**：提供中国镜像源优化方案，配置超时和重试机制
- **降级**：网络异常时优雅降级到模拟数据，保证系统可用

### 3. 依赖风险
- **风险**：第三方依赖包安全漏洞或破坏性更新
- **应对**：锁定依赖版本，定期更新并测试，使用Dependabot等工具
- **隔离**：关键功能实现抽象层，降低对具体实现的依赖

### 4. 资源风险
- **风险**：Redis内存不足，数据库连接池耗尽
- **应对**：监控资源使用情况，设置合理的资源限制和告警
- **优化**：实现连接池管理，配置Redis淘汰策略

## 紧急情况处理

### 1. 服务不可用
```bash
# 快速诊断
bash check_environment.sh

# 重启所有服务
docker-compose down && docker-compose up -d

# 检查日志
docker-compose logs -f [service_name]
```

### 2. 数据异常
```bash
# 检查数据源状态
curl http://localhost:8001/api/v1/monitoring/data-sources

# 清理Redis缓存
redis-cli FLUSHALL

# 重启数据服务
docker-compose restart data-service
```

### 3. 数据库问题
```bash
# 检查数据库连接
psql -h localhost -U postgres -d stock_race -c "SELECT 1"

# 备份数据库
pg_dump -h localhost -U postgres stock_race > backup_$(date +%Y%m%d).sql

# 恢复数据库
psql -h localhost -U postgres -d stock_race < backup_file.sql
```

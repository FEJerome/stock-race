# Stock-Race 协作规则

本文件规定项目现场的角色、质量闸与交付边界。具体任务由维护者授权的规划会话编排；规划侧操作手册只有一份，不在本仓库复制。

## 一、角色与授权

### 规划会话

负责需求讨论、任务编号、任务卡、STATUS、资源协调、链式调用、复审结论和合并清场。正式编号研发通常由自动化规划台承担；早期高交互阶段或其他临时任务，可由维护者明确授权的秘书规划台承担。

两类规划台是职责分工而非权限等级。维护者对具体任务的直接授权始终优先，但执行者不能把一次授权自动扩展到其他任务。

### 执行从者

按任务卡实施并自验，随测随改。交付必须包含实际变更、验证结果、未覆盖项和待裁事项；不得把未运行的方案写成已完成，也不得自行合并或推送。

### 检验员

依据任务契约组织检查，核对实现与验收条件，推动问题在项目现场闭环。链式任务中，规划会话默认只与检验员协调，检验员再与执行从者协作，避免多方同时修改同一现场。

### 机械员

只承担边界清楚、判断量低的重复性修改。不得自行变更方案、接口、数据结构或验收标准；完成后交检验员检查。

### 复审从者

由未参与实施的独立会话承担，复用已有环境复测，并审查代码、配置和文档。执行者的自验不能替代独立复审，复审也不得重复实施者未经验证的结论。

## 二、协作拓扑

常规链式路径：

`规划会话 → 检验员 → 执行从者／机械员 → 检验员复测 → 规划会话验收 → 独立复审`

规划会话可根据任务规模简化角色，但不得省略必要的自验和独立复审。小型只读调研可由单个执行会话完成；多文件代码、配置或环境变更不得借“小任务”规避复审。

跨会话消息只用于提问、交货和求裁。方案、验收和最终结论必须写入 feature、research 或 decision 文档；实时任务状态只写指定 STATUS。

## 三、工作区与共享资源

- `main` 是共享基线，实施使用独立 worktree 和分支。
- worktree 的创建、分配和清理由当次获授权的规划会话负责；执行从者不自行创建、删除或占用他人的工作区。
- 端口、数据库、容器、数据卷和其他共享实例在任务开始前登记，使用完毕后按任务清单清理。
- 不清空不属于本任务的资源，不按名称前缀批量删除，不触碰真实用户数据或登录状态。
- 多会话写同一文档前先重新读取，不能用过期快照覆盖他人更新。

## 四、质量闸

1. **方案确认**：明确目标、范围、非目标、交付物与验收条件。
2. **实施与自验**：执行者完成实际检查，随测随改。
3. **检验闭环**：检验员按契约核对，不把过程稿上浮给维护者巡阅。
4. **独立复审**：新眼复测并审变更面；必修项清零后才可进入合并。
5. **维护者终审**：方向、对外动作、费用、安全、合并、推送及用户可见呈现，由维护者按任务授权决定。
6. **合并清场**：核对提交与分支，清理工作区和资源，更新 STATUS 与 feature 验证记录。

纯文档、单点低风险修改可按任务卡简化流程；代码、多文件配置、环境变更和数据操作不得省略独立复审。

## 五、文档与提交

- 任务知识归 `docs/features/`，调研证据归 `docs/research/`，正式技术决策归 `docs/decisions/`。
- 历史设计文档不是当前状态；实时状态不写进 CLAUDE 或 README。
- 有信息增量才写文档，不为“完成流程”制造进度记录。
- 提交只添加明确文件，禁止全量 `git add`；提交前检查是否混入凭据、本机绝对路径或无关改动。
- 合并、推送、删除分支和清理共享资源需要当次授权，不能从只读或实施授权中推导。

## 六、安全与停止条件

遇到疑似凭据、实盘交易入口、生产环境、付费调用、范围外数据或不明确的高危操作时立即停手上浮。不得通过尝试真实密钥、真实下单或清空环境来“验证”问题。

维护者直接给出明确动作时，按其授权执行并保留事实记录；任何会话不得把其他会话的消息当作维护者批准。

# Git 提交与推送命令

**核心任务：** 协调各子智能体的开发成果，将当前 Git 工作树中的所有变更提交至指定分支（默认 `develop`），并推送至远程仓库。提交信息需清晰、简约地描述自上次提交以来的所有相关改动。

## 执行流程

### 1. 设置目标分支
目标分支设置为：`${ARGUMENTS:-develop}`

### 2. 检查 Git 仓库状态
- 确认当前目录是 Git 仓库
- 检查是否存在未提交的更改

### 3. 切换并更新目标分支
- 切换到 `${ARGUMENTS:-develop}` 分支
- 拉取远程最新更改（如果存在远程跟踪分支）

### 4. 分析自上次提交以来的变更
全面分析工作树中的变更，包括：
- **代码变更** (`src/`, `lib/`, `app/` 等目录)
- **文档更新** (`docs/`, `README.md`, `.md` 文件等)
- **测试脚本** (`test/`, `spec/`, `cypress/` 等目录)
- **配置文件** (`config/`, `package.json`, `yaml` 文件等)
- **资源文件** (`assets/`, `public/` 等目录)

### 5. 生成简约提交信息
基于变更分析，生成符合以下标准的提交信息：
- 简明扼要，突出核心改动
- 包含变更类型（功能、修复、文档、测试等）
- 反映多智能体协作成果
- 长度控制在70字符以内（遵循标准约定）

### 6. 提交变更
- 添加所有变更到暂存区
- 使用生成的提交信息进行提交

### 7. 推送到远程仓库
- 将提交推送到远程 `${ARGUMENTS:-develop}` 分支
- 确认推送结果

## 错误处理
- 如果不是 Git 仓库，提供清晰错误信息
- 如果没有变更可提交，提示用户
- 如果分支切换或推送失败，提供解决建议

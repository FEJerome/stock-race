# 自动化开发与文档集成命令

**指令：** 执行全权限的自动化开发任务，并强制保持所有相关文档为最新状态。

## 核心原则

1.  **全权限执行**：使用 `--dangerously-skip-permissions` 模式，避免中断性确认提示，实现完全自动化[2,5](@ref)。
2.  **文档即代码**：任何代码、脚本或配置的修改，必须同步更新其对应的文档。文档是本次任务的可交付成果之一。
3.  **结构化归档**：所有新生成的文档必须依据既定规范放置在合适的文件夹内，并整合到以 `CLAUDE.md` 为根入口的文档链路中，确保后续智能体能够无缝调用和理解项目上下文[1,3](@ref)。

## 工作流程与具体指令

请严格遵循以下步骤执行任务：`$ARGUMENTS`（此处替换为您的具体开发需求，例如“实现用户登录模块的OAuth 2.0集成”）。

### 第一阶段：分析与规划
1.  **深度思考**：启动 `think harder` 或 `ultrathink` 模式，深入分析 `$ARGUMENTS` 的需求，并评估其对现有代码库的影响[5](@ref)。
2.  **扫描文档链**：通读项目根目录下的 `CLAUDE.md` 文件，理解项目架构、编码规范、以及现有的文档结构约定[1,3](@ref)。
3.  **制定实施计划**：规划实现方案，并明确列出所有需要创建或更新的文档清单（例如：API接口文档、数据库变更说明、部署指南、测试报告等）。

### 第二阶段：开发与文档同步执行
1.  **启用全权限模式**：在实施任何更改前，确保已激活全权限设置，以无中断方式执行命令。
2.  **代码实现**：根据计划编写或修改代码、测试脚本和配置文件。
3.  **即时文档更新**：
    *   **更新现有文档**：在修改某个模块后，立即定位并更新其关联的文档（如代码注释、README.md、API文档等）。
    *   **创建新文档**：对于新功能，必须创建新文档。文档路径需符合项目规范（例如：`/docs/api/` 存放接口文档，`/docs/test-reports/` 存放验证报告）。
    *   **更新文档索引**：确保所有新建的文档都在 `CLAUDE.md` 文件或其引用的主目录文件（如 `docs/README.md`）中被正确索引和描述，形成可追溯的文档链[3](@ref)。

### 第三阶段：测试与验证报告
1.  **运行测试**：执行相关的单元测试、集成测试或您编写的验证脚本。
2.  **生成验证报告**：根据测试结果，自动生成或更新测试验证报告。报告应清晰说明测试目的、过程、结果以及通过标准。将该报告放置在预设的文档目录（如 `/docs/test-reports/`）中。
3.  **更新项目状态**：在 `CLAUDE.md` 或相关项目总览文档中，更新本项目进度和当前状态。

### 第四阶段：最终整理与提交
1.  **完整性检查**：进行最终检查，确保所有代码更改都有对应的文档更新，且文档链接正确。
2.  **生成变更摘要**：创建一个简洁的变更摘要，概述本次开发工作和对应的文档更新情况。
3.  **提交**：将代码和文档的所有更改一并提交到版本控制系统，提交信息需反映代码和文档的变更。

## 可用工具与权限
*   **权限**：已配置为允许所有必要的文件读写、Shell命令执行、Git操作等。
*   **关键工具**：确保可调用 `git`, `npm`/`pip` 等包管理器，测试框架，以及任何项目特定的构建脚本[2,4](@ref)。

请现在开始执行任务：`$ARGUMENTS`。

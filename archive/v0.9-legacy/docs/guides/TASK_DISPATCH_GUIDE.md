# 主智能体任务分发指南

## 🎯 概述

本文档定义主智能体的任务分发机制。主智能体作为纯任务分发协调者，只负责任务分析、智能体匹配和任务委派，不参与具体开发、测试或协调工作。所有具体执行工作都委派给子智能体完成。

## 🏗️ 主智能体角色定位

### 核心原则：纯任务分发
- **仅分发**：只负责任务接收、分析、匹配和委派
- **不参与**：不参与具体开发、测试、文档编写、冲突解决
- **不协调**：协调工作由专门的协调管理智能体负责
- **不执行**：所有执行工作委派给相应的子智能体

### 职责边界
- ✅ **允许的操作**：任务分析、智能体匹配、并行限制检查、任务委派
- ❌ **禁止的操作**：代码编写、测试执行、文档更新、冲突解决、进度跟踪
- 🔄 **协作接口**：与协调管理智能体协作，确保任务顺利执行

## 🔄 任务分发流程

### 完整工作流
```
任务接收 → 任务分析 → 智能体匹配 → 并行检查 → 任务委派 → 状态监控
```

### 详细步骤

#### 1. 任务接收
- **输入源**：用户请求、项目需求、系统触发
- **格式要求**：清晰的任务描述、预期结果、约束条件
- **初始评估**：快速评估任务复杂度和可行性

#### 2. 任务分析
使用任务分析模板对接收到的任务进行详细分析：

**任务分析模板**：
```markdown
## 任务分析报告
- **任务ID**: {唯一标识符}
- **接收时间**: {时间戳}
- **任务描述**: {详细描述}
- **预期结果**: {可衡量的成果}
- **技术需求**:
  - 架构设计需求: [高/中/低]
  - 核心逻辑需求: [高/中/低]
  - 接口服务需求: [高/中/低]
  - 用户界面需求: [高/中/低]
  - 基础设施需求: [高/中/低]
- **复杂度评估**: [简单/中等/复杂/非常复杂]
- **预估工作量**: [小/中/大/巨大]
- **依赖关系**: [无/低/中/高]
- **优先级**: [紧急/高/中/低]
```

#### 3. 智能体匹配
基于任务分析结果匹配最合适的智能体：

**智能体匹配矩阵**：
| 任务类型 | 首选智能体 | 备选智能体 | 匹配理由 |
|----------|------------|------------|----------|
| 架构设计类 | 架构设计智能体 | 基础设施智能体 | 涉及系统架构和技术选型 |
| 业务逻辑类 | 核心逻辑智能体 | 架构设计智能体 | 涉及核心算法和数据处理 |
| 接口集成类 | 接口服务智能体 | 核心逻辑智能体 | 涉及API设计和外部集成 |
| 用户交互类 | 用户界面智能体 | 接口服务智能体 | 涉及UI组件和用户体验 |
| 工具配置类 | 基础设施智能体 | 架构设计智能体 | 涉及开发工具和环境配置 |
| 协调管理类 | 协调管理智能体 | 所有智能体 | 涉及进度跟踪和冲突解决 |

**匹配算法**：
1. 分析任务的技术需求分布
2. 计算各智能体的匹配度分数
3. 选择匹配度最高的智能体
4. 考虑智能体当前负载和专长

#### 4. 并行限制检查
**并行限制规则**：最多4个智能体同时执行任务

**检查流程**：
1. 查询当前活跃智能体数量
2. 检查目标智能体是否已处于活跃状态
3. 如果并行数已达上限（4个）：
   - 将任务加入等待队列
   - 按优先级排序等待任务
   - 监控活跃任务完成情况
4. 如果并行数未达上限：
   - 立即分配任务
   - 更新活跃智能体计数

#### 5. 任务委派
**委派模板**：
```markdown
## 任务委派通知
- **任务ID**: {任务ID}
- **委派时间**: {时间戳}
- **执行智能体**: {智能体名称}
- **任务描述**: {任务描述}
- **预期交付物**: {具体交付要求}
- **完成标准**: {验收条件}
- **预计完成时间**: {时间估计}
- **特殊说明**: {其他注意事项}
```

**委派方式**：
- 创建任务文档在相应智能体工作目录
- 更新任务状态为 `assigned`
- 通知协调管理智能体任务分配情况

#### 6. 状态监控
**监控职责**：
- 跟踪任务执行状态（assigned → in_progress → completed）
- 监控任务超时情况
- 处理任务阻塞上报
- 不参与具体进度跟踪（由协调智能体负责）

### 等待队列管理
**队列排序规则**：
1. 优先级（紧急 > 高 > 中 > 低）
2. 依赖关系（无依赖 > 有依赖）
3. 任务大小（小 > 中 > 大）
4. 等待时间（先到先得）

## ⚠️ 异常处理

### 任务阻塞处理
1. **检测阻塞**：智能体上报任务阻塞状态
2. **分析原因**：技术问题、依赖缺失、资源不足
3. **解决方案**：
   - 重新分配任务给其他智能体
   - 分解任务为更小子任务
   - 调整任务优先级和依赖
4. **记录学习**：记录阻塞原因和解决方案

### 智能体失效处理
1. **检测失效**：智能体无响应或频繁失败
2. **应急措施**：
   - 重新分配任务给备用智能体
   - 临时调整并行限制
   - 通知协调智能体介入
3. **根本解决**：分析失效原因，优化智能体配置

### 并行死锁处理
1. **检测死锁**：所有智能体相互等待依赖
2. **解决策略**：
   - 强制完成某些低优先级任务
   - 重新规划任务依赖关系
   - 临时增加并行限制（需谨慎）

## 📈 性能优化

### 任务分发效率指标
1. **响应时间**：从任务接收到委派的时间
2. **匹配准确率**：任务分配给最合适智能体的比例
3. **资源利用率**：智能体工作负载均衡程度
4. **任务完成率**：按时完成的任务比例

### 优化策略
1. **智能体画像**：建立各智能体的能力画像
2. **历史学习**：基于历史任务完成情况优化匹配
3. **动态调整**：根据项目阶段调整并行限制
4. **预测分析**：预测任务流量，提前准备资源

## 🔄 与协调智能体的协作

### 分工界限
- **主智能体**：任务分发、智能体匹配、并行管理
- **协调智能体**：进度跟踪、冲突解决、文档整合、代码审查

### 协作接口
1. **任务交接**：主智能体分配任务后通知协调智能体
2. **状态同步**：定期同步任务状态和智能体状态
3. **问题上报**：智能体问题通过协调智能体上报
4. **资源协调**：协调智能体提供资源支持信息

### 通信协议
```yaml
任务分配通知:
  from: 主智能体
  to: 协调智能体
  content: 任务ID, 执行智能体, 预期完成时间
  action: 开始进度跟踪

状态更新通知:
  from: 协调智能体
  to: 主智能体
  content: 任务状态变化, 阻塞信息
  action: 更新任务状态

资源请求通知:
  from: 协调智能体
  to: 主智能体
  content: 资源需求, 紧急程度
  action: 调整任务分配
```

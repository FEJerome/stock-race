# 通用智能体角色定义

## 📋 概述

本文档定义了多智能体协同开发中的6个通用功能型角色。每个智能体基于技术功能而非业务领域进行划分，拥有独立的工作空间，通过git-worktree实现并行开发。本模板不与任何具体业务耦合，适用于各种类型的软件开发项目。

## 👥 核心角色列表

### 1. 架构设计智能体 (Architecture Agent)
**职责范围**：
- 系统架构设计和技术选型
- 接口定义和模块划分
- 技术评估和方案设计
- 架构文档和维护

**工作空间**：`worktrees/worktree-architecture`
**分支命名**：`feature/architecture-功能名`

### 2. 核心逻辑智能体 (Core Logic Agent)
**职责范围**：
- 核心业务逻辑实现
- 算法开发和优化
- 数据处理和转换
- 业务规则引擎

**工作空间**：`worktrees/worktree-core-logic`
**分支命名**：`feature/core-logic-功能名`

### 3. 接口服务智能体 (Interface Service Agent)
**职责范围**：
- API接口开发和服务层实现
- 外部系统集成和适配
- 数据格式转换和验证
- 服务间通信机制

**工作空间**：`worktrees/worktree-interface-service`
**分支命名**：`feature/interface-service-功能名`

### 4. 用户界面智能体 (User Interface Agent)
**职责范围**：
- UI组件开发和用户体验设计
- 前端逻辑和状态管理
- 响应式设计和交互实现
- 前端框架集成和优化

**工作空间**：`worktrees/worktree-user-interface`
**分支命名**：`feature/user-interface-功能名`

### 5. 基础设施智能体 (Infrastructure Agent)
**职责范围**：
- 工具类开发和配置管理
- 构建部署和CI/CD流水线
- 开发环境配置和优化
- 监控日志和性能工具

**工作空间**：`worktrees/worktree-infrastructure`
**分支命名**：`feature/infrastructure-功能名`

### 6. 协调管理智能体 (Coordination Agent)
**职责范围**：
- 进度跟踪和状态管理
- 冲突解决和依赖协调
- 文档整合和知识管理
- 代码审查和合并协调
- 与主智能体协作进行任务协调

**工作空间**：`worktrees/worktree-coordination`
**分支命名**：`feature/coordination-功能名`

## 🎯 角色分工原则

### 模块隔离原则
1. **功能隔离**：每个智能体负责特定的技术功能领域
2. **文档隔离**：每个智能体维护自己领域的文档
3. **接口定义**：功能模块间通过明确定义的接口通信
4. **依赖管理**：跨功能依赖需记录在协调文档中

### 协调机制
1. **任务分发**：主智能体负责任务分析和分配
2. **进度同步**：各智能体定期更新工作状态
3. **冲突解决**：接口变更需提前协调
4. **合并审核**：协调智能体审核各模块的合并请求

## 🔧 技术规范

### Git工作流
1. **分支策略**：
   ```bash
   # 从main分支创建feature分支
   git checkout main
   git pull origin main
   git checkout -b feature/architecture-系统设计
   ```

2. **提交规范**：
   ```
   feat(architecture): 添加系统架构设计
   fix(core-logic): 修复业务逻辑漏洞
   docs(ui): 更新组件使用文档
   ```

3. **合并流程**：
   - 本地测试通过后提交到远程
   - 创建Pull Request（或协调智能体手动合并）
   - 协调智能体审核并运行集成测试
   - 合并到main分支

### 文档更新规范
1. **状态更新**：完成任务后更新状态（pending → in_progress → completed）
2. **进度报告**：定期更新工作进度
3. **问题记录**：遇到问题及时记录
4. **依赖变更**：影响其他功能模块的变更需记录

## 📊 权限边界

### 允许的操作
- 修改自己负责的功能领域代码
- 更新自己领域的文档
- 在自己的worktree中创建分支
- 提交代码到自己的分支

### 禁止的操作
- 直接修改其他智能体的代码
- 修改其他智能体的文档（可阅读）
- 直接合并到main分支
- 修改协调智能体的核心协调文档

### 需要协调的操作
- 修改跨功能模块的接口定义
- 添加影响其他模块的新功能
- 重大架构变更
- 生产环境部署

## 🚀 快速开始

### 新智能体加入流程
1. 阅读本文档和相关协作文档
2. 配置git-worktree工作空间
3. 了解负责功能领域的现有架构
4. 从分配的任务开始实施
5. 定期与协调智能体同步进度

### 日常开发流程
```
1. 进入worktree工作空间
2. 拉取最新main分支代码
3. 创建feature分支
4. 开发并测试功能
5. 更新文档状态
6. 提交代码并通知协调智能体
```

## 📞 沟通协调

### 问题上报
1. **技术问题**：记录在相应文档中，标记为"阻塞"
2. **依赖问题**：更新协调文档中的依赖记录
3. **进度问题**：在定期进度更新中说明

### 协调机制
- **定期同步**：通过文档更新进行状态同步
- **接口评审**：协调智能体组织模块间接口评审
- **紧急问题**：立即通知协调智能体

## 🔄 与项目模板协调

### 与主智能体的关系
- **主智能体**：纯任务分发，负责任务分析和分配
- **协调智能体**：具体协调执行，处理进度跟踪、冲突解决
- **功能智能体**：具体功能实现，负责各自技术领域

### 项目模板适配
- 本文档作为通用模板，可根据具体项目需求调整角色定义
- 智能体数量可配置，但建议保持6个核心功能角色
- 工作空间路径可根据项目结构调整

# 产出物管理规范

**制定日期**：2026-02-06
**版本**：1.0.0
**维护者**：首席架构师

## 📋 概述

本规范定义了stock-race项目中所有开发、测试和文档工作的产出物管理流程。遵循"规范存储、更新日志、规范留痕"三大原则，确保产出物可追溯、可复用、可协作。

## 🎯 管理原则

### 1. 规范存储
所有产出物必须按照项目规范分门别类存储到对应目录：

| 产出物类型 | 存储位置 | 文件命名规范 |
|------------|----------|--------------|
| **代码文件** | 对应模块目录（frontend/, backend/, ai-service/, data-service/） | 遵循CODING_STANDARDS.md命名约定 |
| **配置脚本** | .claude/scripts/ 相关子目录 | 描述性名称，如session-cleanup.js |
| **测试脚本** | tests/ 对应子目录 | test_前缀 + 功能描述，如test_api_integration.js |
| **文档文件** | docs/ 对应分类目录 | 大写标题 + 功能描述，如MEMORY_OPTIMIZATION.md |
| **进度报告** | 对应模块根目录 或 docs/testing/ | 模块名 + 报告类型，如BACKEND_OPTIMIZATION_PROGRESS.md |
| **验证报告** | docs/testing/ | 功能描述 + 报告类型，如VALIDATION_HISTORY.md |

### 2. 更新日志
任何产出物创建或修改后，必须更新相关日志：

| 日志类型 | 位置 | 更新要求 |
|----------|------|----------|
| **模块进度** | 模块根目录的进度文档 | 添加时间戳、变更描述、负责人 |
| **测试记录** | docs/testing/VALIDATION_HISTORY.md | 记录测试时间、结果、问题 |
| **智能体状态** | docs/agents/AGENT_STATUS.md | 更新任务状态、进度百分比 |
| **协调主控** | docs/coordination/COORDINATION_MASTER.md | 更新开发阶段、任务分配状态 |
| **变更摘要** | docs/ 根目录的变更摘要文档 | 汇总重大变更及其影响 |

### 3. 规范留痕
所有产出物必须在相关文档中清晰留痕：

| 留痕类型 | 位置 | 内容要求 |
|----------|------|----------|
| **API变更** | docs/architecture/API_SPECIFICATION.md | 记录接口变更、版本、影响范围 |
| **数据库变更** | docs/architecture/DATABASE_DESIGN.md | 记录表结构变更、迁移脚本 |
| **架构变更** | docs/architecture/SYSTEM_ARCHITECTURE.md | 记录架构调整、组件增减 |
| **部署变更** | docs/deployment/DEPLOYMENT_GUIDE.md | 记录部署配置、环境变量变更 |
| **测试结果** | 对应的测试报告文档 | 记录测试时间、环境、结果、问题 |

## 📁 产出物分类体系

### A. 代码类产出物
1. **功能代码**：业务逻辑实现
2. **工具脚本**：构建、部署、分析脚本
3. **配置代码**：环境配置、服务配置
4. **测试代码**：单元测试、集成测试、E2E测试

### B. 文档类产出物
1. **需求文档**：功能规格、接口定义
2. **设计文档**：架构设计、数据库设计
3. **实现文档**：模块说明、API文档
4. **测试文档**：测试计划、测试报告
5. **部署文档**：部署指南、运维手册
6. **用户文档**：使用指南、故障排除

### C. 数据类产出物
1. **数据库脚本**：DDL、DML、迁移脚本
2. **配置文件**：环境变量、应用配置
3. **测试数据**：测试用例、模拟数据
4. **监控数据**：性能指标、日志分析

### D. 报告类产出物
1. **进度报告**：开发进度、任务完成情况
2. **质量报告**：代码质量、测试覆盖率
3. **性能报告**：性能测试结果、优化建议
4. **安全报告**：安全扫描结果、漏洞修复

## 🔄 管理流程

### 1. 产出物创建流程
```
需求/任务 → 开发/编写 → 产出物生成 → 分类存储 → 日志更新 → 文档留痕
```

### 2. 产出物更新流程
```
变更需求 → 产出物修改 → 版本控制 → 影响评估 → 相关文档更新
```

### 3. 产出物审核流程
```
产出物完成 → 自检验证 → 相关智能体审核 → 协调智能体确认 → 归档存储
```

## 🚨 违规处理

### 轻度违规
- 产出物存储位置不正确
- 文档更新不及时
- 留痕信息不完整

**处理措施**：限期整改，记录违规

### 中度违规
- 产出物与任务无关联
- 关键文档缺失
- 测试验证未完成

**处理措施**：暂停相关任务，整改完成后恢复

### 严重违规
- 产出物功能缺失
- 文档与代码严重不符
- 未经审核发布产出物

**处理措施**：撤回产出物，重新开发，责任人记录

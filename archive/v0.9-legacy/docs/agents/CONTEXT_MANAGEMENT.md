# 上下文管理策略

## 📋 文档简介

本文件详细说明多智能体系统的 **上下文管理策略**，旨在解决 DeepSeek 模型 100k 上下文容量限制的问题。通过主动进行 compact 操作，优化上下文使用，避免超限风险。

**目标**：在保证系统功能完整性的前提下，最大化利用上下文容量，确保智能体间高效协作。

## 🎯 核心策略

### 1. 上下文容量规划

| 模型 | 总容量 | 安全阈值 | 压缩触发点 | 最大使用限制 |
|------|--------|----------|------------|--------------|
| DeepSeek | 100k | 80k | 70k | 90k |

### 2. 主智能体命令

```
# 上下文管理策略
1. 当任务描述超过 5k tokens 时，自动触发 compact 操作
2. 当会话历史超过 80k tokens 时，主动进行上下文压缩
3. 每个子任务完成后，对相关上下文进行选择性保留
4. 优先保留核心决策和技术方案，压缩具体实现细节
5. 建立上下文分层机制：核心层（必须保留）、功能层（按需保留）、细节层（可压缩）
```

### 3. 子智能体命令

```
# 子智能体上下文管理
1. 子智能体启动时，仅携带与当前任务相关的最小上下文
2. 子任务完成后，返回压缩后的结果摘要（限制在 2k tokens 内）
3. 当子智能体内部上下文超过 60k tokens 时，主动触发 compact
4. 优先保留与当前任务直接相关的信息，压缩历史交互
5. 提供标准化的结果格式，便于主智能体快速整合
```

### 4. 任务委派策略

```
# 任务委派优化
1. 大型任务（预计超过 10k tokens）必须委派给子智能体
2. 委派时提供明确的任务边界和上下文范围
3. 为子智能体设置最大上下文使用限制（如 70k tokens）
4. 子智能体完成后，主智能体只保留结果摘要，释放原始上下文
```

## 🔧 实施方法

### 1. 上下文压缩钩子

| 钩子类型 | 触发条件 | 操作内容 | 负责智能体 |
|----------|----------|----------|------------|
| **启动钩子** | 智能体启动时上下文 > 50k | 压缩历史上下文 | 所有智能体 |
| **任务完成钩子** | 子任务完成后 | 压缩结果为摘要 | 子智能体 |
| **周期性钩子** | 每 10 轮交互后 | 检查并压缩上下文 | 所有智能体 |
| **内存预警钩子** | 上下文使用 > 80% | 主动触发压缩 | 所有智能体 |

### 2. 上下文分层实现

#### 核心层（必须保留）
- 项目架构和技术栈
- 核心决策和技术方案
- 关键接口定义和数据结构
- 当前任务的目标和范围

#### 功能层（按需保留）
- 与当前任务相关的功能模块
- 已完成任务的结果摘要
- 待处理任务的详细要求
- 依赖关系和约束条件

#### 细节层（可压缩）
- 具体实现代码
- 调试信息和日志
- 历史交互记录
- 与当前任务无关的信息

### 3. 压缩策略

#### 摘要压缩
- 将长文本总结为关键要点（保留 10-20% 的核心信息）
- 使用列表格式呈现重要信息
- 移除冗余描述和重复内容

#### 分层保留
- 核心层：完整保留
- 功能层：保留与当前任务相关的部分
- 细节层：压缩为摘要或清理

#### 历史清理
- 清理与当前任务无关的历史交互
- 保留历史任务的结果摘要，移除过程细节
- 定期清理过期的上下文信息

#### 代码压缩
- 只保留关键代码片段和函数签名
- 移除注释、空行和调试代码
- 使用代码摘要描述实现逻辑

## 📊 任务委派优化

### 1. 任务大小评估

| 任务类型 | 预计大小 | 处理策略 |
|----------|----------|----------|
| 小型任务 | < 5k | 主智能体直接处理 |
| 中型任务 | 5k-10k | 主智能体处理或委派 |
| 大型任务 | > 10k | 必须委派给子智能体 |
| 超大型任务 | > 20k | 拆分为多个子任务委派 |

### 2. 委派上下文范围

```markdown
# 子任务委派模板

## 任务目标
[简明描述任务目标]

## 上下文范围
- **必须包含**：[核心上下文信息]
- **可选包含**：[辅助上下文信息]
- **排除**：[不需要的上下文信息]

## 任务边界
- **输入**：[子智能体需要的输入]
- **输出**：[子智能体需要返回的结果格式]
- **限制**：[时间、资源或其他限制]

## 评估标准
- **成功指标**：[任务成功的衡量标准]
- **验收标准**：[结果验收的具体要求]
```

### 3. 结果整合流程

1. **子智能体返回**：压缩后的结果摘要（限制在 2k tokens 内）
2. **主智能体处理**：
   - 验证结果是否符合要求
   - 将结果整合到主上下文
   - 清理与该子任务相关的临时上下文
3. **上下文更新**：只保留结果摘要，释放原始上下文

## 📈 实施效果

### 预期收益
1. **上下文使用更高效**：通过主动压缩，减少无效上下文占用
2. **避免超限风险**：在接近阈值前主动压缩，预防上下文超限
3. **任务委派更合理**：大型任务自动委派给子智能体，分散上下文压力
4. **信息传递更精准**：子智能体返回压缩后的结果摘要，减少信息冗余
5. **系统响应更迅速**：减少上下文大小，提高模型处理速度

### 监控指标

| 指标 | 目标值 | 监控频率 |
|------|--------|----------|
| 主智能体上下文大小 | < 80k | 每轮交互 |
| 子智能体上下文大小 | < 60k | 每轮交互 |
| 压缩率 | > 50% | 每日 |
| 上下文超限率 | < 1% | 每日 |
| 任务完成时间 | 符合预期 | 每次任务 |

## 🔄 持续优化

### 1. 策略评估

- **每周评估**：协调智能体每周评估上下文管理策略的有效性
- **数据收集**：收集上下文使用情况、压缩率、超限率等数据
- **策略调整**：根据数据反馈持续优化上下文管理策略

### 2. 最佳实践

- **设置合理的阈值**：根据实际使用情况调整压缩触发点
- **优化压缩算法**：不断改进摘要生成质量，提高压缩效率
- **平衡信息完整性**：在压缩上下文的同时，确保关键信息不丢失
- **标准化结果格式**：统一子智能体返回格式，便于主智能体快速处理
- **定期清理上下文**：建立上下文生命周期管理机制

## 📌 注意事项

- **信息安全**：压缩过程中确保敏感信息不泄露
- **功能完整性**：压缩上下文时确保系统功能不受影响
- **协作效率**：上下文管理策略应提高而非降低协作效率
- **适应性**：根据任务类型和复杂度调整上下文管理策略
- **可扩展性**：为未来模型容量变化预留调整空间

## 🚀 快速参考

### 压缩触发条件
- 主智能体：任务描述 > 5k tokens 或会话历史 > 80k tokens
- 子智能体：内部上下文 > 60k tokens 或任务完成后

### 压缩优先级
1. 历史交互记录
2. 具体实现细节
3. 调试信息和日志
4. 与当前任务无关的信息

### 保留优先级
1. 核心决策和技术方案
2. 关键接口定义和数据结构
3. 当前任务的目标和范围
4. 与当前任务相关的功能模块

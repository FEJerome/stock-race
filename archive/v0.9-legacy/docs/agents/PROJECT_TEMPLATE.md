# 多智能体协作项目模板配置指南

## 🎯 概述

本文档提供通用多智能体协作项目模板的配置和使用指南。本模板不与任何具体业务耦合，适用于各种类型的软件开发项目，提供标准化的多智能体协作框架。

## 🏗️ 模板核心特性

### 1. 通用性设计
- **不与业务耦合**：智能体角色基于技术功能而非业务领域
- **可配置性**：所有参数可根据项目需求调整
- **可扩展性**：支持自定义智能体角色和协作流程

### 2. 智能体架构
- **6个通用功能型智能体**：架构设计、核心逻辑、接口服务、用户界面、基础设施、协调管理
- **纯任务分发主智能体**：只负责任务分析和分配，不参与具体执行
- **并行限制管理**：最多4个智能体并行执行

### 3. 技术支持
- **git-worktree集成**：每个智能体独立工作空间
- **标准化协作流程**：明确的状态管理和协调机制
- **完整文档体系**：涵盖角色定义、协作方案、工作流指南等

## 🚀 快速启动指南

### 第一步：环境准备
1. **项目初始化**：
   ```bash
   # 克隆项目模板或创建新项目
   git clone <template-repository> your-project
   cd your-project
   ```

2. **依赖安装**：
   ```bash
   # 根据项目技术栈安装依赖
   # 例如：npm install, pip install, etc.
   ```

### 第二步：智能体配置
1. **角色自定义**（可选）：
   - 编辑 `docs/agents/GENERIC_ROLES.md` 调整角色定义
   - 根据项目需求修改智能体职责和工作目录

2. **工作空间配置**：
   ```bash
   # 运行worktree配置脚本
   chmod +x scripts/setup-worktrees.sh
   ./scripts/setup-worktrees.sh
   ```

3. **状态管理初始化**：
   - 更新 `docs/agents/GENERIC_AGENT_STATUS.md` 中的智能体状态
   - 配置项目特定的依赖关系

### 第三步：协作流程配置
1. **任务分发配置**：
   - 配置主智能体的任务分析规则
   - 更新 `docs/agents/TASK_DISPATCH_GUIDE.md` 中的匹配算法

2. **并行限制调整**：
   - 根据团队规模调整并行限制（默认4个）
   - 更新相关文档中的并行限制参数

3. **汇报机制设置**：
   - 配置阶段性汇报频率和格式
   - 设置进度跟踪文档模板

## 📁 项目结构配置

### 标准目录结构
```
your-project/
├── docs/agents/                    # 智能体相关文档
│   ├── GENERIC_ROLES.md            # 通用角色定义
│   ├── GENERIC_COLLABORATION_PLAN.md # 通用协作方案
│   ├── GENERIC_WORKTREE_GUIDE.md   # 通用worktree配置
│   ├── GENERIC_AGENT_STATUS.md     # 通用状态管理
│   ├── TASK_DISPATCH_GUIDE.md      # 任务分发指南
│   └── PROJECT_TEMPLATE.md         # 项目模板配置（本文档）
├── worktrees/                      # git-worktree工作空间
│   ├── worktree-architecture/      # 架构设计智能体
│   ├── worktree-core-logic/        # 核心逻辑智能体
│   ├── worktree-interface-service/ # 接口服务智能体
│   ├── worktree-user-interface/    # 用户界面智能体
│   ├── worktree-infrastructure/    # 基础设施智能体
│   └── worktree-coordination/      # 协调管理智能体
├── src/                            # 源代码目录（示例结构）
│   ├── core/                       # 核心逻辑
│   ├── services/                   # 接口服务
│   ├── ui/                         # 用户界面
│   └── utils/                      # 基础设施工具
├── config/                         # 配置文件
├── scripts/                        # 工具脚本
└── CLAUDE.md                       # 项目主文档
```

### 目录自定义指南
1. **源代码结构**：根据技术栈调整src目录结构
2. **文档结构**：保持docs/agents结构，可添加项目特定文档
3. **工作空间**：worktrees目录结构应与角色定义一致
4. **配置文件**：将项目特定配置放在config目录

## 🔧 智能体角色自定义

### 1. 修改角色定义
编辑 `docs/agents/GENERIC_ROLES.md`：

```markdown
### 自定义智能体角色
**职责范围**：
- [根据项目需求定义职责]
- [添加特定技术栈要求]
- [定义项目特有的工作流程]

**工作空间**：`worktrees/worktree-自定义名称`
**分支命名**：`feature/自定义缩写-功能名`
```

### 2. 调整智能体数量
- **增加智能体**：在相关文档中添加新角色定义
- **减少智能体**：合并相关职责，更新依赖关系
- **重命名智能体**：全局替换角色名称

### 3. 配置技术栈
- **架构智能体**：配置项目使用的技术栈和架构模式
- **开发规范**：定义代码规范、测试策略、部署流程
- **工具链**：配置开发工具、构建工具、监控工具

## ⚙️ 协作流程自定义

### 1. 任务分发规则
编辑 `docs/agents/TASK_DISPATCH_GUIDE.md`：

```yaml
# 自定义匹配规则
匹配规则:
  - 任务类型: "数据分析"
    首选智能体: "核心逻辑智能体"
    匹配权重:
      算法需求: 0.6
      数据处理: 0.4
  - 任务类型: "用户界面"
    首选智能体: "用户界面智能体"
    匹配权重:
      UI设计: 0.5
      交互逻辑: 0.3
      性能优化: 0.2
```

### 2. 并行限制调整
编辑相关文档中的并行限制参数：

```bash
# 调整并行限制（默认4）
MAX_PARALLEL_AGENTS=6  # 根据团队规模调整
MONITOR_INTERVAL=60    # 监控频率（秒）
```

### 3. 汇报机制定制
- **汇报频率**：调整每日/每周汇报时间
- **汇报格式**：自定义汇报文档模板
- **汇报内容**：定义必须包含的进度指标

## 🛠️ 工具脚本配置

### 1. 初始化脚本
创建 `scripts/init-project.sh`：

```bash
#!/bin/bash
# 项目初始化脚本

echo "初始化多智能体协作项目..."

# 1. 创建目录结构
mkdir -p src/{core,services,ui,utils}
mkdir -p config scripts worktrees

# 2. 配置git-worktree
./scripts/setup-worktrees.sh

# 3. 初始化文档
cp -r docs/templates/* docs/

# 4. 安装依赖
# [根据技术栈安装依赖]

echo "项目初始化完成！"
```

### 2. 智能体启动脚本
创建 `scripts/start-agent.sh`：

```bash
#!/bin/bash
# 智能体启动脚本

AGENT_TYPE=$1
TASK_ID=$2

# 根据智能体类型执行不同的启动逻辑
case $AGENT_TYPE in
  "architecture")
    cd worktrees/worktree-architecture
    # 架构设计智能体启动逻辑
    ;;
  "core-logic")
    cd worktrees/worktree-core-logic
    # 核心逻辑智能体启动逻辑
    ;;
  # ... 其他智能体
esac

echo "智能体 $AGENT_TYPE 启动完成，任务ID: $TASK_ID"
```

### 3. 状态监控脚本
创建 `scripts/monitor-agents.sh`：

```bash
#!/bin/bash
# 智能体状态监控脚本

while true; do
  # 检查运行中的智能体数量
  RUNNING_COUNT=$(check_running_agents)

  # 检查系统负载
  SYSTEM_LOAD=$(check_system_load)

  # 动态调整并行限制
  adjust_parallel_limit $RUNNING_COUNT $SYSTEM_LOAD

  # 生成状态报告
  generate_status_report

  sleep 30
done
```

## 🔄 模板使用工作流

### 新项目启动流程
1. **项目初始化**：使用模板创建新项目
2. **角色配置**：根据项目需求调整智能体角色
3. **环境搭建**：配置开发环境和工具链
4. **流程定制**：调整协作流程和规则
5. **团队培训**：介绍多智能体协作机制

### 日常开发流程
1. **任务接收**：主智能体接收新任务
2. **任务分析**：分析任务需求和复杂度
3. **智能体分配**：匹配并分配给合适智能体
4. **并行检查**：确保不超过并行限制
5. **任务执行**：智能体在独立工作空间开发
6. **进度跟踪**：协调智能体监控执行状态
7. **代码审查**：完成开发后进行代码审查
8. **合并部署**：通过审查后合并到主分支

### 项目管理流程
1. **进度监控**：定期检查项目进度
2. **风险管理**：识别和解决项目风险
3. **资源调整**：根据需求调整智能体分配
4. **流程优化**：持续改进协作流程
5. **知识沉淀**：积累最佳实践和经验

## ⚠️ 常见问题与解决方案

### 1. 智能体负载不均衡
**问题**：某些智能体任务过多，某些空闲
**解决方案**：
- 调整任务匹配算法权重
- 重新定义智能体职责范围
- 增加智能体间的协作机制

### 2. 并行限制过于严格
**问题**：智能体经常需要等待
**解决方案**：
- 增加并行限制数量
- 优化任务分解策略
- 调整依赖关系管理

### 3. 状态管理复杂
**问题**：状态更新不及时或不一致
**解决方案**：
- 自动化状态更新机制
- 增加状态验证检查
- 简化状态类型定义

### 4. 文档维护负担重
**问题**：文档更新成为负担
**解决方案**：
- 自动化文档生成
- 简化文档更新流程
- 建立文档审查机制

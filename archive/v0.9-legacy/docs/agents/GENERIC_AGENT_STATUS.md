# 通用智能体状态管理

## 📋 文档简介

本文件用于管理和监控通用智能体的运行状态，确保并行执行的智能体数量不超过四个。协调管理智能体将通过此文件跟踪各智能体的状态变化，并据此决定是否启动新的智能体。

**目标**：提供一个集中式的智能体状态管理机制，确保系统在性能限制范围内高效运行。本模板不与任何具体业务耦合，适用于各种类型的多智能体协作项目。

## 🎯 智能体状态定义

### 状态类型

| 状态 | 描述 | 操作 |
|------|------|------|
| `pending` | 智能体等待启动 | 协调智能体可根据并行限制决定是否启动 |
| `starting` | 智能体正在启动 | 启动过程中，不计入并行数量 |
| `running` | 智能体正在运行 | 计入并行数量限制 |
| `paused` | 智能体暂停运行 | 不计入并行数量，但保留资源 |
| `completed` | 智能体任务完成 | 不计入并行数量，可启动等待中的智能体 |
| `failed` | 智能体运行失败 | 不计入并行数量，可启动等待中的智能体 |
| `blocked` | 智能体被阻塞 | 不计入并行数量，等待依赖解决 |

| 智能体名称 | 当前状态 | 启动时间 | 预计完成时间 | 依赖智能体 |
|------------|----------|----------|--------------|------------|
| 架构设计智能体 | pending | {日期} | {日期} | - |
| 核心逻辑智能体 | pending | {日期} | {日期} | 架构设计智能体 |
| 接口服务智能体 | pending | {日期} | {日期} | 架构设计智能体 |
| 用户界面智能体 | pending | {日期} | {日期} | 核心逻辑智能体 |
| 基础设施智能体 | pending | {日期} | {日期} | - |
| 协调管理智能体 | running | {日期} | 持续 | - |

## 🔧 状态管理机制

### 1. 启动流程

1. **智能体启动前检查**：
   - 协调管理智能体检查当前 `running` 状态的智能体数量
   - 如果数量 < 4，且智能体的依赖已满足，则启动智能体
   - 如果数量 >= 4，或依赖未满足，则保持 `pending` 状态

2. **状态更新流程**：
   - 智能体启动：从 `pending` → `starting` → `running`
   - 智能体完成：从 `running` → `completed`
   - 智能体失败：从 `running` → `failed`
   - 智能体阻塞：从 `running` → `blocked`

3. **并行数量监控**：
   - 协调管理智能体定期检查运行中的智能体数量
   - 当运行中的智能体数量 < 4 时，检查是否有可启动的 `pending` 智能体
   - 优先启动依赖已满足且优先级高的智能体

### 2. 协调管理智能体职责

1. **状态监控**：
   - 定期检查 `GENERIC_AGENT_STATUS.md` 文件中的智能体状态
   - 跟踪运行中的智能体数量，确保不超过并行限制

2. **智能体启动决策**：
   - 当运行中的智能体数量 < 4 时，启动等待中的智能体
   - 遵循依赖关系，确保智能体在依赖满足后启动
   - 考虑智能体优先级，优先启动高优先级任务

3. **状态更新**：
   - 接收智能体的状态更新通知
   - 及时更新 `GENERIC_AGENT_STATUS.md` 文件中的状态信息
   - 当智能体状态变更时，重新评估启动策略

4. **紧急情况处理**：
   - 处理智能体崩溃或无响应的情况
   - 重新分配任务，确保项目进度不受影响
   - 调整启动策略，应对突发情况

## 📊 启动策略

### 1. 初始启动顺序示例

1. **第一轮启动**（4个智能体）：
   - 协调管理智能体
   - 架构设计智能体
   - 核心逻辑智能体
   - 基础设施智能体

2. **第二轮启动**（等待第一轮完成后）：
   - 接口服务智能体（依赖架构设计智能体）
   - 用户界面智能体（依赖核心逻辑智能体）

### 2. 动态启动策略

1. **智能体完成时**：
   - 当任何智能体完成任务时，协调智能体检查是否有等待中的智能体
   - 优先启动依赖已满足的智能体

2. **依赖满足时**：
   - 当智能体的依赖条件满足时，协调智能体将其标记为可启动状态
   - 当并行数量允许时，立即启动该智能体

3. **优先级考虑**：
   - 高优先级：架构设计、核心依赖模块
   - 中优先级：接口服务、用户界面
   - 低优先级：工具优化、文档完善

## 🔄 与主智能体的协作

### 分工界限
- **主智能体**：纯任务分发，负责任务分析和分配
- **协调管理智能体**：状态管理、进度跟踪、冲突解决
- **功能智能体**：具体功能实现

### 协作流程
1. **任务接收**：主智能体接收任务并进行分析
2. **任务分配**：主智能体将任务分配给合适的智能体
3. **状态更新**：协调智能体更新智能体状态
4. **进度跟踪**：协调智能体跟踪任务执行进度
5. **完成通知**：功能智能体完成任务后通知协调智能体

## 📌 注意事项

- **状态一致性**：确保 `GENERIC_AGENT_STATUS.md` 文件的状态与实际情况一致
- **并发安全**：处理多个智能体同时更新状态的情况
- **错误处理**：考虑智能体崩溃或无响应的情况
- **性能监控**：定期检查系统性能，根据实际情况调整并行数量
- **可扩展性**：设计时考虑未来可能的智能体数量增加
- **模板通用性**：保持文档的通用性，不与具体业务耦合

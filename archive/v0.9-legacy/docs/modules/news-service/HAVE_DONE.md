## 二、架构实现详情

### 2.1 精简情报架构

```
┌─────────────────────────────────────────────────────────────┐
│                    News Service 数据流架构                    │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  采集层（流式采集，不存储原始数据）                             │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐    │
│  │ 新浪财经  │  │ 东方财富  │  │ 微博舆情  │  │ 投资论坛  │    │
│  │ 财经新闻  │  │ 财经新闻  │  │ 流式监听  │  │ RSS聚合  │    │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘  └────┬─────┘    │
│       │             │             │             │           │
│       └─────────────┴──────┬──────┴─────────────┘           │
│                            │                                 │
│                            ▼                                 │
│                   ┌─────────────────┐                        │
│                   │  Redis Stream   │  ← 原始数据流（TTL 1h） │
│                   │   (news:raw)    │                        │
│                   └────────┬────────┘                        │
│                            │                                 │
│  处理层（DeepSeek流水线）      ▼                               │
│  ┌─────────────────────────────────────────────────────────┐│
│  │              DeepSeek 实时处理引擎                       ││
│  │                                                         ││
│  │  输入：原始新闻文本（< 300字，控制token）                  ││
│  │       ↓                                                 ││
│  │  处理：                                                 ││
│  │    1. 实体识别（股票代码、板块、概念）                     ││
│  │    2. 情感分析（正/负/中性，置信度）                       ││
│  │    3. 重要性评分（1-10，是否突发）                         ││
│  │    4. 摘要提炼（50字以内核心信息）                         ││
│  │    5. 关联度评分（与A股相关度 0-1）                        ││
│  │       ↓                                                 ││
│  │  输出：结构化情报JSON（< 500字节）                        ││
│  │                                                         ││
│  └─────────────────────────────────────────────────────────┘│
│                            │                                 │
│  过滤层（控制Token质量）       ▼                               │
│  ┌─────────────────────────────────────────────────────────┐│
│  │              过滤规则                                    ││
│  │                                                         ││
│  │  • 关联度 < 0.6 → 丢弃                                   ││
│  │  • 情感置信度 < 0.7 → 丢弃（可选）                        ││
│  │  • 重复新闻（相似度>0.9）→ 去重                          ││
│  │  • 无股票代码 → 丢弃                                     ││
│  │                                                         ││
│  └─────────────────────────────────────────────────────────┘│
│                            │                                 │
│  存储层（精简存储）            ▼                               │
│  ┌─────────────────────────┐  ┌─────────────────────────┐   │
│  │ Redis（热数据，24h）      │  │ PostgreSQL（温数据，7d） │   │
│  │ intelligence:{code}     │  │ stock_intelligence      │   │
│  │ • 股票代码               │  │ • 股票代码               │   │
│  │ • 情感标签               │  │ • 情感分数               │   │
│  │ • 摘要（50字）           │  │ • 摘要（100字符限制）     │   │
│  │ • 时间戳                 │  │ • 重要性                 │   │
│  │ • 来源                   │  │ • 关联板块               │   │
│  │ • 关联度评分             │  │ • 来源、过期时间          │   │
│  └─────────────────────────┘  └─────────────────────────┘   │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

**存储空间对比**：
- 原始新闻存储：25MB/天 × 3.5 = 87.5MB/天（ES方案）
- 结构化情报：500字节 × 3000条 = 1.5MB/天（本方案）
- **节省：98% 存储空间**

### 2.2 Token控制策略

| 项目 | 预算 | 实际控制 | 状态 |
|------|------|---------|------|
| 单条新闻处理 | 2000 tokens | 输入1500 + 输出500 | ✅ 符合 |
| Prompt长度 | 1500 tokens | 内容截断至300字 | ✅ 符合 |
| 输出长度 | 500 tokens | JSON结构化输出 | ✅ 符合 |
| 每日总预算 | 6M tokens | 3000条 × 2000 tokens | ✅ 符合 |
| 单股票查询返回 | 150-200 tokens/条 | 最多10条 | ✅ 符合 |

### 2.3 数据生命周期

| 阶段 | 存储 | 内容 | TTL | 用途 |
|------|------|------|-----|------|
| **原始** | Redis Stream | 完整新闻文本 | 1小时 | 临时缓冲，给DeepSeek处理 |
| **热数据** | Redis List | 结构化情报（500字节） | 24小时 | AI实时决策 |
| **温数据** | PostgreSQL | 浓缩情报（100字节） | 7天 | 趋势分析、复盘 |
| **冷数据** | 不存储 | - | - | 不保留，降低成本 |

| 文档完整 | 88/100 | TODO.md详细，但缺少TEST_SCRIPTS.md |

### 3.2 核心优势

1. **精简架构实现优秀**
   - 采用DeepSeek流式处理，不存储原始新闻
   - 结构化情报控制在500字节以内
   - 相比ES方案节省98%存储空间

2. **Token控制严格**
   - 内容自动截断至300字（约450 tokens）
   - Prompt工程优化，输出严格JSON格式
   - 批量处理支持并发控制（默认5并发）

3. **降级机制完善**
   - Redis失败 → 直接查PostgreSQL
   - PostgreSQL失败 → 返回空数据（不阻塞）
   - DeepSeek失败 → 3次重试后丢弃

4. **分层存储符合设计**
   - 热数据：Redis 24h TTL
   - 温数据：PostgreSQL 7d TTL + 自动清理
   - 冷数据：不存储（与架构设计一致）

5. **采集器设计规范**
   - 抽象基类设计，易于扩展新数据源
   - 统计信息收集（成功率、延迟）
   - 速率限制控制（防反爬）

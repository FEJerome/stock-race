## 3. 分层采集可行性评估

### 3.1 中频层 (10秒延迟/300只)

**当前能力**:
```
新浪: 5只/0.34s = 14.7只/秒
300只需要: 300/14.7 = 20.4秒 ✗

优化方案:
- 新浪批量上限实际为100只
- 100只/0.5s = 200只/秒
- 300只需要: 3次请求 × 0.5s = 1.5s ✓
```

**结论**: ✓ **可行** - 使用新浪财经批量接口，10秒内可完成300只

### 3.2 低频层 (60秒延迟/全量5000只)

**当前能力**:
```
新浪: 100只/0.5s = 200只/秒
5000只需要: 50次请求 × 0.5s = 25秒 (串行)

6源并行方案:
- 新浪: 2000只 (20次请求)
- 腾讯: 1000只 (单股，需修复批量)
- 东方: 1000只 (单股，需修复批量)
- AkShare: 500只 (需优化响应时间)
- Baostock: 300只 (需修复代码)
- Tushare: 200只 (需配置token)

并行后预计: 25-40秒 ✓
```

**结论**: ✓ **可行** - 6源并行+优化后，60秒内可完成全量采集

### 3.3 10秒全量目标评估

**数学验证**:
```
目标: 5000只 / 10秒 = 500只/秒

当前最优 (新浪):
- 100只/0.5s = 200只/秒 ✗

理论极限 (6源并行):
- 6源 × 200只/秒 = 1200只/秒 ✓

实际限制:
- 网络延迟、限流、数据源不稳定
- 实际可达: 300-600只/秒
- 5000只需要: 8-17秒 ✓ (理论值)
```

**结论**: △ **谨慎可行** - 在理想条件下可达10秒，但生产环境建议分层策略
